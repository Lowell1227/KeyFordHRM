使用说明

先明确谁来验、验什么

✓
推荐组织方式

由 HR 担任验收主持人，准备员工、直属主管、审批人各 1 名协同操作。涉及“提交、审批、公示”的动作，必须使用验收周期，禁止直接操作正在运行的正式绩效周期。

主验收人

HR / 系统管理员

维护组织人员、指标模板和周期，完成校准、公示、申诉、报表、试用期与转正管理。

协同角色

直属主管

确认团队范围，完成指标审核、主管评分、绩效面谈和试用期评分。

协同角色

员工

查看个人任务，确认指标、提交自评、查看结果和个人改进事项。

协同角色

审批人 / 分管领导

仅处理授权范围内的绩效结果和转正申请，核对退回与通过后的状态流转。

01 · BEFORE YOU START

验收准备与登录

先把账号、组织关系和验收数据准备好，再开始跨角色流程。缺少任何一个关键关系，后续待办会自然为空。

1.1 验收前置条件

  1. 确定验收窗口。通知参与人验收开始和结束时间，避免与真实业务操作混用。
  2. 准备四类账号。HR、员工、员工的直属主管、员工所属部门的审批人。
  3. 核对组织关系。员工必须有直属主管；部门必须有负责人和结果审批人。
  4. 使用专用数据。周期建议命名为“[验收] 年份-季度-日期”，模板和指标也使用明显的验收前缀。
  5. 记录初始状态。截图或记录参与人数、周期状态和各角色待办数量，便于问题回溯。

准备检查

01

登录系统

公司员工点击“选择钉钉账号/组织登录”，按钉钉授权流程进入。多组织账号需要在授权页选择应用所属企业。

  • 正常结果：登录后进入个人工作台，右上角显示本人姓名。
  • 管理员备用入口：仅由管理员展开并使用，不向普通员工分发账号密码。
  • 失败记录：保存页面提示、发生时间、所选企业和浏览器版本。

02 · ROLE WORKBENCH

工作台与角色导航

工作台是当前角色的业务入口。HR 首屏重点是高频动作和最近结果摘要，不需要从完整人员表开始查找。

02

核对 HR 工作台

  1. 确认左侧出现“工作台、绩效、试用期与转正、分析与设置”四个一级模块。
  2. 确认常用入口包含“周期与计划、绩效校准、结果公示、申诉管理”。
  3. 核对最近周期的应参评、已出结果、待出结果和合格率口径。
  4. 点击任一入口后，应进入对应页面；浏览器刷新后仍停留在当前页面。
通过标准 当前角色只看到有权限的入口，点击可处理，刷新不丢失页面。

03 · ORGANIZATION

组织与人员

组织关系决定任务归属和审批范围。验收时先核对身份与关系，再判断“为什么看不到待办”。

03

核对部门与人员关系

  1. 进入“分析与设置 → 用户管理”，先看“配置检查”是否存在待处理项。
  2. 在组织视图中选择员工所属部门，核对部门人数、下级部门、组织负责人和绩效结果审批人。
  3. 在人员名册中搜索验收员工，进入“人员设置”，核对系统角色、直属主管和在职状态。
  4. 切换到主管账号，确认团队列表只包含其授权范围内的员工。
重点：组织负责人、直属主管、结果审批人是不同概念，不要用系统角色代替业务关系。

04 · INDICATORS & TEMPLATES

指标库与考核模板

指标库解决“评什么”，考核模板解决“哪些岗位用什么组合和权重”。先配置指标，再配置模板。

4.1

维护指标库

  1. 进入“分析与设置 → 指标库”，按名称、编码、类型、维度或分组查询。
  2. 新建指标时填写指标名称、编码、类型、考核维度、目标值、指标说明和评分标准。
  3. 保存后重新查询，确认指标可被检索；停用后不应再用于新模板。
  4. 需要批量维护时，先下载模板，再导入并核对成功、失败条数。
4.2

配置考核模板

  1. 进入“分析与设置 → 考核模板”，新建或复制一个验收模板。
  2. 按业务部门或岗位配置维度、指标、权重和适用范围。
  3. 确认维度权重合计为 100%，维度内指标权重也符合规则。
  4. 保存后检查模板状态和适用人员；缺失模板的参与人会阻断周期开放检查。

05 · PERFORMANCE CYCLE

绩效周期创建与发起

周期发起不是简单的“保存并通知”。系统会先检查参与人、组织关系、模板覆盖、豁免和任务快照，检查失败时不得形成半开放状态。

05

创建并开放验收周期

  1. 进入“绩效 → 周期与计划”，点击“新建周期”。
  2. 填写周期名称、周期类型、起止日期和各流程节点截止时间。
  3. 选择全公司或指定部门，确认参与范围；再检查等级分布上限和结果可见字段。
  4. 保存草稿后，在“待发起”列表找到验收周期，点击“开放检查”。
  5. 如果检查失败，按提示修复组织关系或模板覆盖后重新检查；不要绕过提示直接改数据。
  6. 检查通过后确认开放，分别登录员工和主管账号核对任务数量。
通过标准 周期由草稿进入运行状态；每名参与员工只有 1 个周期任务，主管归属与当前直属主管一致。

06 · CROSS-ROLE WORKFLOW

员工与主管协同验收

这一章要用真实角色完成操作。HR 负责观察状态流转，不代替员工或主管提交。

指标制定→员工确认→员工自评→主管评分→HR 校准→审批公示
6.1

员工操作

  1. 员工进入“绩效 → 绩效工作台”，选择当前验收周期。
  2. 在“我的绩效待办”中打开任务，核对指标名称、说明、评分标准和权重。
  3. 先完成指标确认；进入自评阶段后逐项填写自评分和事实说明。
  4. 保存草稿并刷新页面，确认内容仍在；随后提交自评。
  5. 提交后员工不得提前看到主管分数、总分或等级。
6.2

主管操作

  1. 主管进入“绩效 → 绩效工作台”，切换到“我的团队绩效待办”。
  2. 确认团队成员范围只包含当前授权人员，不能看到无关部门员工。
  3. 打开员工任务，逐项填写主管评分和评价；需要时记录加减分或一票否决依据。
  4. 保存草稿、刷新复核，再提交主管评分。
  5. 核对任务进入下一阶段，员工不再出现在待评分列表中。

07 · RESULT GOVERNANCE

绩效校准、结果审批与公示

HR 负责结果口径和分布治理，审批人负责授权范围内决策，公示则是员工可见结果的正式出口。

7.1

HR 绩效校准

选择验收周期，核对当前等级分布、分布告警和校准名单。需要调整时填写校准等级与说明；超过等级上限时系统应明确告警，但是否提交按公司制度执行。

核对点 计算分、原始等级、校准等级和说明清晰；一票否决人员保持 D；提交后进入审批阶段。
7.2

审批人处理结果

审批人进入“结果审批”，选择验收周期，仅查看本人被授权的任务。验证单条退回必须填写意见，批量通过需要二次确认；退回后任务应回到 HR 校准。

通过标准 非审批人看不到审批内容；审批范围、通过和退回后的状态均正确。
7.3

HR 发布公示

回到“结果公示”，选择已审批任务，核对人员范围后发布。发布属于对员工可见的正式动作，必须二次确认；未审批任务应被系统拒绝。

风险提示：正式环境公示前，请由 HR 再次确认周期、人数和可见字段，避免误发布。

08 · APPEALS & REPORTS

申诉管理与报表分析

申诉是结果发布后的正式记录；报表用于观察结果和进度。两者都必须保持周期口径一致。

8.1

记录和处理申诉

  1. 进入“绩效 → 申诉管理”，选择已公示的员工任务并录入申诉事实。
  2. 处理时选择维持原判或改判；改判必须填写新等级和处理说明。
  3. 提交后核对员工结果、档案和申诉记录保持一致。
  4. 申诉页面用于正式留痕，不应出现未定义的多级流转入口。
8.2

核对报表口径

  1. 进入“分析与设置 → 报表分析”，先选择验收周期。
  2. 核对应参评、已出结果、待出结果和已出结果合格率。
  3. 查看结果概览、流程进度、重点关注和员工趋势。
  4. 执行 Excel 导出，核对人数、等级和页面口径一致。
口径说明

合格率与等级占比只按“已出结果人员”计算；未出结果人员不计为不合格。部门平均分也应排除未评分人员。

09 · PROBATION & CONFIRMATION

试用期考核与转正

“试用期与转正”是人员生命周期模块，不是个人主页。HR、主管、员工和审批人从同一业务记录分别完成自己的动作。

HR发起试用期考核配置指标与计划转正日期
→
员工自评与签字查看进度并提交本人材料
→
主管评分与建议完成直属员工考核
→
HR / 审批人归档与转正审批形成可追溯结论
09

完成试用期与转正验收

  1. HR 进入“试用期考核管理”，按姓名和状态查询，发起一条验收考核。
  2. 核对员工、主管、HR、计划转正日期、指标和当前状态。
  3. 员工进入“我的试用期考核”，主管进入“试用期评分”，分别完成自评和评分。
  4. 流程结束后检查签字和归档状态，再由员工提交转正申请。
  5. HR 在“转正申请管理”核对材料，审批人在“转正审批台”完成授权范围内审批。
  6. 退回时必须填写意见；通过后员工和 HR 看到相同的最终状态。
