## 过程中发现与修正

- 新矩阵在实现前 14 项因现有 IA/路由缺失失败；随后实现通过。
- 初次页面脚本误用了 48 字符分享 token，原后端按 64 字符安全要求拒绝；改虚构夹具，不放宽分享校验。通知状态 testid 与实现不符也已纠正。
- 手机原导航有意隐藏分组标题并扁平展开，不能点击桌面折叠标题。补验证桌面折叠状态不会隐藏手机链接；横向菜单改用真实滚动加触摸，而非鼠标模拟。最后全部对应页面断言通过，没有跳过或删弱断言。
- 初次截图拍在录用队列加载中，最终改为实际选中本次虚构申请并出现操作后截图。夹具收尾撤回自建待确认记录、软删人才、撤销分享、归档自建用户，保留审计；未处理其他任务或真实资料。

## 继承风险：混合评审/HR 身份

- `isAssessorOnly=true` 同时保留 HR 或档案授权时，现有后端部分人才读取不一致。本轮前端隐藏人才入口并阻止人才 URL，不代表 API 已隔离。
- 真实预览用一个隔离虚构 HR+仅评审账号验证：人才列表 200、非参与面试详情 200、录用队列 403。所有测试对象已软删/归档；不在生产试探真实资料。
- 该混合组合与正常仅评审员工不同：正常仅评审员工在本轮角色矩阵中人才/录用均 403。后端缺口先于本轮存在，违反 API 不改的任务范围，留作独立权限修复；不得宣称所有可能身份组合三层一致。
