## 已实现行为

- 入口“人员 → 人员档案 → 合同主体维护”，URL `/contract-subjects`。支持名称新增、修改、停用、启用；名称唯一、去除首尾空格、最多 150 字，不支持物理删除。
- HR 管理员和系统管理员维护；具备档案编辑/审核能力的普通 HR 可查看、选用；普通员工不可访问。API 守卫、页面入口和操作按钮分别约束。
- 新增员工“本次任职”的“所属公司（合同主体）”、合同“签约公司”、再入职及任职记录共用主体目录；原“组织归属”独立保留，不根据主体推定组织或权限。
- 任职与每份合同独立选用，保存稳定 ID 和名称快照；目录改名不回写旧记录。停用后禁止新选，已有引用可原样保留并继续修正其他字段。
- 旧公司原文保留，未关联记录不自动匹配；未操作的 null/缺字段保持原值，显式清空才移除关联和快照。仅 ID 变化也进入审核差异。
- 员工资料继续沿用原档案审核、并发校验、生效和审计；目录变更直接生效并审计。

## 调试中修正的问题

1. 全局隐式转换曾把查询字符串 false 转成 true，改为从原始查询读取并严格校验。
2. 新建合同草稿尚无正式合同 ID 时，主体改名后的续存曾刷新名称，现保留草稿内快照。
3. Prisma 返回旧记录 null ID，前端曾按显式清空提交，现区分未操作与用户清空。
4. 状态说明与旧字段标签、旧 JSON 摘要展示保持兼容；新关联仍明确展示。
5. 目录启用状态只接受 JSON 布尔值，拒绝字符串/数字经隐式转换产生错误状态。
