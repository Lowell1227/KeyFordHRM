# 薪酬模块可用性修缮与发布

日期：2026-11-23。版本保持 **0.9.2**。

## 范围与业务决定

用户要求在薪酬、产品、技术联合评审后改进当前难以上手的功能，并明确授权修改后直接上线。本轮不调整真实工资、不确认支付、不增加生产权限，也不修改钉钉后台。

办理主线沿用：工资资料与人员范围 → 直属主管审核资料 → 考勤核对封账 → 税后试算对账 → 首月独立复核审批签收 → 正式核算、复核审批 → 授权导出和实发登记。资料的直属主管审核与工资批次的独立复核审批不是同一职责。

用户新增确认：有考勤维护权限的经办人可以登记“已核定缺勤”及依据，需由有封账权限的人核对后纳入算薪。缺卡本身不是旷工，不能自动推定缺勤；该答复不允许自动办理真实员工。

## 修复对照

| 问题 | 本轮处理 | 边界 |
| --- | --- | --- |
| 扣缴表单一次展示过多字段，月度逐人录入困难 | 分为人员与发薪日、个人缴费、个税与累计；支持批量准备、粘贴核对、逐人保存草稿 | 不批量批准，不默认缺项为零；首次公共规则仍由HR据真实制度填写 |
| 复制可能带走其他人的累计期初或确认事实 | 个人复制锁定原人；共享已审规则只复制公共规则 | 不复制他人工资、基数、累计、证据及确认状态；发薪日期明确核对 |
| 不清楚缺什么、下一步去哪里 | 首次配置就近指引、字段旁错误、主体与月份保留 | 不新增平行办理流程，不替HR猜规则 |
| 审核主要展示技术数据 | 经授权且前序版本hash匹配后显示新旧参数对比；办理记录、计算依据改为业务展示 | 查不到可靠旧版本明确待核，不拼造旧值；原始依据按需展开 |
| 分钟级迟到等可封账但无法计算 | 时长精度与货币配置精度分离，保留可验证区间精度到最终金额处理 | 不用提前粗略四舍五入“修好”金额 |
| 历史已付导致完整对账按未付余额计算 | 对账及首月签收使用完整核定应发，另列已付和待结；正式结算保持余额逻辑 | 对账不能审批工资、最终导出、支付、占用正式额度或写入扣税累计 |
| 有证据的休息日/节假日加班也被阻断 | 按已验证终审事实和时间区间转换加班，不伪造正常班次 | 无完整证据、撤回、重复或重叠仍待核 |
| 真实缺勤无闭环入口 | 经办提交依据 → 封账人员核定/退回 → 新考勤版本；支持有原因的撤销 | 仅在完整排班及查询证明覆盖的人日办理；来源变化需重核 |
| 发薪范围变更后无法继续同步 | 展示新增/移除人日，显式按最新已审范围创建可恢复草稿 | 原版本和移除历史保留；新增覆盖不完整不能封账；已有在审/批准/已付安排不得强行恢复 |
| 历史已付登记错后难纠正 | 版本校验、原因及凭证，审计保留完整前后值和更正记录 | 实际支付记录及冻结快照不改，相关旧试算需重算；受支付/审批安排保护 |
| JSONB回读后误报考勤内容变化 | 仅考勤采用版本化、对象键顺序无关的摘要；数组顺序及实际内容变更仍可识别 | 不改共享hash、不重写已审工资或参数；旧考勤需重同步后办理新增纠错 |

## 最短试用路线

选择发薪主体与2026-10 → 工资资料中维护并提交本主体发薪范围和工资规则 → 按员工维护固定工资、人工绩效金额和扣缴资料 → 直属主管审核 → 考勤同步、核对异常、封账 → 真实资料对账并核对完整税后结果。

缺真实已审资料时系统应准确报缺，不自动补规则或生成真实工资。实际发薪仍需首月签收及对应权限、批准版本和已确认资料。
