## 已实现

| 环节 | 实现与保护 |
|---|---|
| 资料 | HR逐人逐发薪日录入，HRM当前直属主管审核；基准日前累计、本月累计扣除目标、缴费月外部已扣与HRM实际账本分开。空白不当零 |
| 核算 | 服务端五项应发差额接已批资料及实际账本，冻结发薪日、个人扣缴/个税/实发、依据版本和来源哈希，同一版本进入原复核审批链 |
| 防重 | 工资归属项占用继续保留；人员/主体/税年另有未结实发占用；同月累计扣除和同缴费月缴费只算尚未扣部分 |
| 更正 | 新审核参数和新批次追加差额；保留原批准与已付。负实发/负缴费差需人工核对；个税负差记待抵，不自动现金退税或追回 |
| 年度 | 税累计只用实际发薪年度，缴费可引用往年同缴费月实际事实；显式新年基准，不搬用上年收入/已扣税 |
| 审批 | 独立经办、复核、审批；在审输入或实际累计变化则暂停，退回/撤回重算重审，不绕过审核 |
| 实发 | 授权人员按批准日期、整个人员行明确确认已实发且扣缴一致，须财务凭证；一个事务写实际扣缴、五项税前结算、释放占用和审计，同一请求并发重试只记一次 |
| 未付恢复 | 部分人员已付、其他人资料变化时，允许财务撤销指定未付人员安排，保留已付/审批，旧整表停止导出、旧安排不能再付，新批次重新审核后恢复 |
| 导出 | 工资实发、工资明细、审批依据三表，数值列精确核对，独立文件密码；加密前后复查授权/开关/版本/累计，失败清零缓冲区。试算禁止，验证表有测试标识 |
| 正式域 | 维护域和参数审核列表按服务端选择；正式核算/导出必须完整实发快照及开关、独立主体权限。总开关关闭时派生参数审核也不能读快照；非预览前端不再创建验证批次 |

## 直接证据

- `scripts/verify-payroll-net-preview.cjs`：真实HTTP/PG五组通过，包括退回重提、自审/错步骤拒绝、在审来源变化、跨批占用、真实加密下载解密核对、并发同请求确认、同月500补差只扣50税、试算/正式门禁。所有金额均为虚构数学夹具。
- `scripts/verify-payroll-net-recovery-preview.cjs`：真实两人批次四组通过，包括部分已付不变、拒绝撤销已付、经办无权撤销、取消未付释放占用、旧导出/付款拒绝、新批次恢复且原已付人员本批应发为0。
- `web/e2e/preview/payroll-net.spec.ts`：真实页面桌面/手机各一条完整链路；1024×768与390×844只读布局；手机页面实际撤销未付安排通过。未使用API绕过核算、复核、审批、选人、下载及确认动作。
- 首轮页面测试发现详情先于授权返回时默认税前操作的竞态，已改为等待授权后加载；脚本自身两处定位错误修正，没有删除业务断言。后续补充截图等待二次确认框关闭，避免抓到退场动画。
- 旧静态检查将三处排班数量汇总的`Math.round(Number(day.units)*10000)`误判为工资计算；仅对这三份既有日历文件的这一精确表达式例外，工资计算、持久化秘密等禁令保留。

预览准备/校验脚本只允许已登记虚构主体和独立数据库，拒绝生产。写验收脚本为一次性场景，已消费的夹具不清空重置；重验须另建受控虚构夹具或只读复核。截图和详细日志保存在忽略的`test-results/payroll-net-20261123/`及对应日志，不能提交真实材料。
