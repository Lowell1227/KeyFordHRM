## 范围和边界

- 复用原目标台账、目标变更、改进计划和试用期转正；没有新建统一审批引擎或超级台账。
- 管理能力分为全局查看、终止、删除。删除仅从常规列表移除，保留原业务状态、生效事实和审计；未结束记录须先终止。
- 原参与者仍按原范围查阅历史。全局绩效查看不赋予工资或转正内部材料权限；没有给真实账号新增权限。
- 实际离职生效时，仅处理明确绑定该次任职的未完结记录。再入职、其他员工及已生效结果不被反向改变。旧记录任职关联缺失/歧义不猜测、不批量清洗。
- 工作台按绩效、招聘、人事、薪酬四组复用原办理入口。普通待办与关注/交接/清理分开，没有跨模块总人数。
- 用户指定本轮先预览，生产发布留待晚上 Docker 迁移后另行安排。本轮没有迁移 Docker、修改钉钉或触发真实通知。

## 追加修复：工作台折叠后持续抖动

- 用户在固定预览反馈后重新复现：折叠各组并触发一次页面 focus，6 秒内招聘和办理汇总接口各请求 8～9 次，板块出现 4 种位置组合。原折叠状态测试没有覆盖持续几何稳定性，不把此前通过当作本缺陷不存在。
- 根因一：两处调用把刷新自身的 loading 作为 `useVisibleRefresh.blocked`，触发“加载阻塞→排队→再次加载”循环。仅移除这两处自阻塞；共享刷新钩子的编辑保护、慢请求合并与身份失效机制不改。
- 根因二：临时未知数量被当作零项参与 CSS order，导致接口返回先后不同就反复换位。`DashboardSection` 在加载和未知数量期间保留上一次已确定优先级，只在实际结果或错误落定后调整；折叠选择和错误可见性保持。
- 新增真实预览回归 `web/e2e/preview/workbench-collapse-stability.spec.ts`，先在旧代码失败（一次 focus，办理接口实际 8 次而非 1 次），修复后 PC/手机 **2/2 通过**。对真实响应延迟 250ms 后继续原请求，不替换后端数据；每端连续逐帧采样 6 秒，两个接口均各 1 次、板块位置组合均为 1，保持全部折叠且无横向溢出。截图在 `test-results/workbench-collapse-fixed`。
- 定向纯 Web 单测 **54/54 通过**：`node --test tests/dashboard-section.test.cjs tests/visible-refresh.test.cjs tests/recruitment-workbench.test.cjs tests/performance-background-refresh.test.cjs tests/recruitment-workbench-queues.test.cjs tests/performance-operation-links.test.cjs`（在 `web` 执行）。包含新增稳定优先级、账号独立偏好、错误不假报零、慢请求及原导航保护。
- `npm run build`（包含 vue-tsc）通过，原 VueUse 注释与大 chunk 警告仍保留。本次只改 Web，不重复 API 全量或数据库检查；未改共享钩子行为、接口、权限、业务数据或正式环境，未提交/上线。固定预览热更新后可刷新继续试用，真人验收仍待用户。
