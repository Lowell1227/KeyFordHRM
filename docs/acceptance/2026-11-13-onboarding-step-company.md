## 需求与实现

| 用户要求 | 实现及边界 |
| --- | --- |
| 下一步即校验当前环节 | 基本信息校验姓名、已填写的手机号/身份证及查重；本次任职校验公司、部门、日期、类型和状态；档案校验已填资料及合同。错误贴近字段，定位到可修改位置，未通过不前进。最终提交仍保留防御性校验。 |
| 所属公司与组织归属统一 | 按用户明确选择，以合同主体目录为准。入职、再入职、档案编辑和任职维护只呈现一个“所属公司”；列表、详情与办理预览用同一业务名称。 |
| 内部公司代码另做映射 | 在“人员 → 基础资料 → 合同主体”维护映射，沿用现有目录权限和审计。新选的员工所属公司必须已配置映射，后端以目录派生代码，不接受客户端覆盖。不根据名称猜测，不批量回填历史档案。 |
| 四步名称 | 基本信息 → 本次任职 → 档案 → 检查并提交。完成标记反映已校验步骤，最终步骤和标题一致，主按钮仍为“提交”。 |

历史公司名称与代码作为任职快照保留，目录改名、改映射或停用不会自动重写已存在任职。已审核待到岗的再入职，同主体修订也保留已审核快照；换选新主体才使用新映射。普通合同签约主体不强制要求员工公司映射。

历史无任职/无公司档案仍可仅补个人资料，不创建任职、不默认写入孚德。非法代码、清空既有公司会被后端拒绝。没有改变审批权限、确认到岗门槛、工号分配、再入职身份复用或离职生效规则。

## 试用步骤

1. 用预览 HR 身份进入“入离职 → 办理入职”，只填虚构资料。填错手机号点下一步，应停在基本信息并就近提示。
2. 第二步选择“虚构验收所属公司”，不再填写组织归属；缺少部门/日期时不能进入下一步。选填档案中的非法输入也会在该步提示。
3. 最后应显示“检查并提交”，提交后进入办理详情；审核后仍须确认到岗，再查看对应员工档案。
4. 在“基础资料 → 合同主体”新建虚构公司并配置内部公司映射，再用档案编辑选择该公司。未配置的新公司不能作为员工所属公司；修改目录映射不会重写已保存的任职。

## 剩余边界

- 生产真实员工、真实钉钉送达和实体 Safari 未在本轮验收；手机证据是 Chromium 的移动尺寸页面验证。
- 转正数据范围仍沿用部门的公司代码，未改成按员工任职公司授权；公司概念与部门范围不一致时需要单独确认权限口径，本轮不扩大权限。
- 新增映射字段默认空，生产现有主体需由有权限人员明确配置后才能被新选为员工公司；不会由智能体代填真实映射。
- 单测、真实隔离页面验证、生产上线和用户业务验收分别记录，互不替代。
