# 人才列表单删与批量删除

> 本文保留11月19日的历史验证。2026-11-22用户明确要求一起发布，已将删除功能整合到最新主线；后续状态见[增量发布记录](2026-11-22-talent-list-delete-release.md)。

## 范围与状态

- 需求：列表增加单个删除、勾选批量删除及二次确认；保留详情页原单个删除。
- 基线：main / origin/main 为 54567a82；产品保持 0.9.1。仅 Web 修改，复用原 DELETE 与 delete-impact，不改 API、权限、模型或迁移。
- 已实现、固定预览通过；未提交、未推送、未上线、业务待验收。生产 API/Web 仍运行 e0b6b9ec，容器 ID 未变；原保护工作区未修改。
- 预览：[人才库](http://localhost:5173/talents)，真实预览后端、隔离虚构数据，无真实员工/人才资料或外部通知/日程调用。

## 行为

- PC 勾选列、手机勾选框、全选本页、已选数量和批量删除；每行也可直接删除。换页/筛选/刷新清空选择，不跨隐藏页保留目标。
- 确认弹窗固定选中的 ID 和姓名，先读取全部关联影响，读取失败不可提交。显示待进行面试与办理中入职数量；不删除员工档案，不自动取消关联面试、日程或入职。
- 沿用档案维护能力与原软删除/审计，查看型 HR 无删除入口，后端仍拒绝越权。
- 逐条使用原 impactVersion / force。部分失败只留下未完成项，关联变化需人工重新核对并再次删除；网络结果不明时保留原请求依据，可利用后端幂等重试。提交中防重复，不自动接受冲突或重试写请求。
- 删除后刷新当前页；当前页已空则回到有效页。详情的原删除入口、确认提示和实现未改动。

## 验证

- 新增组件回归 8 项（含部分成功、409、新旧会话、断网重试、权限、重复点击和身份固定），联合已有编辑/详情/文件重试共 45 项通过。
- `npm run type-check`、`npm run build` 通过；仅既有依赖 PURE 注释与大 chunk 警告。纯 Web 模块档，不重复全量 API 或付费 AI 调用。
- `web/e2e/preview/talent-list-delete.spec.ts`：真实后端 PC / 手机共 2 项通过，23.7 秒。实际勾选、取消不写、批删、列表单删、详情单删、搜索后清选、只读角色后端 403。
- 每个视口构造关联虚构面试，确认读取后并发增加其版本，真实 DELETE 返回 409；另一条成功后显示 1 成功 / 1 未完成，人工再确认才重试。最终 4 条软删除 / 4 条审计，面试仍为 scheduled / unconfigured。

## 试用与边界

1. 用预览 HR 进入人才库，创建两条虚构人才，勾选后点“批量删除”，先取消，再重新打开并删除。
2. 再核对单行“删除”和详情顶部“删除”均保留。
3. 批量处理不是整批数据库事务，部分成功会清楚显示，取消不能撤销已完成的删除。保留历史/审计不等于提供用户恢复入口。
4. 本轮未发布；正式上线需要用户另行明确授权，真人业务验收不能由以上技术验证代替。
