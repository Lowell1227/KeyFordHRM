# 绩效审批与待办入口优化：技术验收记录

## 范围

- 审批权限：最终等级仅冻结的绩效直属上级可写；员工读取月评时遮蔽未提交的主管草稿；周期计划退回理由必填；历史本人任务不能通过团队列表读取未公示结果。
- 待办入口：目标变更当前办理事项进入工作台、变更页和钉钉绩效卡片；通知按事项和本人/团队动作进入受控详情；未完成目标先提示目标制定。
- 页面：周期审核、部门复核、目标审核、校准、结果审批与目标变更强调当前动作和关键依据；退回意见原位保留；目标变更记录显示业务节点和差异摘要。
- 稳定性：目标变更按后端权限过滤、分页并批量读取；列表失败显示重试；创建成功后详情跳转失败可从原弹窗重试。

## 技术验证（2026-11-18）

| 证据层 | 结果 |
| --- | --- |
| API 全量 Jest | 191 套、3243 项通过 |
| API 生产构建 | `npm run build` 通过 |
| Web 类型检查与生产构建 | `npm run type-check`、`npm run build` 通过 |
| 目标变更、部门复核、审批历史和通知等 Playwright | 68 项通过，含 390px 页面、分页第二页、失败重试与审批记录 |
| 周期审核 Playwright | 通过与必填退回理由 2 项通过 |
| 目标审核单项操作 Playwright | 通过、退回、失败后保留意见重试及跨任务迟到响应 4 项通过 |
| 校准驳回 Playwright | PC 和 390px 多行意见及原位必填校验 2 项通过 |

全量周期排程页面测试另有两项旧日期预期失败：用例要求 `2026-11`，而当前创建的周期为 2027 年第一季度，页面返回的期次随周期变化。本次未修改周期排程算法；这两项不是本轮审核表单回归的通过证据，相关验收仅采用上面单独通过的两项周期审核用例。

## 证据边界

- 上述 Playwright 使用合成身份和接口夹具，只证明界面及请求契约；不等于真人员工、绩效上级、部门负责人、分管领导、HR 在正式系统中完成审批。
- 目标变更分页的服务端测试使用 Prisma mock，尚未在有大量历史记录的隔离数据库测得实际查询时延。上线后需观察请求延迟与错误率。
- 本记录不证明代码已提交、已上线或业务已验收；这些状态以 Git、生产容器修订和用户实际办理结果分别确认。
