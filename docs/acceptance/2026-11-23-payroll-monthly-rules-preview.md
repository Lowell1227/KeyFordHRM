# 月度薪酬规则隔离预览

日期：2026-11-23。基线：0c7fc23c，需求稿0.12，产品版本0.9.2。本轮用户要求检查需求并开发，不包含生产发布或真实工资核对。

## 已实现

| 确认规则 | 本轮实现 |
|---|---|
| 月中入离职固定月薪按工作日折算 | 规则新增monthly_workdays依据，按同一有版本和确认依据的完整自然月逐日日历取分母及在职日期分子，不按实打卡天数。缺日、重复、非法日期、错月、零分母、与考勤应出勤单位不一致均阻断；不重复扣假勤。 |
| 月度最终个人公示来源 | 新规则及formal域只接受明确登记的唯一周期、monthly类型、起止同工资归属月、个人公示事实一致且无未解决申诉。周期期间纳入来源版本，季度过程评分和错月结果不能计入。 |
| 另计及统一系数表 | 新依据要求additional，登记系数表版本与确认依据，缺等级映射不补0/1；保留个人固定基数和对应生效规则。 |
| 绩效折算未确认 | 月中入离职或月中绩效基数/适用状态变化时挂起，不沿用固定工资比例。不以本轮功能决定晚公示补发、基础工资部分结算或正式规则。 |
| 审批中来源变化 | 复用现有SourceHash及批准版本；日历版本等来源变化后暂停旧版审批，退回、重算、重提后才可继续。 |
| 页面维护 | 工资规则抽屉增加应出勤日期、整月总天数、日历版本/确认依据、统一系数表版本/依据。错误就近显示，修改日历后清除旧错误；不增加营销卡片或说明大段流程。 |

只在已有政策JSON、Sources和版本契约上扩展，无迁移、新依赖或生产配置变化。旧季度示例仅保留在旧虚构验收兼容路径，不迁移旧批准结果；formal不能通过省略新依据退回旧算法。实际正式来源选择、数据授权及扣缴累计审批导出尚未完成，不能据此启用正式算薪。

## 剩余依赖

1. 实际发薪主体/人员归属、正式日历和边界、实际固定标准和个人绩效基数、统一系数表实值/批准依据/有效期。
2. 先由HR/绩效负责人核公司是否已有2026-11正式月度公示来源。此前HRM内部无候选不等于公司其他渠道没有；不代建真实周期或取季度评分替代。正式来源选择及工资封账切点仍待接线。
3. 晚公示安排、月中绩效折算和基础工资部分结算边界未定；不默认后批、补零、提前发放或自动延付。
4. A2正式扣缴输入/累计期初和更正账本、A3批准后的完整实发导出、A4正式授权办理、A5真实钉钉取数以及首月财务独立对账仍未交付或未获配置授权。本轮不把计算底层和虚构扣缴试算冒充这些能力。
5. 实体设备、正式人数规模/大历史数据负载及HR财务业务签收未验证。生产API/Web仍ae106896；现场PAYROLL_ENABLED/PAYROLL_FORMAL_ENABLED/快捷测试登录均非true，未触碰真实工资。
