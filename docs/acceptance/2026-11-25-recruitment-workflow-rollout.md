# 招聘流程打磨验收与发布记录

2026-11-25，产品版本0.9.2。用户已明确授权本批开发、验证后上线；真人业务签收另计。

## 范围与使用路径

- 招聘需求详情：收件按条、应聘按份独立统计，筛选/面试/录用/答复/到岗可点开原单；需求内折叠展示招聘进度留痕、外部职位处理及渠道转化。
- 简历收件：待归岗位、待核对筛选与工作台一致；明确复用同人同岗应聘，原来源不覆盖，版本不符保留输入。既有「仅入库」「入库并创建应聘」继续使用。
- 应聘：可提前选意向需求、记录来源，改归属须原因。意向供前段归类，不占名额；正式提交录用仍重新校验选单并冻结快照。历史来源不猜、不回填。
- 原工作台：经办本人的待归岗/待核对，以及当前有效预计到岗日已过仍待确认的事项。改期、终止、到岗按原业务办理后更新；窄录用确认/面试角色不因此得到收件或需求分析权限。
- 招聘进度登记只记录招聘中/招满/暂停/取消，不自动终止应聘、释放名额或控制BOSS职位；外部职位由经办在原渠道处理后登记。暂停/取消是否拦新的录用提交待业务决定，本批不擅改门槛。

## 实际发现与修复

| 问题 | 处理及直接证据 |
| --- | --- |
| 收件锁与需求源锁取锁顺序相反，并发可能超时 | 确认入库先取需求源锁、再取收件锁；真实PG双连接旧代码失败、修正后通过，原幂等和事务保留。 |
| 退回后换意向再撤回应聘，统计可能回旧冻结需求；旧终止影响重新办理 | 共用当前需求归因SQL，明确区分当前意向、正式有效接受和当前版本终止。API回归覆盖退回/拒绝/撤回、终止后重开再撤回；不改旧快照。 |
| 新应聘版本0在收件复用时被前端拒绝 | 允许合法版本0，仍要求精确同人/部门/岗位及后端当前版本，纯测试先失败后通过。 |
| 手机长意向链接撑宽抽屉 | 链接按容器换行，保留完整目标ID和点击能力，不隐藏溢出制造通过。 |
| 分析请求失败可能显示零或空态 | 加载/错误和成功为空分开，不以失败结果作为业务计数；组件加载/403/500/输入保留回归。 |
