### 业务验收入口

- 人才库 `/talents`：录入人才、邀约面试、多选参与人、粘贴腾讯会议邀请、查看删除影响。
- 面试邀约 `/talent-interviews`：HR查看“我发起的”，参与人查看“我参与的”；未受邀人员不获得记录或简历权限。
- 入离职 `/entry-exit`：入职审核后停留待确认到岗，HR显式确认才生效；离职按批准最后工作日结束停用HRM访问。

## 本期业务闭环

`人才库 -> 面试邀约 -> 入职申请 -> HR审核 -> 待确认到岗 -> HR确认到岗 -> 在职档案`

`在职档案 -> 离职申请 -> HR审核 -> 最后工作日结束 -> HRM登录与业务访问停用`

1. 员工档案只有一个主要“提交”按钮，编辑自动暂存，草稿不生效。
2. 宽松审核开关及自动审核分支取消，历史配置、审批与审计不删除。部门合并仍人工审核。
3. 新入职和再入职需确认到岗；日期到达、定时刷新、读取或登录均不能代替确认。确认由 `employee_archive_review` 能力控制；修改日期由档案维护能力控制，必须重新审核。
4. 历史申请默认 `requiresArrivalConfirmation=false`，没有伪造到岗人/时间或静默改变旧流程。发布前需另行盘点真实待入职申请。
5. 人才转入职持久关联同一来源，防止重复未结束申请；候选人转为已入职只发生在实际生效时。
6. 面试是简单邀约记录。腾讯会议由发起人在个人账号创建后粘贴邀请；本系统不管理会议房间，也不自动创建、改期或取消腾讯会议。
7. 明确选中的内部参与人可看邀约及共同安排备注，不获得整个人才库、简历原件或内部跟进的权限。简历继续独立授权。
8. 删除候选人需核对关联影响，有未结束流程时二次确认“仍然删除”。软删除保留已有面试、日程、申请和历史，不级联取消、不自动复活来源。
9. 已取消且从未到岗的首次入职可通过“重新办理入职 -> 重新提交审核”恢复同一申请和身份；不伪造离职记录，不因打开详情自动恢复。工号按新序列重新预留，原释放记录保存到申请修订历史。
10. 面试入口使用 `/talent-interviews`，原 `/interviews` 绩效面谈入口保留。HR可通过“我发起的”找到删除候选人后仍保留的邀约。

## 固定档案审核口径

沿用现有 `api/src/employee-archives/direct-apply-profile-fields.ts`，不扩展免审范围：

- 点击提交后直接生效：手机号、性别、出生日期、民族、学历、职称、毕业院校、毕业日期、专业、婚姻状况、子女状况/数量、政治面貌、籍贯、户籍类型、身份证地址、现住址、紧急联系人及关系/电话。
- 组织、任职、合同、社保/公积金、证件、绩效上级等变更继续走已有审核。
- 当前工号由系统分配，状态/任职与审核结果按流程生成，不将草稿值直接当正式结果。
- 混合提交分别返回已生效字段和待审核结果；自动暂存不触发这些生效动作。

### 重点修复证据

- 取消后恢复最初在真实PostgreSQL产生 `source_request_id` 唯一约束错误；改为更新原已释放工号槽位、分配新序列号，旧槽位快照写入原申请修订历史。复跑验证单一申请、单一身份、单一来源工号记录、取消审计仍在，重审后才可确认到岗。
- `我发起的` 只查当前发起人，未向普通受邀员工开放人才管理视图；受邀接口不返回简历和内部跟进。
- 日程核对仅按已知远端ID或稳定标记读取匹配。唯一匹配后复用原事件ID；无匹配、多匹配或无读取权限仍保持结果不明，不自动新建。迟到回包用版本与领取标识隔离。
- 日程派发双实例并发只允许一个领取成功；实际钉钉服务仍待开通权限后验收。当前邀约站内通知可用，不宣称钉钉工作通知已打通。
- 截图为虚构数据，保存在本机TEMP的 `hrm-lifecycle-{archive,interview,interview-hr,arrival}-*.png`，未生成含真实人员资料的验收截图。
