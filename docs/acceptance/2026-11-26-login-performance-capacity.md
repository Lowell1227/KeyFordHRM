# 2026-11-26 登录、绩效流转与 100 人压力实测

## 结论

本轮已实际运行，不是计划或单测替代：100 个有效虚构员工账号完成 5 分钟混合登录/读取/保存，共 13,008 次 HTTP 请求、1,801 次成功保存，业务错误和请求错误为 0；100 份目标提交并继续完成五步目标审核，重复和并发处理未重复生效。但**整体验收不通过**：预打开待办页面没有自动更新，30/100 账号同刻冷登录超过原定时延线，100 人档 `/auth/me` 的单路由尾延迟也超普通读取目标。不能写成“全功能全绿”。

这证明本轮限定核心路径能办理 100 人规模，不代表生产公网、全模块、完整绩效结果周期或全天稳定性已通过。暂不因这轮结果建议拆服务、减弱密码安全、缓存撤权结果或购买新服务器。

### 资源保护的具体调整

早期通用预检的 4 GiB 余量线没有通过，未将它报成通过。为实际执行，本轮先明确并降低临时服务硬限额、浏览器与负载分时运行，采用 `scripts/capacity/isolation.mjs` 的**增量峰值预算 0.984375 GiB + 保留 2 GiB**。开跑时宿主可用 3.044 GiB、CPU 14%，Docker 可用 5.366 GiB，满足这一明确预算；不是降低性能通过阈值来造绿。

执行期间每 15 秒只读采样，共 81 次；宿主可用最低 2.107 GiB、CPU 最高 31%，生产健康接口 81 次均正常，p95 6.41ms、最大 15.82ms，无测试 API OOM或安全停止。采样不是连续监控，也不能据健康接口保证每个真实用户没有瞬时体验波动。

## 实测结果

单位为毫秒，p95 表示 95% 请求不超过该时间。每档 VU 用独立员工与任务，3 秒最小思考间隔；业务操作为 80% 读/20% 保存，版本读取和落库回读另计请求。初始登录没有错峰，因此 daily-30/100 同时包含同刻冷登录压力。

| 场景 | 实际量 | 登录 p95 | 读 p95/p99 | 写 p95/p99 | 判断 |
| --- | ---: | ---: | ---: | ---: | --- |
| 单人 1 分钟 | 30 请求、4 保存 | 118.91 | 42.16 / 71.14 | 43.41 / 43.79 | 原门槛通过 |
| 10 人 2 分钟 | 568 请求、76 保存 | 738.73 | 127.44 / 211.38 | 196.10 / 205.01 | 原门槛通过 |
| 30 人 3 分钟 | 2,473 请求、330 保存 | **2,705.76** | 137.43 / 611.49 | 267.29 / 360.40 | 冷登录 p95 超 2 秒，退出码99；没有业务/请求错误 |
| 100 人 5 分钟 | 13,008 请求、1,801 保存 | **8,723.52** | 417.22 / 1,673.96 | 1,220.33 / 1,987.41 | 冷登录超线；并非整档通过，业务/请求错误均0 |
| 100 人在 10 秒内陆续发起登录并进入读取 | 100/100 登录、600 请求 | 1,818.87 | 1,916.11 / 2,603.20 | 不适用 | 突发目标 p95 <=5秒、最大<=10秒通过 |
| 登录准备后 100 份目标在约 10 秒窗口内提交 | 100/100 提交、400 请求（含准备登录） | 准备阶段73.86 | 30.35 / 38.29 | 51.78 / 90.54 | 提交成功数100；突发时延目标通过 |

前三档及100人档的原目标是普通读 p95<=1秒/p99<=2秒，普通登录/写 p95<=2秒/p99<=4秒；突发目标另为 p95<=5秒、最大<=10秒。原始失败保留，未调整阈值重写结果。k6 legacy JSON 中 `thresholds` 布尔值表示阈值失败状态，不能看到 `false` 就误判失败；以退出码、原表达式和实际数值共同核验。

### CPU 受限的对照

同一隔离数据和构建、同样 100 个账号同刻开始真实密码登录并读取本人资料，仅改临时 API CPU额度：

| CPU | 成功登录 | 登录 p95/最大 | 本人资料 p95 | 原突发门槛 |
| --- | ---: | ---: | ---: | --- |

## 登录与页面实测

同正式 Web 的本机隔离入口、headless Chromium、PC1440x900/手机390x844，员工/主管/部门负责人/审批人/HR五类角色实际填写密码登录；不是维护会话。初次 HR 因没有个人周期，被探针错误要求存在任务列表请求而判未完成。核对当前页面的空周期分支后，探针要求成功读取空周期数组并显示无错误/无加载的真实空态，定向补验PC/手机2项成功；初次记录保留，没有削弱业务请求成功或可用页面断言。

- 其余角色：密码POST网络时间约68～74ms；从点击到绩效内容可用约628～907ms。
- HR补验：POST64～69ms，内容可用478～495ms。
- 页面脚本错误0，相关失败读取0。没有复现本机单人“半天无反应”。
- 没有代账号319尝试密码、没有重置真实账号或使用真实会话做压力；因此不能声称已完整复现其昨晚/当天特定网络与设备故障。

### 绩效跨账号交接：已确认缺陷

1. 领导先打开真实“待我审核”页面；员工通过详情按钮及确认弹窗提交目标确认，真实 POST200，点击到成功285ms。
2. 使用领导真实UI登录产生的会话独立 GET：51ms返回，目标存在且允许该领导办理。
3. 领导页面20秒内业务列表 GET **0次**、目标仍不显示，未达到15秒目标。
4. 手动正常刷新后458ms目标出现且可办理。

这是“服务器已经流转，页面没有重新取数”的直接复现。`web/src/views/task/components/GoalPlanList.vue:70`只随scope触发加载；工作台入口`web/src/views/dashboard/DashboardTaskEntries.vue:193`主要随身份变化加载，结果审批页`web/src/views/approval/ApprovalView.vue:260`主要挂载时加载。这些是相关代码证据，不能把本轮只测目标交接扩大称所有结果审批都已实测。

headless `bringToFront` 没有产生真实OS焦点/可见性事件，报告明确 `realBackgroundTransitionObserved=false`。因此切回前台3秒指标本轮**未有效验证**，不能冒称已复现原生焦点失败；源码也未显示这些页面有相应自动刷新。

### 公网资源：只读低频比较，不是公网压力测试

对正式页面与主脚本各取3次匿名样本，间隔15秒；均HTTP200且主脚本内容为1,164,891字节（解压后），gzip已开启：

- 本机主脚本：19.64 / 22.54 / 15.59ms。
- 公网主脚本：3,005.28 / 3,010.49 / 3,021.82ms；响应头约42～62ms即返回。

说明该采样的主要差异发生在静态资源传输，而非等API返回。未验证服务商带宽配额、用户Mac/Chrome网络或100人公网同时下载，不能由此断言具体隧道限速值，也不能把首屏大脚本当作已经显示登录按钮后所有点击等待的唯一根因。
