## 本轮发现并修正

1. 真实 PostgreSQL 不支持直接反序列化 advisory lock 的 void 返回；改用仓库已有的 `SELECT 1 FROM pg_advisory_xact_lock`。
2. 期初只存在金额或确认时间、缺确认人或凭据时不得计算和提交。
3. 主体范围判定内部仍检查跨主体任职重叠，外发快照只保留本主体必要任职及范围异常，不返回另一主体详情。
4. 工资表冻结当期任职工号，不使用当前账号工号猜测历史；缺失或同月多值阻断。
5. 工资 API 的 Decimal 在旧全局响应转换前变为字符串；Excel 逐格验证 Decimal 回转、15 位有效精度、项目完整性及批准总额一致性，无法准确交付时拒绝，不默默丢分。
6. 审批可不填通过意见，退回仍须依据；作废按钮与结算权限一致。作废后返回办理回执，不再请求已失去可见性的历史详情。
7. 薪酬专用异常边界不输出数据库查询或工资值；并发冲突为 409；工资下载密码不进入 URL、审计、消息或持久化页面状态。
8. 查询分页不完整、无完成证据或人员日期缺口均不能封账。补同步不删除范围外事实，不用缺席推断撤销；较新版本及撤销墓碑保留。
9. 仅被配置在未来审批路径、不等于已分配批次；尚未提交的计算草稿不向仅复核/审批账号开放。提交后可读分配版本，退回重算的新草稿再次隐藏，原已提交历史保留。
