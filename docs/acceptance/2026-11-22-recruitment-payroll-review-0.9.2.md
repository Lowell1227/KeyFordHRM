## 跨月安全边界

本次只做冲突识别与安全挂起，不实现自动跨月搬移、冲回或替人确认财务事实。同一来源在多个归属月出现，包括撤销墓碑，需先核对来源分段标识、原月份及既往入薪。没有经过业务确认的跨月处理流程前，相关范围保持阻断，不能通过换来源标识规避。

已批准金额不与包含新入薪累计的全量来源指纹比较，正常付款不会仅因累计变化误判为过期。下载在加密前后均复查归属冲突；已成功的原付款请求允许幂等回执，新付款请求被拒绝。取消剩余安排及确认未付后作废继续受原权限和业务限制，历史保留。

新增入薪与下载检查必须读取获得主体锁后的已提交事实，不能把“使用 Serializable”误当成“等待后刷新快照”。本次没有全局降低隔离级别，写入仍受同主体/核算域事务锁保护，审批和取消保持原 Serializable。真实并发夹具只写入模拟来源冲突，不访问正式工资数据。

## 继承风险与未决项

1. **历史混合身份权限缺口。** `isAssessorOnly` 同时叠加 HR 权限时，旧人才读取入口仍可能可访问；新工作台的拒绝不代表所有旧 API 已隔离。此前已单列，本轮未扩大授权或擅改混合角色语义；需单独确认治理，不能称全项目安全审计通过。
2. **历史前端测试债务。** 完整运行 `system-overview-status.test.cjs` 与 `talent-share-recipients.test.cjs` 两文件合计 35/39（含子项），四项旧接收人选择断言与当前公开外链实现不匹配；没有删断言或改产品来假通过。概览旧 0.8 断言已改为当前包版本并保持功能边界校验。另 `talent-resume-form.test.cjs:282` 的旧字段文案断言在指定基线同样失败，未扩改。公开链接的现行业务授权需以既有决定为准，不将旧测试当新需求。
3. **历史量增长。** 旧 API 调用若不传月份仍返回全部授权历史，规模增长后需单独设计分页契约；本轮没有重建新分页框架，也不再静默截断。跨月来源核对使用现有 JSON 快照，正式大规模运行前需实测容量。
4. **正式薪酬依赖。** 适用主体/人员、工资制度与参数、计薪周期/系数、复核审批/导出财务权限、期初和实付证据、跨月核对/冲回、文件列与留存尚待确认；真实钉钉适配、IP 白名单、分段 sourceId 和覆盖回放未验收。扣缴/实发、部门奖金、工资条及银行付款不在本期启用。
