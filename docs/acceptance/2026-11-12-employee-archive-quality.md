## 已修复的问题

### 查询和导出

- 列表请求使用代次判断，较慢的旧查询不再覆盖后发查询结果。
- 查询失败显示明确错误及重试入口，避免把失败误当成空结果；失败时不能导出未经确认的结果。
- 导出使用最后成功查询的筛选快照，未点击查询的新输入不会悄悄改变导出范围。
- 导出 Excel 前可勾选字段、全选和清空，至少选择一项；默认保留原有九个字段，新增可选“本次司龄”。弹窗显示导出范围及匹配人数，并保留本页内的字段选择。
- 后端按字段白名单校验，拒绝空选项、重复或非法字段，审计记录所选字段和筛选条件；原有权限范围及导出数量限制继续生效。
- 导出接口的 JSON 错误即使以 Blob 返回也能展示可读提示，失败后保留字段选择。
- 办理中页面展示申请记录，不显示花名册导出入口，避免将申请列表误导出为员工列表。

### 查看详情和合同

- 详情读取失败保留抽屉并提供重新加载，不再直接关闭；没有当前有效任职时不把历史第一条冒充为当前任职。
- 切换员工后，前一个员工的迟到钉钉关联操作响应不再覆盖当前抽屉。
- “最新合同”只默认展开一份保留记录，其余进入默认收起的历史合同；保留所有合同原始数据、日期和状态。
- 编辑、审核、正式档案和历史共用“名称/类型 + 日期”的标题，不再用随排序改变的“合同 8 / 合同 5”标识。导入数据的 `kind` 与正式合同的 `contractType` 均兼容。
- 最新排序使用签订日期，缺失时用生效日期，再以创建时间和稳定 ID 排序；“最新”不代表期限有效，仍展示实际合同日期状态。
- 档案及导出共用本次司龄口径：本次入职起算、调岗不重算、再入职重新起算；离职截至最后工作日，未来入职不提前累计，矛盾或缺失日期提示待完善。

### 编辑和续编

- 已保存的草稿改回正式原值后正确覆盖旧草稿，并递增版本，避免重新打开又出现旧修改；不写正式档案或自动发起审核。
- 明确清空岗位、主管、绩效直属上级和性别会提交 `null`；省略字段仍表示保留，兼容没有岗位 ID 的历史岗位文本。
- 旧档案缺少 profile 手机号但账号有手机号时能正确回填，人工清空仍可保存。
- 历史返回可续编标记，使符合现有权限和状态的退回申请能按原身份及版本继续编辑。
- 合同原公司、新公司复用公司目录，支持搜索、保留历史文本及禁用停用项；签约主体继续保存 ID 和名称快照，原公司/新公司继续保存文本，不伪造关联。
- 没有当前任职时，编辑仍沿用现有 API 的最近任职作为录入参考；已在表单说明，保存依然使用填写的生效日期。本轮未重定义任职生效或审批规则。
