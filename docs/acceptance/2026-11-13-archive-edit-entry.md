# 员工档案编辑入口与冲突提示修复

状态：已实现、定向验证通过、固定预览可用；功能提交`c8c744ed`已推送main并于2026-11-13发布Web。线上只读检查通过，真实业务验收待用户试用，详见[发布记录](2026-11-13-archive-edit-release.md)。

## 问题与修复

- 开发基线 `main`、`origin/main`、远端 main 均为 `2bfa2ef7`。当时生产 API/Web 为 `5247cb5b`，健康接口正常；预览验证阶段未修改生产环境，后续仅发布Web，全程未修改真实员工资料。
- 原编辑入口仅恢复草稿/退回单，忽略尚在处理的档案申请。首次写入没有原单 ID，后台拒绝重复创建；前端又将该 409 误解为资料版本冲突，并同时显示全局提示和页内提示。
- 编辑前读取最新档案。已有草稿续用原单 ID、版本及填写内容；已有待处理申请则留在查看模式，显示“查看原申请”，不启动自动保存。草稿列表和问题维护入口同步处理最新状态；已归档人员保持只读。
- 保存/提交错误由编辑器在页内呈现一次。409 保留输入、暂停自动保存，提供“重新加载”；替换未保存输入前需明确选择，读取失败仍保留输入。400 校验信息和 403 权限原因仍可见。
- 保存状态统一放在抽屉底部。输入控件挂载完成后建立初始快照，避免数字类型归一化被误当成手工修改。
- 从员工档案深链接打开原申请时清除 employeeId 参数，避免档案和申请两个抽屉重复打开。
- 没有调整后端版本保护、审批规则、权限和正式数据生效规则。不能根据截图确认该员工最初写请求的具体触发字段；正常打开以及数字归一化边界均已回归验证。
