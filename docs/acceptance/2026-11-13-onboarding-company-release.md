## 发布中问题与闭环

初次发布的临时构建脚本把 `VITE_API_BASE_URL` 设为 `/api/v1`，但客户端会再添加该前缀，浏览器请求成为 `/api/v1/api/v1/auth/me` 并返回 404。健康接口及钉钉构建检查未覆盖这一配置错误。

发现后先仅回退 Web 恢复原页面，保留正常的新 API 与迁移；将同源 API 基址恢复为空，重新构建 Web。候选镜像通过 PC/手机只读登录态及受影响页面验证后，于 22:42 再次替换 Web；随后公网同样检查通过。没有恢复数据库或改业务权限。该失败属于发布参数错误，不计为业务测试失败，也不能省略记录。

发布副本内的 `build.json`、`backup.json`、`postflight.json`、`migration-status.log`、`candidate-readonly-smoke.json`、`readonly-smoke.json` 保存最终证据。

## 正式试用

1. 有权限 HR 先在“人员 → 基础资料 → 合同主体”核对并配置内部公司映射；智能体不推测真实映射。
2. HR 经办进入 [入离职](https://1260cw31az927.vicp.fun/entry-exit)，办理入职；每一步填错应当场提示，最后为“检查并提交”。
3. 姚瑶使用自己的账号进入待我审核，审核通过后仍须确认到岗，才使本次任职生效并进入员工档案。

当前不是定向只派给姚瑶，其他具备档案审核能力的 HR 也可审核；同一人同时具备维护/审核权限时仍可自审。本轮没有扩展这些规则。真实扫码、实体 Safari 和真实人员办理需业务继续验收。
