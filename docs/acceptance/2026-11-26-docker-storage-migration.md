## 实际阻断

1. 官方 UI 选择 D 盘后复制完成，但日志将 Robocopy 返回码 1 判作错误，配置未应用；原数据盘仍在 C 盘。微软文档确认 1 表示复制成功。Docker 官方问题 #550 与现场错误一致，维护者说明 4.92 已修复该 UI 问题。
2. 当前版本重新选择已存在的目标目录显示 `Invalid path`，没有可用的直接采用选项。不能凭通用设置文档假定 WSL 界面支持采用已有磁盘。
3. 首次采用复制副本时，实际启动遇到 containerd 页断言错误。未删除 containerd 索引、镜像、卷或业务数据作为修复。
4. 从完整冷备份恢复 D 盘并校验实际落盘摘要后，再次启动遇到 WSL bootstrap 无法找到指定 WWID 的数据盘。此问题的底层原因尚未确认，不把它直接归因于业务数据库损坏，也不承诺升级必然解决全部挂载问题。
5. `DataFolder` 是 VM 通用设置，不能据此判断 WSL 数据盘已切换；本机 WSL 对应 `CustomWslDistroDir`。两项临时覆盖均已撤回，当前恢复原配置。严禁仅凭界面路径、配置 JSON、文件存在或摘要一致就删除原盘。
