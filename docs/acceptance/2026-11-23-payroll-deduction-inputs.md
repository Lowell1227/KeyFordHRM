# 扣缴资料维护与审核接线 A2.1

## 本轮范围

用户要求继续既定薪酬开发；延续“真实数据由HR录入，其主管审核，开发阶段先造数据”。本轮把代码示例之外的可维护扣缴资料接入既有参数审核和实发试算。产品仍0.9.2，只改固定隔离预览，不读真实工资，不改钉钉、不部署/启用生产。

流程：`HR录入/复制扣缴资料 → 保存版本 → 提交直属主管 → 退回重提或审核发布 → 工资批次使用已审核资料试算实发`。

## 已实现

- 新增PayrollDeductionProfile，按主体/员工/域/发薪日独立递增版本。个人社保、公积金分别维护适用性、缴费归属日、规则生效期/依据及个人基数/比例；个税明确算法、规则版本/分档、生效期、累计期初确认与来源、本次扣除。没有任何实际法定税率/企业制度默认值，不填资料不补零。
- PayrollParameterRelease增加deduction种类和外键/尝试唯一索引，复用同一HRM直属主管分配、禁止自审/无权管理员代审、主体授权、退回/撤回/重提和前版/快照指纹及串行事务。通过不覆盖旧资料。
- 资料接口和试算均拒绝客户端覆写gross，资料内部也不接受隐藏的员工/主体/年度/已扣字段；员工与主体已批准任职匹配，年度来自明确发薪日。金额、日历有效性及依据复用A1校验，不另写税算法。
- 扣缴资料页面和主管审核明细复用业务列表/抽屉，手机单列。字段缺项就近提示；主管只读被分配版本，没因此获得资料全集、工资或导出权。
- 试算新增saved（已审核资料）来源：准确匹配员工/主体/发薪日，仅读active且具有一致approved快照的版本。税前额来自当前冻结工资五项明细；草稿/待审/错日/参数缺项或篡改不回退示例金额。全员完整才汇总，结果有parameter id/version/releaseId/snapshotHash及A1输入hash。
- 旧complete/missing仍是显式虚构示例/缺项演示，不成为正式规则。页面区分“示例参数”和“已审核资料”，状态明确“实发未审批”。
