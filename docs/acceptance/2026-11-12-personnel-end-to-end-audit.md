## 3. 已确认的功能问题

### F1 / P1：面试选人查到归档离职人员，正常在职人员选不到

- 复现：人才详情 → 新增面试 → 内部参与人。1440和390宽度均只提供“预览离职员工 · PREVIEW_EXIT002”；选择该人并填写合法时间/邀请后，保存返回400：“部分参与人不在职或不可用，请重新选择”。
- 对照请求：`/users?status=active&pageSize=30` 返回7名在职虚构员工；增加 `archived=false` 后返回1名已归档离职人员，与 `archived=true` 结果相同。
- 根因：`TalentInterviewPanel.vue:60` 显式传 `archived:false`；`UserQueryDto` 的布尔属性在全局隐式转换下先将字符串 `false` 转为true，后续Transform无法恢复。`UsersService.buildUserListWhere` 因此进入已归档/已离职分支，覆盖active筛选。
- 修复方向：在DTO入口正确解析布尔查询值，并覆盖所有同类布尔字段；面试选人必须只呈现未归档的有效在职/试用员工。属于共享查询边界，修复后需复验关联人员列表/导出/选择器。
- 证据：`tmp/personnel-audit-20261112/browser-proof.json` 的active-users、interview-participant-options和save-with-only-offered-participant；`interview-editor-1440.png`、`interview-editor-390.png`。

### F2 / P2：“查看员工档案”跳到未筛选的全员列表

- 复现：本轮虚构人才经真实入职审核和到岗确认后，点击“查看员工档案：姓名”。地址虽包含 `keyword=姓名`，页面搜索框仍为空，档案抽屉0个，显示9个“查看档案”按钮。
- 根因：`TalentDetailDrawer.vue:139` 已有 `convertedUserId`，跳转却只使用姓名；`UserManageView.vue` 未消费该keyword参数，也未按关联员工ID打开档案。同名人员亦无法可靠定位。
- 修复方向：使用已关联的员工ID打开该档案，并保持权限校验；不要用姓名猜关联身份。
- 证据：`fullflow-proof.json` 的linked-user、archive-link-result；`archive-link-lands-on-unfiltered-list.png`。

### F3 / P2：北京时间凌晨默认跟进日期少一天

- 复现：浏览器时区Asia/Shanghai，将浏览器时间固定到 `2026-11-13 01:00`，点击“记一条”，日期显示 `2026-11-12`；PC、手机均复现，并可将错误默认日期保存为201。
- 根因：`TalentFollowUpTimeline.vue:34,55` 使用UTC的 `toISOString().slice(0,10)` 作为中国业务日；服务端省略日期时的默认today也使用同类算法。
- 修复方向：前后端统一使用北京时间业务日；补北京时间00:00～07:59边界用例。
- 证据：`browser-proof.json` 的followup-default-at-beijing-01与follow-up-save。

### F4 / P2：不存在的跟进日期被悄悄改为另一日期

- 复现层级：直接请求真实预览API。提交 `occurredAt=2026-02-31` 返回201，保存结果为 `2026-03-03T00:00:00Z`，没有提示日期无效。
- 根因：`create-follow-up.dto.ts` 只验证字符串格式；`parseTalentDate` 直接交给JS Date，后者会把超出月份的日期滚动到下月。
- 修复方向：发生日、下次跟进日均校验真实日历日期并拒绝非法值；错误显示在对应字段。不是由页面日期选择器正常选择触发的证据，不扩大表述。
- 证据：`fullflow-proof.json` 的invalid-calendar-date。

### F5 / P2：仅粘贴含链接的会议邀请，不能生成入会入口

- 复现：创建邀约时 `invitationText` 包含合法 `https://meeting.tencent.com/dm/synthetic-audit`，不另填meetingUrl，API成功但meetingUrl为null。
- 根因：`TalentInterviewsService.validate` 只处理独立meetingUrl字段，不从邀请内容提取；`TalentInterviewContent.vue` 仅在独立meetingUrl存在时展示“打开腾讯会议”。邀请原文按纯文本显示。
- 与批准设计的差距：设计5.1要求粘贴官方邀请后提取链接供确认、无法提取时再人工补充。目前用户必须把同一链接再填一次，否则受邀者没有直接入会按钮。
- 修复方向：从原邀请提取并按现有官方域名/HTTPS规则验证，供HR核对；失败时就近提示补链接，保留纯文本安全边界。
- 证据：`fullflow-proof.json` 的valid-interview-via-api和complete-interview，均为邀请含链接但meetingUrl=null。

## 4. 交互验收

已有优点：人员入口与待到岗入口清楚；入职四步、字段分组及固定底部按钮可用；再入职同名候选需明确选择；PC和390手机未发现本次走查页面的整页横向溢出，独立探针页面脚本错误为0。不能外推为所有字段、所有设备都没有问题。

需要简化两项：

1. **每一步重复展示很长的后续流程。** `EmployeeCreateDrawer.vue:865` 在整个表单内始终展示“后续办理流程”、解释文字和4个灰色等待节点。第一步仅几个输入框，下半屏却被未来流程占据，手机更需额外滚动。建议仅在最终检查页展示一次紧凑的“提交审核 → 审核通过 → 确认到岗 → 入职生效”，删去解释灰显规则的文字。截图：`onboarding-step1.png`、`onboarding-step4.png`。
2. **入口与标题命名不一致。** 人才详情和入离职按钮均为“办理入职”，打开抽屉却称“新增员工”（`EmployeeCreateDrawer.vue:694`）；该入口还承担匹配后切换再入职。建议统一主标题为“办理入职”，明确选中历史人员后显示“办理再入职”；让标题直接表达当前办理动作。

保留删除影响、共享备注、最后工作日等必要业务说明；不以删光说明文字作为简约的标准。
