# 周期终止与入口整理验收

## 范围与状态

- 基线 `dac6e53f`，产品版本保持 `0.9.3`。本轮先交固定隔离预览；正式账号授权和发布状态须以最终回执为准。
- 绩效侧栏顺序为“绩效任务、目标台账、目标变更”，按原资格显示。绩效任务内保留“我的目标、目标审核、绩效待办”；原绩效待办的阶段、路由和业务权限不变。
- 常用工作入口置于工作台顶部，由既有路由资格、招聘能力和薪酬主体授权决定，不按个人姓名硬编码。人员经办可见档案、入离职等原有入口，不因此获得档案审核或录用确认权。
- 独立能力 `cycle_terminate` 不由 HR 或系统管理员角色隐含获得，不包含删除权限；仍受原周期管理范围限制。首批真实账号由用户明确指定，尚未在本记录中宣称授权已生效。
- 后续收到并批交办，将 `4c9cd97d` 的工作台薪酬汇总提速增量纳入同批集成；不改其原有主体、当前办理人和独立审核边界。

## 实现与保护

1. `GET /cycles/:id/termination-preview` 返回完整人员影响清单、保护分类、待取消变更/提醒及影响 hash。
2. `POST /cycles/:id/terminate` 原因必填、页面二次确认；事务内依次锁评分期、任务及周期，再核当前账号、原数据范围和影响 hash。撤权/版本变化时拒绝且不部分写入。
3. 周期保留原业务状态，新增不可覆盖的终止元数据。可终止任务及其未生效目标变更只改生命周期状态，不删除内容；已审批、公示、确认、豁免等受保护事实不变。只取消尚未发送的关联提醒，不调用外部通知。
4. 已终止周期禁止补建/迁入任务、修改评分期、重新发起和自动推进。已有受保护结果的公示、申诉仍使用原路径；其他周期、转正、改进计划、薪酬和入离职不联动终止。
5. 期间正式提交可能不改变父任务状态。独立复核确认原 hash 存在此漏检，新增真实双连接用例先复现失败，再将评分期正式状态、提交/锁定时间和正式版本标识纳入 hash；不把普通草稿版本变化一律升级为冲突。
6. 员工、主管的旧表单遇到 409，先读取有权限的生命周期元数据。确认已终止后保留当前组件/输入、阻止继续写入；普通版本冲突不冒称终止；401/403/404 或状态核实失败时停止提交。
7. 新增触发器最初的 `SHARE` 与原阶段聚合的 `NO KEY UPDATE` 存在锁升级冲突；真实双连接先复现，再改为仍与终止 `FOR UPDATE` 冲突的 `KEY SHARE`。截止日更新在写入 CAS 中检查未终止，排队请求不能越过门禁。
8. 已终止周期的配置有数据库围栏，兼容旧客户端，终止元数据不可覆盖；原结果推进只保留状态、公示/申诉期限和结案时间。公示与自动结案使用的真实字段逐一对照，不误拦既有保护结果。
9. HR 管理员和系统管理员也可显式维护终止能力；保存其他人员设置不会把该能力过滤丢失。不自动给任何角色追加。
