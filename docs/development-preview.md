## 开发者操作

前提：现有 `hrm` 的五个开发服务、依赖卷和基础设施仍在。本工具不是新机器安装器，不会创建第三套服务。

```bash
# 仓库根目录。首次初始化，或后端源码变化后更新预览。
node scripts/preview.mjs

# 配置保护测试
node --test scripts/preview.test.mjs

# 真实预览后端浏览器回归，无普通 global-setup，无 mock
cd web
npx playwright test --config playwright.preview.config.ts
```

- 前端使用 Vite 热更新，通常无需重启。后端采用编译启动，源码变化后执行启动命令；只重建 API 容器，Web 配置未变时保留。
- 后端启动先校验隔离配置，再依次重新生成 Prisma 客户端、部署迁移、检查一次性虚构数据、编译、启动。直接运行 Compose 也不能跳过迁移前检查。修复了旧开发客户端缺新模型的问题，也避免精简镜像缺少 `ps` 导致 Nest watch 重启失败。
- 首次生成 `.env.preview.local`，包含本机预览密钥，已被 `*.local` 忽略并限制文件 ACL。不要打印、提交或发送此文件。
- 不要用旧的 base + dev Compose 命令覆盖预览 API/Web。它会重新引入根目录 `.env`。也不要把 preview 文件与生产 Compose 合并。
- 新增依赖后需单独更新对应开发依赖卷；启动器不自动安装依赖或访问包源。缺少既有镜像/卷时停止排查，不静默改用生产镜像。
- 启动器用 `.preview-start.lock.local` 防止并发初始化，密钥先在空文件上设置私有权限，再写入并原子替换。异常中断留下锁时，先确认没有启动进程，再处理残留；不要自动删除未知锁或重建数据库。

## 隔离边界

| 项目 | 预览 |
| --- | --- |
| Compose 项目 | 复用 `hrm`，只更新 API/Web |
| 数据库 | 新建 `hrm_preview`，独立同名登录角色；保留旧 `kayford_perf` |
| 文件 | 开发 MinIO 的独立 `hrm-preview` 桶 |
| 缓存 | 开发 Redis DB 9 |
| 身份 | 八个固定虚构测试身份，独立 JWT/档案/AI 加密密钥 |
| 网络 | Web 仅绑定 `127.0.0.1:5173`；API 只加入 internal 网络、不发布端口 |
| 外部能力 | 钉钉凭据为空，通知/日程/机器人/档案助手关闭；API 无外网出口 |
| 本地环境文件 | 用空文件覆盖容器 `/app/.env`，不继承原 API 本地密钥 |

初始化遇到“已有库或角色但缺少本机配置”会拒绝运行，不接管未知数据库。已有初始化标记时不覆盖用户改动，不提供自动重置/清空命令。

预览的虚构主管有四名真实关联的虚构下属。初始未造绩效周期和任务，须按当次验收需求创建；不能把角色标签当成已走通对应周期的证据。

## 尚需独立验收

- 此入口不验证真实钉钉扫码、日程或消息投递。第三方集成需另行限定身份与发送范围。
- 当前仅本机可访问，手机尺寸测试使用浏览器模拟，不代表其他电脑/手机可通过公网打开。
- 预览 Web 使用开发热更新，不等同于生产构建产物。正式发布仍需核对最终构建参数、授权和受影响路径。
