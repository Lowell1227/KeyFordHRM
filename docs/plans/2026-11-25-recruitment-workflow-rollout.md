## 工作包和契约（开工拆分，现状见下方当前进度）

1. **意向需求与完整岗位进度（进行中，主执行）**：新增可空的应聘 `intentDemandId`、`sourceChannel`，不回填历史。创建或早期编辑经现有经办权限及当前版本校验，关联部门/岗位必须匹配，改归属须原因及审计。意向不占名额，不覆盖 `recruitmentDemandId/Revision/Snapshot`。收件确认复用旧应聘时不静默换需求或来源。岗位进度复用原 `/recruitment-demands/:id/applications`，按唯一应聘与正式录用关联分层，收件单独计数/跳转。
2. **原工作台待办（待开发）**：追加 `intake_review`、`intake_assignment`、`entry_overdue`。经办收件仅本人负责，归岗不明/待核对不重复归类；现有窄角色不扩权。逾期用北京时间，点击原收件/应聘/入职单，改期、终止、到岗后消失。
3. **招聘进度留痕与渠道分析（待开发）**：需求独立 `trackingState`（recruiting/filled/paused/cancelled）及办理审计；它不改上游审批、在办应聘或名额。关闭前展示在办人员/外部职位，外部职位处理仍手工登记。分析按唯一应聘、经办核定的应聘来源和期间，可查明细；空来源单列，不从候选人旧来源倒填。
4. **集成、严格档验收和发布（待开发）**：一次集中 API 全量/构建，关联事务与权限集成，Web 类型/构建、PC/手机真实后端回归。保护全部预览旧资料及正式档案维护，备份/恢复校验、兼容回退、固定提交，仅更新 API/Web，外网及正式角色只读冒烟。
