# 身份证加密导出 Implementation Plan

> **For agentic workers:** 使用 superpowers:executing-plans 逐项实施，保留其他会话未提交的绩效页面改动。

**Goal:** 有档案权限的HR/管理员选身份证后，验证本人账号密码，导出以独立密码加密的XLSX。

**Architecture:** 保留普通GET导出；身份证仅经POST请求体提交密码，后端先校验权限/本人密码再读取敏感列，复用原数据范围和审计。ExcelJS生成后用Office Agile文件加密，纯内存处理。

**Tech Stack:** NestJS/Prisma、Vue/Element Plus、ExcelJS、officecrypto-tool。

**Spec:** 用户2026-11-18确认“验证账号密码，并设置Excel打开密码”。文件密码至少8位、最多64位，不同于账号密码，前端重复输入；只在当前弹窗内短暂保留。账号未设密码或要求改密时，提示先在个人中心设置/修改；失败保留字段选择但清空密码。

## Global Constraints

- 不修改现有员工、入离职、导出范围或组织维护权限；身份证不默认选择。
- 不在URL、浏览器持久存储、日志、审计中保存身份证或密码；敏感响应禁止缓存。
- 错误密码走字段错误，不将操作人登出；限制本人密码尝试次数，文件加密置于工作线程，限制并发。
- 不在正式库验证导出真实身份证；使用虚构加密资料与独立解密器验密。

## Review Focus

- GET及缺密码POST不能绕过保护；组织维护人员不可导出身份证。
- 错密码/需要改密/离职账号必须在读取敏感档案前拒绝。
- 取消勾选、关窗、重开、请求失败均清理密码，不影响普通导出。
- 文件必须整文件加密，正确密码还原，错误密码拒绝；号码作为文本保留前导零。
- 后端解密失败不退回明文或空白文件，审计仅列名/计数/加密标记。
