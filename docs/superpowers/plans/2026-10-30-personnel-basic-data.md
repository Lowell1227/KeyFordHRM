# 人员基础资料实施计划

目标：交付统一基础资料入口与工作地点/职系目录，填写处就近新增，原表单和历史名称保持。

1. API：先针对现有目录方式写失败测试，新增表/迁移、kind限定、DTO、接口、权限、事务审计。目录只写新表；全量 API 测试及构建。
2. Web目录/共享选择器：先写直接覆盖交互的 Playwright，再实现两种目录的列表与输入旁新增、刷新、保留原值、错误/重复处理。实现独立接口与权限辅助函数。
3. 导航及表单：统一 /basic-data 标签入口，兼容旧 URL；复用原合同主体/岗位组件，接入员工新建、档案编辑、岗位的职系与工作地点。保留原审核、脏数据和旧测试覆盖。
4. 联合检查：API 权限、名称和并发冲突；Web PC/平板/手机角色与表单流程；实际隔离HTTP/数据库迁移验证，不写生产或真实档案。
5. 独立复核并修正，记录实际实现/测试/提交/发布状态。不要以构建代替业务验收，不顺带提交其他任务修改。

决策：用户已选本轮范围并要求直接做好体验。名称快照继续用原字符串字段，避免为本轮基础选项重做档案/任职数据模型与审核；无历史数据回填。权限复用既有能力，无账号授权变更。
