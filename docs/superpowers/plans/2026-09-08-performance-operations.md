# 绩效运营权限与流程衔接实施清单

> 使用 subagent-driven-development 分工实施并独立审查；用户已要求整理、优化并上线，延续 main 发布授权。

## 目标与已确认范围

整理本轮讨论，补齐绩效专员、启动前审批链核对、后续详情统一。基线为 main/origin/main/生产 API/Web `49fd46d`。

已上线：月度跟进参考及汇总同步、周期均分与独立等级/评语、ABCD 展示、待办状态、合并部门复核、部门成员历史、关键节点意见。此次不重复实现。

本轮交付：
- 管理员可给 HR 配置“绩效专员”权限组合，包含周期创建管理、结果公示。沿用 HR 能力配置，不新增一套身份系统。
- 专员管理自己负责或明确分配的周期，以现有周期负责人 hrOwnerId 表示分配；公示必须经过审批。校准与最终审批维持各自职责。
- 绩效启动审批链优先读取本部门明确审批人、向上继承明确审批人；默认关系来源必须展示，不把父部门负责人直接当作已确认的分管审批人。只影响新启动的任务快照，不改已启动周期。
- 在启动检查中展示实际绩效直属上级、部门复核人、结果审批人及来源。
- 部门复核、校准、结果审批等详情采用共同的信息结构，显示周期、员工、阶段、结果、关键节点意见；公示列表保留已发布记录并区分待审批、待公示。

## 边界

- 不修改任何真实员工角色、部门或任务审批快照，不指定未经确认的分管总；管理员在上线后通过配置入口分配专员。
- 不回填旧审批记录、不修改绩效结果；不发送测试钉钉消息。
- 管理员及原有 HR 管理员权限兼容；专员权限不包含全局校准、最终审批、人事档案或系统设置。
- 本人公示前的绩效结果仍按既有规则遮罩；不能通过公示管理提前查看。
- 沿用现有模型，优先无需数据库迁移；所有新权限必须在后端落实。
