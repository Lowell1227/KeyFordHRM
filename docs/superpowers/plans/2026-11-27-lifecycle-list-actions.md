# 终止、逻辑删除与列表操作补齐

## 基线与约束

- 工作树`performance-response-fix-20261126/HRM`，基线`75ab426d`；现场main与远端一致，生产API`e75ceeae`、Web`b500f517`，0.9.3。其他工作树不改动。
- 用户明确要求给指定绩效专员目标台账终止/删除权限、已终止周期可逻辑删除，并核查列表操作入口。名称仍叫“删除”，不开发恢复或物理清除，不代办真实业务删除。
- 用户后续确认：指定专员原管理范围不变，只同步原HR负责人已有的终止/删除动作；不追加全局查看、人事或薪酬权限。删除周期连同所属任务一起逻辑删除。周期删除沿用指定专员/原HR负责人两位的明确授权及原周期范围。
- 本期先复用已有列表、后端allowedActions、原原因/版本/审计/409保护，不另建管理台账；招聘、人事、薪酬等其他列表只盘点既有动作，不凭UI需求新增销毁、撤销或薪酬权限。

- [x] 现有两项绩效终止/删除已通过正式可审计服务补给指定专员，原角色、全局可见标志及其他能力不变；原HR负责人不改。新周期删除能力随技术交付另配置，不混同本项。
- [x] 已终止周期连同所属任务、相应已结束目标变更一起逻辑删除：保留原周期/任务/结果/审计，独立鉴权、状态及并发校验，有未办结事项就整体拒绝，不影响独立改进/转正或薪酬。
- [x] 统一周期旧草稿的实体删除为经核验的逻辑删除；不借此改变当前草稿编辑/审核边界，不直接复用旧DELETE实现处理已启动周期。
- [x] 名称统一为“删除”；列表成功后更新当前页，已删除记录不再出现在普通列表，历史访问沿用原权限，恢复功能另议。
- [x] 严格档最终API及关联真实数据库验证、Web类型/构建、固定预览PC/手机实际页面验证。先复用未变范围证据，最后按实际权限/模型变更范围集中全量API。
- [x] 分开交付实现/提交/上线/业务签收；新功能已交预览，尚未提交/发布或业务签收，生产仅明确授权的两项原有能力追加。

## 最小验收

有权经办在原列表操作列完成原因填写和明确提交；无权、进行中不可删除、保护结果不可终止、已删除无重复动作。409/403保留原因且不得盲重试，筛选/分页和原详情仍可用。周期删除与个人办理竞争不得部分成功，撤权后排队写入拒绝。正式只核授权和入口，不添加虚构员工、不终止或删除真实记录。

## 实现约定

独立显式能力`cycle_delete`不随HR/管理员角色隐含获得，沿原周期归属；未启动草稿继续沿原编辑资格，但删除改为逻辑删除。新增完整删除影响预览、hash、原因和二次确认；所有所属任务及目标变更须符合原删除条件，原事务一次锁定、重核并写入。已删除周期默认不列出，可按“已删除/全部记录”查看；原参与者的历史读取权限不扩张，结果报表仍保留已经办结的有效事实。新增数据库元数据及防物理删除/防再写围栏，已应用迁移只追加不改写。

## 最终复核处理

- 独立只读评审2项P2：已公示确认但未归档的有效结果删除后漏归档；改进计划末页唯一行删除后空页。两项均由直接回归先失败后通过，未降低原断言。
- 归档格式提取为普通关闭和逻辑删除共用的纯函数；删除只补缺失快照，不覆盖已有快照；Scheduler按期间→任务→周期同序加锁，在ReadCommitted锁后重核已删除，避免并发旧候选再写。真实PG最终57项通过，含已有档案、保留得分及两连接自动归档排队。
- 原44项组件完整通过，新末页回归修复后单项通过；全量API302套6052通过，收尾影响的周期/归档/调度/报表4套141追加通过，相关源/测试类型通过。Web最终类型/构建和最新后端PC/手机最终2组通过，未发布。
- Ruling: 草稿维持原编辑资格；已终止周期另需显式删除；独立改进/转正/薪酬不级联；不提供恢复，均来自已确认范围，不增加隐含授权。若范围理解有误，需另行授权设计，不能直接扩大。
