# 员工档案生命周期交付验证

## 范围

已确认设计：四步新增员工、自动保存与草稿续填、办理中、退回后原申请重提、任职/合同/变更历史、手动归档和取消归档、入离职日期与账号准入一致。

- 一人一个主档；再入职产生新工号，历史工号不重新用于登录。
- 基础档案和绩效关系独立生效；一次审核勾选的同一申请整体成功或回滚。
- 普通 HR 提交，HR 管理员审核，允许管理员自审；未扩大管理权限。
- 已生效部分不能通过退回续填改写；只重提被退回的绩效关系。
- 离职最后工作日仍可使用，次日北京时间零点停用；已过日期的审核立即执行。
- 未来离职撤回按申请审计快照恢复原任职区间，保留申请与审计历史。
- 归档和取消归档是手动展示管理，不恢复任职或登录；批量逐条反馈。
- 新 JWT 校验当前任职工号和实时权限，发布后旧版会话需要重新登录。

## 新鲜验证

- API 全量：98 suites / 1130 tests 全通过；`npm run build` 成功。
- 独立 PostgreSQL、真实 Nest HTTP：11 / 11 全通过。测试入口 `api/test/jest-personnel-lifecycle.config.json`，仅允许 loopback 的 `hrm_lifecycle_test` 数据库，禁止指向生产。
- Web：类型检查和生产构建成功；15/23/32/54/58 五组 Playwright 覆盖列表、审核、维护、离职归档、四步向导。包含 1440、1024、390 像素布局。
- 独立代码复核发现并关闭：同日离职再入职记录顺序、部分退回无法原申请重提、未来离职无法撤回、旧工号被普通修改复活。
- 发布前生产只读核对：114 个在职/试用期员工账号，均有当前已审核的有效任职，没有缺失或当前离职记录。
- 没有新增数据库迁移；未批量改写真实员工主档，未启用正式测试快捷登录。
