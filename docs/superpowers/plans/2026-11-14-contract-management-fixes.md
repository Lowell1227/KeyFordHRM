# 合同子表修复与发布计划

**Goal:** 修复合同显示、导出、输入校验和附件提交问题，保留历史凭据与权限边界。
**Architecture:** 沿用员工合同表、档案显式提交事务和既有变更记录；无数据模型迁移、无批量历史清理。
**Tech Stack:** Vue 3 / Element Plus / NestJS / Prisma / PostgreSQL / ExcelJS。
**Spec:** `docs/acceptance/2026-11-13-contract-management-audit.md`；用户2026-11-14确认的以下规则优先于审查建议。

## 已确认范围

- 用户已授权本轮修复后上线；不再另建“待生效合同”分类。
- 页面只分“当前合同”和默认折叠的“历史合同”。当前合同指最近生效日期的一份未移除主合同，可处于待生效；时间状态另行显示待生效、正常、已到期等。
- 生效日期明确的主合同优先，均缺少生效日期时才参考签订日期；历史缺项保留可读及待补标记，不补造日期。时间状态按北京时间业务日。
- 首签、续签、转签为类型；劳动合同等为独立名称。保留旧类型原文，不改历史内容。
- Excel默认包含当前合同，不默认输出历史合同工作表；历史按需勾选。权限及已应用员工筛选不变。
- 新合同生效后替代原合同的业务约定不等于删除原记录或改写其签订/到期日期。
- 正式历史重复记录只核对、不自动删除、合并或迁移；旧版本必须可追溯。原未跟踪产物不提交。

## 工作项

- [x] 展示与导出：补签/转签反序、待生效、已到期、旧版本、附件类型不抢占主合同回归；统一当前合同选择、标签及默认导出。API导出3套22项、Web工具11项、展示Playwright桩数据3项通过，真实预览另计。
- [x] 表单：首签标签、合法日期/起止关系就近错误、上传中/失败禁止提交、在途数量、迟到回调隔离、移除撤销、准确变更摘要。真实日期控件PC/手机8项、合同技术测试35项及类型检查通过。
- [x] API：对新建或变更合同校验合法日期/起止关系和重复内容；保持旧缺项兼容，不修改非合同权限或审核规则。修复DTO隐式转换对象行问题；档案模块40套535项、最终全量158套2505项及API构建通过。
- [x] 集成：隔离真实预览PC/手机8项通过，真实后端办理并导出回读、上传字节核验；不用内存桩替代页面验收。
- [ ] 集中验证：API全量及关联集成、API构建、Web类型检查/构建和直接覆盖问题的Playwright；记录现有测试债务。
- [ ] 发布：核对差异，只提交本任务文件并推送；备份、保留回滚镜像，只替换API/Web，外部健康与受影响路径冒烟。

## 不扩展范围

不新建合同审批流、电子签章、提醒任务或合同法务状态，不重跑历史初始化，不新增第三套环境，不修改真实员工样本，不将数据记录停用等同于法律意义合同终止。

## 验收重点

1. 首签签订日晚于转签但生效日更早，当前与导出选择转签。
2. 待生效标签变化不需要新分类；历史默认折叠，默认导出没有历史工作表。
3. 新增非法日历日期、到期早于生效和完全重复新合同被拒绝；旧不完整数据不被静默改写。
4. 上传中、上传失败、并发上传超过限制、切换记录与取消编辑不会漏附件或污染其他合同。
5. 修改/移除可核对准确对象，附件替换展示具体差异，权限及草稿/正式提交边界保持。
