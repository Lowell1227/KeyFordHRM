# HRM 业务列表页面模板与建设技能设计

## 背景

HRM 已经通过 `QueryFilterPanel`、`ListPagination`、`MobileResultCard`、全局表格样式和 2026-09-09 的查询列表设计，统一了部分查询、分页和移动端展示。但新增列表页面仍需重复组合页面标题、主操作、查询区、桌面表格、手机卡片、分页、详情容器和响应式样式；现有页面也继续存在详情方式、操作区、列宽、滚动和移动端行为不一致的问题。

本设计在既有查询列表标准上继续收敛页面级结构，不重复创建查询、分页或手机卡片能力。

## 目标

1. 新增普通业务列表页面时，可直接选择标准模板并填入业务字段、权限和动作。
2. 将现有普通管理列表、流程任务列表和主数据分栏列表分批迁移到统一页面结构。
3. 统一 PC 与手机端的详情打开方式、返回行为、滚动、底部操作和错误保留。
4. 将选择模板、接入业务、验证页面和报告结果的步骤沉淀为 `hrm-business-page-builder` 技能。
5. 保持现有 API、权限、数据范围、业务流程和正式数据不变。

## 非目标

- 不建设 JSON 配置驱动的万能列表或万能表单引擎。
- 不把业务字段、复杂表格单元格、角色动作或接口调用放进通用组件。
- 不强制 Dashboard、Reports、CycleWorkspace、复杂校准工作台等页面套用普通列表模板。
- 不借迁移调整业务文案、审批规则、角色能力、路由权限或数据口径。
- 本设计不包含生产发布；后续上线仍需用户明确授权。

## 总体架构

### 运行时基础组件

在 `web/src/components/common/business-list/` 增加三个薄组件。

#### `BusinessListPage.vue`

职责：

- 统一页面标题、辅助说明、主操作、查询区、结果区、分页和详情承载位置。
- 提供 `title`、`subtitle`、`primary-action`、`filters`、`desktop-list`、`mobile-list`、`pagination` 和 `detail` 插槽。
- 统一列表页高度、最小宽度、结果区伸缩和移动端堆叠。
- 允许业务页面决定是否展示标题辅助说明、批量操作或摘要上下文。

不负责数据请求、分页计算、字段定义、权限判断和业务状态。

#### `BusinessDetailDrawer.vue`

职责：

- 提供 `standard`、`workflow`、`wide` 三种尺寸；PC 使用右侧抽屉，手机自动全屏。
- 统一标题、业务对象摘要、状态区、可滚动正文和固定底部操作区。
- 支持加载态、保存中状态、关闭事件和未保存内容关闭保护。
- 保留业务页面传入的表单错误，不因请求失败或抽屉关闭拦截而清空内容。

不负责读取详情、提交业务数据、判断角色权限或生成流程操作。

#### `SplitListLayout.vue`

职责：

- PC 提供左侧组织或分类范围与右侧列表的稳定分栏。
- 手机将左侧范围转换为可打开的范围选择面板，列表保持单列。
- 统一左右区域最小宽度、滚动边界和选中范围摘要。

不负责组织树加载、数据范围推导和选择权限。

### 模板与技能资源

三套页面模板不作为万能运行时组件，而是作为 `hrm-business-page-builder` 的可复制模板资源。模板只组装上述公共组件和插槽，业务页面复制后直接填写实际代码，避免运行时出现大量 `variant` 条件。

项目内的页面规范文档是规则来源；本机 Codex 技能安装到 `C:\Users\lwei\.codex\skills\hrm-business-page-builder\`，负责执行流程和读取模板。技能模板必须引用项目实际组件，不另建一套样式。技能失效或迁移到其他机器时，仍可根据仓库内设计文档和公共组件恢复，不把项目标准只保存在本机技能目录中。

## 三种标准模板

### 1. 管理台账型

适用：申诉、面谈、指标、模板、岗位目录和其他查询维护台账。

结构：

1. 页面标题、简短说明和一个主要新增动作。
2. 无冗余标题的查询条件区。
3. PC 表格或手机业务卡片。
4. 结果底部分页。
5. 普通详情或轻量编辑抽屉。

详情默认使用 `standard` 抽屉。少量字段确认或退回原因继续使用弹窗，不使用弹窗承载完整详情。

### 2. 流程任务型

适用：转正、改进计划、审批、复核、公示和其他多角色办理列表。

结构：

1. 页面标题和当前角色下的主要发起动作。
2. 仅在有业务价值时展示待我处理、临近到期和当前数据范围。
3. 状态或环节切换、查询条件区。
4. PC 表格或手机业务卡片；当前责任和下一步操作优先展示。
5. 结果底部分页。
6. 可路由的 `workflow` 宽抽屉。

流程详情默认使用宽抽屉。抽屉顶部固定显示业务对象、当前状态和当前责任；正文滚动；底部固定展示当前角色可执行动作。手机端为全屏抽屉。

### 3. 主数据分栏型

适用：组织人员、人员名册及需要先选择范围再查看记录的页面。

结构：

1. 页面标题、主数据来源说明和主要新增动作。
2. PC 左侧范围树、右侧查询列表；手机以范围选择面板替代常驻树。
3. PC 表格或手机业务卡片。
4. 结果底部分页。
5. 查看和普通维护抽屉。

员工完整档案、跨多个独立业务域的长内容仍可进入独立详情页，不强行塞入抽屉。

## 路由抽屉规则

1. 流程详情使用列表页的子路由，打开详情时列表组件保持挂载。
2. 每条流程详情拥有稳定 URL，支持刷新、复制地址和直接访问。
3. 直接访问详情 URL 时先加载列表外壳，再打开对应抽屉。
4. 浏览器返回关闭抽屉，再次返回才离开列表。
5. 关闭抽屉后保留查询条件、页码、排序和列表滚动位置。
6. 抽屉中的保存、提交、通过或退回成功后，只刷新受影响的详情和列表数据。
7. 未保存内容存在时，关闭、返回或切换记录都需要明确提醒。
8. 禁止抽屉嵌套抽屉；辅助详情在当前抽屉中分区、折叠或使用短弹窗。
9. 弹窗仅用于二次确认、退回原因和少量字段输入。

## 数据流与错误处理

1. 列表页面维护查询条件、分页、排序和列表请求。
2. 查询、周期、排序或每页条数变化时回到第一页；关闭详情不重置列表状态。
3. 详情组件维护详情请求、表单状态和业务操作。
4. 通用外壳通过事件接收 `changed`、`closed` 和 `dirty-change`，不读取业务对象。
5. 操作成功后，业务页面更新详情并刷新当前列表；不存在的记录显示明确提示并关闭抽屉。
6. 字段校验错误贴近字段显示；汇总错误靠近对应操作区。
7. 网络失败保留用户输入。对于结果不确定的写请求，先读取最新业务状态再决定提示成功、继续等待或引导刷新，避免重复提交。
8. 权限失败不隐藏为通用网络错误；页面保留当前上下文并提示用户无权执行的真实动作。

## 响应式与可访问性

- 断点继续使用 768px。
- 1440px 和 1024px 显示完整表格；390px 显示业务卡片。
- 手机卡片展示 3 至 5 个当前决策必需字段，不机械复制所有表格列。
- 手机抽屉占满可用宽度和高度，顶部与底部操作不遮挡正文。
- 查询字段、主要操作和分页在窄屏自然重排，不使用整体缩放。
- 长姓名、长部门、长状态和长说明允许换行或省略并提供可查看完整内容的方式。
- 所有抽屉具有明确标题；图标操作保留可访问名称；键盘焦点不落入已关闭抽屉。

## 现有页面迁移

### 阶段 1：公共基础与代表页面

先实现三个基础组件和针对性组件测试，再选择代表页面验证：

- 管理台账型：`AppealsView.vue`
- 流程任务型：`ConfirmationManageView.vue`

代表页面通过 PC、手机、路由和角色回归后，模板与技能资源才能定版。

### 阶段 2：管理台账型迁移

迁移 `InterviewListView.vue`、`IndicatorLibraryView.vue`、`TemplateManageView.vue`、`PositionDirectoryView.vue` 及其他普通查询维护列表。

### 阶段 3：流程任务型迁移

迁移转正申请、转正审批、我的转正、试用期考核、部门复核、结果审批、结果公示、校准名单和改进计划列表。改进计划仅在执行时确认其工作区无其他未提交改动后迁移。

### 阶段 4：主数据分栏与剩余列表

迁移人员名册的其他列表区域和人事变更审核队列。Dashboard、Reports、CycleWorkspace、团队绩效工作台等复杂页面不在本轮模板迁移范围内，只继续复用基础颜色、间距、表格、分页和移动卡片规则。

### 脏工作区处理

每个迁移批次开始前运行 `git status --short --branch`。与当前批次重叠的未提交文件立即从该批次移除，不覆盖、不回退、不顺手提交。每个提交只暂存当前批次文件。

## `hrm-business-page-builder` 技能

### 触发条件

- 新增包含查询、列表、分页、详情或维护操作的 HRM 页面。
- 用户要求统一、重构或修正现有列表页面样式。
- 页面需要同时支持 PC 和手机。
- 页面需要选择抽屉、宽流程抽屉或独立详情页。

### 固定流程

1. 读取 `AGENTS.md`、项目记忆和本页面规范。
2. 检查工作区与相关页面近期提交，识别未提交冲突。
3. 判断页面属于管理台账、流程任务或主数据分栏；复杂工作台不强行归类。
4. 明确业务对象、查询条件、数据范围、桌面列、手机字段、状态、角色动作和详情复杂度。
5. 选择并复制对应模板，复用现有公共组件。
6. 保持 API、权限和业务状态不变；需要改变业务含义时停止并询问用户。
7. 先增加直接覆盖页面结构和交互的 Playwright 用例，再实施页面。
8. 验证 1440px、1024px、390px、长文本、空状态、加载失败、字段错误、抽屉返回和权限一致性。
9. 分别报告代码、测试、提交、上线和业务验收状态。

### 技能资源

- `SKILL.md`：触发规则、决策顺序、红线和验收流程。
- `templates/record-list-page.vue`：管理台账型骨架。
- `templates/workflow-list-page.vue`：流程任务型和路由宽抽屉骨架。
- `templates/split-master-list-page.vue`：主数据分栏型骨架。
- `references/acceptance-checklist.md`：PC、手机、抽屉、权限和状态验收表。

技能在代表页面完成后生成，以真实组件 API 和已通过的页面结构为准，避免先写出与代码不一致的模板。

## 测试与验收

### 组件级

- 插槽、尺寸、加载、空态、关闭保护和移动全屏行为。
- `BusinessListPage` 不读取业务数据，`BusinessDetailDrawer` 不调用业务 API。
- PC 表格和手机卡片切换不复制分页或权限状态。

### 页面级

- 查询、重置、分页、排序和打开详情。
- 详情子路由直接访问、刷新、浏览器返回和关闭。
- 保存、提交、退回成功后刷新当前记录，查询条件和页码保持。
- 未保存内容关闭提醒；网络失败保留填写内容。
- 有权限和无权限角色在 PC 与手机看到相同的数据范围和动作。
- 表头和表体列数、序号、列宽、行高及操作列一致。
- 1440px、1024px、390px 无页面级横向溢出。

### 工程验证

- 相关 Playwright 用例。
- `npm run type-check`。
- Web 生产构建。
- 每批迁移核对业务请求数量和接口参数，避免因布局重构产生重复请求或查询条件丢失。

构建通过、代码提交、生产发布和真实角色验收继续分别记录，不互相替代。

## 完成标准

1. 三个公共组件具有明确、稳定且无业务依赖的接口。
2. 三个代表页面分别证明三种模板可用。
3. 新页面可通过技能模板直接建立列表、响应式卡片和详情抽屉，不再重新编写整套页面骨架。
4. 本轮范围内现有普通列表分批迁移并通过对应回归。
5. 业务接口、权限、流程状态和正式数据未因样式统一发生变化。
6. 技能、模板和验收清单与最终实现一致。
