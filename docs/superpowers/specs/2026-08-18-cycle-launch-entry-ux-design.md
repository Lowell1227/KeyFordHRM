# 绩效周期发起入口交互优化设计

## 目标

让 HR 明确理解“新建周期”只是发起流程的第一步，并用更少判断完成常规季度周期配置。实际业务流程保持为：创建草稿、开放检查、修复阻断项、确认立即开放或预约开放。

## 设计决策

1. “待处理”改为“待发起”，空列表不再保留空表格和分页，而是解释当前没有待发起周期并提供创建入口；筛选后无结果则提供清空筛选。
2. 创建弹窗标题改为“创建绩效周期 · 基本信息”，主按钮改为“下一步：开放检查”，并明确说明该操作不会立即通知员工。
3. 考核范围必须显式选择“全公司”或“指定部门”。选择全公司时提交空部门数组；选择指定部门后才显示部门选择器。
4. 自动时间计划使用中性信息提示，不再使用成功态。摘要展示目标开放、周期开始、周期结束、自评开放四个关键节点。
5. 高级设置保留总开关，展开后按“参与范围与例外、时间节点、等级比例、公示范围”四组折叠。每组标题显示当前配置摘要，避免一次展示整面长表单。
6. 弹窗正文限制在视口内滚动，头部和底部操作保持可见；键盘焦点使用品牌色 `focus-visible`。

## 交互细节

- 默认考核范围为全公司。
- 切回全公司时清空已选择部门，避免隐藏字段继续生效。
- 指定部门但未选择部门时，点击保存或下一步应在范围区域就近提示。
- “参与范围与例外”中，全公司范围不显示无意义的“额外参与人员”；明确豁免人员仍可配置。
- 时间节点组提供“恢复默认计划”，只根据当前起止日期重新计算时间节点，不覆盖名称、负责人、范围、等级和公示设置。
- 继续保留“保存草稿”和未保存关闭确认。

## 验收标准

1. 待发起列表为空时显示业务空状态、创建按钮，并隐藏分页。
2. 创建弹窗明确显示三步流程中的第一步，主按钮不再暗示已经发起。
3. 全公司与指定部门行为和提交数据一致，指定部门为空时无法提交。
4. 关键时间线首屏可见，高级设置四组默认收起且摘要可见。
5. 展开高级设置后，弹窗底部操作始终可见；390px 下无横向溢出。
6. 不修改 API、权限、周期状态和开放检查规则。
