# 考核范围与审核链路展示修正

## 目的

让“考核范围”只表示真正参加考核的员工，不再把仅承担组织或审核职责的公司负责人混入范围；同时把周期标题下难懂的技术备注改成业务人员能理解的目标审核链路。

## 已确认口径

- 已发起周期：隐藏并从范围统计中排除历史 `top_leader_exempt` 技术记录；保留数据库历史记录，不修改目标、评分或审批轨迹。
- 新周期：不再把公司负责人强制加入人员范围，也不再为其生成“最高负责人豁免”任务。
- 公司负责人不再出现在周期详情中；绩效审批仍以各员工任务冻结的分管领导为最终节点。

## 展示方案

- 周期标题下保留一条蓝色业务提示：`目标审核流程：员工填写 → 绩效直属上级 → 部门负责人 → 员工确认 → 分管领导`。
- 删除标题下的“周期结束统一评分”“已调整月份：0个”“公司负责人（不参与绩效审批）”三项技术备注。
- “人员明细”按每名员工显示实际冻结的绩效直属上级、部门负责人和分管领导；多人周期不在标题区拼接姓名。
- 同一人兼任多个环节时仍按角色分别展示姓名，便于解释实际链路；流程办理继续沿用既定的同人合并和跳过本人规则。

## 实现边界

- 后端未来发起计划直接使用所选人员，不再调用公司负责人注入逻辑。
- 已发起周期的参与记录接口过滤 `top_leader_exempt`，并用过滤后的列表计算总人数、参与人数和豁免人数。
- 参与记录补充冻结的部门负责人和分管领导姓名，前端只读展示。
- 不删除历史任务、不回写生产考核数据、不修改审批状态，也不新增权限或数据库迁移。

## 考虑过的方案

1. **仅前端隐藏（不采用）**：改动最小，但未来仍会生成无意义任务，人数语义继续错误。
2. **范围语义与展示同时修正（采用）**：未来不再注入，历史记录在接口层排除，页面展示真实审核链路；兼顾正确性与历史留痕。
3. **删除历史豁免任务（不采用）**：能清理数据，但会改动已发起周期及审计基线，没有必要。

## 验收标准

- 金茜茜试用期周期显示范围 1 人、参与 1 人、豁免 0 人，人员明细不出现李宏。
- 新建仅选择一名员工的周期，发起检查和发起记录都只有该员工，不生成公司负责人的豁免任务。
- 标题区只显示目标审核角色链，不再显示旧三项备注。
- 人员明细能看到每名员工的实际绩效直属上级、部门负责人和分管领导。
