# 目标地图画布式关系图重构设计

## 目标

保留 KeyFord HRM 当前应用外壳、绩效二级导航、目标权限与目标管理能力，将 `/objectives` 的树形表格完整重构为参考图所示的浅灰蓝画布式目标关系图。

页面必须让管理者直接看懂公司目标、部门目标与个人目标之间的承接关系。参考图没有展示部门目标和上级目标的完整样式，本设计补充为三级关系：公司或上级目标位于上方，部门目标位于中间，个人目标位于下方，并使用连接线表达 `parentId` 关系。

## 已确认边界

- 保留 KeyFord 顶部栏、蓝色主导航和绩效二级导航，不复制参考系统的品牌外壳。
- 保留页面标题“目标地图”和右上角“新建目标”按钮。
- 重构范围仅限目标地图内容区及其测试；目标跟进、绩效待办和其他模块不随之改版。
- 使用现有目标、周期、部门、用户和指标数据，不新增虚构业务目标。
- 继续使用现有路由、角色权限、数据范围、CRUD 接口和 Prisma 模型。
- 普通员工仍不能进入目标地图；管理者、部门负责人、VP、HR、董事长和系统管理员沿用现有可见范围。

## 方案选择

### 采用：现有目标树加原生 SVG/CSS 画布

前端继续请求现有目标树，将可见节点规范化后计算三级布局。卡片使用 Vue 模板和 CSS 渲染，连接线使用覆盖在卡片层下方的 SVG 渲染。平移和缩放由页面自身管理。

该方案不引入依赖，不改变接口，容易精确还原参考图的卡片、留白、阴影、悬浮工具栏和缩放控件，也便于把布局计算抽成纯函数测试。

### 不采用：图形库

Vue Flow 等图形库能提供现成的缩放和连线，但会增加依赖、默认交互和 DOM 结构，反而需要大量覆盖才能贴近参考图。当前目标关系只有三层，不值得引入该复杂度。

### 不采用：后端专用地图聚合接口

现有 `/objectives` 和 `/objectives/tree` 已返回 `parentId`、`children`、层级、负责人、部门和进度，足以计算画布。新增接口会扩大测试和维护边界，但没有增加业务价值。

## 页面结构

`PerformanceWorkspace` 继续提供标题栏和左侧“目标跟进 / 目标地图 / 绩效待办”导航，目标地图继续传入 `show-context=false`。

内容区不再使用白色表格卡片，而是占满剩余高度的画布：

1. 左上角是白色浮动筛选条。
2. 右上角是白色浮动排序和显示设置条。
3. 中间是可平移、可缩放的目标关系图。
4. 左下角是定位、缩小、缩放比例和放大控件。
5. 加载、空状态和错误状态在画布中心展示，但不改变工具条位置。

桌面端画布至少占满工作区可用高度，不因目标数量较少收缩。移动端保留相同信息结构，工具条允许横向滚动，画布维持可拖动和缩放，不把三级关系强制压成表格。

## 浮动筛选条

筛选条在视觉上贴近参考图：白色背景、轻阴影、小圆角和紧凑间距。包含：

- 周期选择器：使用日历图标和“周期：”前缀，默认优先选中当前有效周期；无法确定当前周期时保留“全部周期”。
- 我的目标。
- 我团队成员的目标。
- 我负责组织的目标。
- 其他目标。

管理者默认选择“我团队成员的目标”。若当前角色没有直属成员，则回退到第一个有数据的范围，最终回退到“其他目标”。

范围含义如下：

- **我的目标：** 当前登录用户负责的个人目标，以及这些目标可见的部门和公司祖先。
- **我团队成员的目标：** 当前用户直接下属负责的个人目标，以及对应部门和公司祖先。直属成员集合继续使用现有用户数据范围，不扩大到无权查看的员工。
- **我负责组织的目标：** 当前用户作为负责人或管理范围内的部门目标、其可见公司祖先及相应个人子目标。
- **其他目标：** 当前接口已经授权、但不属于前三个范围的目标。它不是全公司越权查询。

任何范围都先选出业务目标，再补齐接口结果中可见的祖先节点，保证连接关系完整。祖先不在接口结果中时不请求、不构造、不显示其名称。

## 关系图与布局

### 层级

画布采用从上到下的三级布局：

- 第一层：公司目标或当前可见链路中的上级目标。
- 第二层：部门目标。
- 第三层：个人目标。

每个目标只渲染一次。真实 `parentId` 决定连接关系；不依据标题、部门名称或显示顺序猜测父子关系。

若筛选结果中只有部门目标或个人目标且其父级不可见，该节点成为当前画布的可见根节点，不渲染虚假的“隐藏上级”卡片。孤立目标仍可显示，但不创建伪连线。

### 排列

布局逻辑抽成无 DOM 依赖的纯函数，输入为规范化节点和显示选项，输出卡片坐标、画布边界和连接线端点。

- 同一父目标的子目标水平排列。
- 父目标水平居中于其可见子目标组上方。
- 不同目标组之间保留大于卡片间距的组间留白。
- 默认按“对齐数量”排序：子孙节点较多的分支靠近画布中心，其次按优先级和创建顺序稳定排序。
- 关闭某个层级后重新布局，不能只隐藏卡片后留下空洞。
- 画布尺寸由布局结果决定，并额外保留四周安全留白。

默认首次加载和每次切换周期、范围后自动居中。用户手动平移或缩放后，普通数据刷新尽量保留当前视口；显示层级变化时重新适配居中。

## 目标卡片

卡片尺寸、圆角、白色背景、轻阴影和信息密度贴近参考图。所有卡片包含：

- 层级色块：公司、部门或个人。
- 负责人名称；负责人缺失时显示部门名称，再缺失时显示“未指定负责人”。
- 目标标题。
- 右下角进度标签，使用暖黄色背景和百分比文本。

部门目标额外显示所属部门。公司或上级目标使用较稳重的深蓝层级色，部门目标使用靛蓝，个人目标使用参考图的青色。层级不能只依赖颜色表达，必须同时显示文字。

鼠标悬停时提升阴影并显示右上角更多操作按钮；键盘聚焦时提供同等可见的焦点样式。只读角色不出现写操作。

## 连接线

连接线位于卡片下方的 SVG 层，从父卡片底部中心连接到子卡片顶部中心。使用低对比度蓝灰色正交或平滑折线，避免穿过卡片。

线条不承担唯一语义：卡片层级文字和空间位置仍能表达关系。显示设置可关闭连接线；关闭后卡片布局保持不变。

## 画布交互

- 拖动空白区域平移画布。
- 鼠标滚轮在指针位置缩放。
- 左下角减号和加号以固定步长缩放。
- 缩放范围为 50% 到 150%，默认 100%。
- 百分比显示当前缩放值。
- 定位按钮重新计算适配比例并居中全部可见节点。
- 拖动卡片不移动节点，只触发点击或悬浮操作，避免误操作布局。
- 切换筛选前取消未完成的旧请求或忽略过期响应，防止快速切换后显示错误数据。

## 排序与显示设置

右上工具条默认显示“排序：按对齐数量”。本轮只实现这一种排序规则，不增加没有业务依据的其他排序选项。

“显示设置”使用弹出面板，包含：

- 显示公司或上级目标。
- 显示部门目标。
- 显示负责人。
- 显示进度。
- 显示连接线。

个人目标始终显示，因为它是地图最小业务节点。若关闭上级或部门层级，仍依据剩余节点重新布局。显示设置仅保存在当前浏览器，不上传服务器；使用带版本的独立本地存储键，读取非法值时回退到默认配置。

## 目标业务操作

保留现有“新建目标”按钮和创建弹窗。卡片点击打开目标详情抽屉，展示现有字段：标题、描述、层级、负责人、部门、周期、权重、优先级、进度、状态和关联指标。

可管理角色在卡片更多菜单和详情抽屉中看到：

- 编辑目标。
- 更新进度。
- 进入目标跟进。
- 删除目标。

只读角色只可查看详情和进入允许的目标跟进。所有写操作继续调用现有接口并沿用当前后端授权；前端隐藏按钮不代替后端权限。

成功创建、编辑、更新进度或删除后刷新目标树并重新计算布局。删除仍使用现有确认提示，不能在卡片上提供无确认的快捷删除。

## 组件和代码边界

页面拆分为以下职责明确的单元：

- `ObjectiveMapView.vue`：加载权限内的业务数据、管理筛选、弹窗和写操作。
- `objective-map-layout.ts`：目标规范化、范围筛选、祖先补齐、稳定排序和坐标计算纯函数。
- `ObjectiveMapCanvas.vue`：画布视口、平移缩放、连接线、空状态和控制条。
- `ObjectiveMapCard.vue`：单个目标卡片、详情入口和可用操作事件。
- `ObjectiveMapFilters.vue`：周期和目标范围筛选。
- `ObjectiveMapDisplaySettings.vue`：显示选项及其本地持久化。

组件通过属性和事件传递数据，不在卡片或画布组件中直接请求 API。现有创建、编辑和进度弹窗可留在页面文件中；若页面尺寸明显失控，再做仅服务本页面的表单组件提取，不进行无关重构。

## 数据流

1. 页面加载周期和权限范围内的用户辅助数据。
2. 根据周期调用现有目标树接口，获得后端已经裁剪过的数据。
3. 将树展开为唯一节点集合，同时保留 `parentId`。
4. 根据当前范围选出目标并补齐可见祖先。
5. 应用显示设置和稳定排序。
6. 布局函数输出节点坐标、连接关系和画布边界。
7. 画布渲染 SVG 连接线与 HTML 卡片。
8. 写操作成功后重新请求目标树并重复以上流程。

接口失败时不复用上一周期的数据冒充当前结果。页面显示错误提示和“重新加载”动作；周期或辅助数据加载失败时，保留可操作的其他筛选，不扩大查询范围。

## 可访问性

- 筛选项使用真实按钮或单选语义并暴露选中状态。
- 目标卡片可通过键盘聚焦和激活。
- 缩放、定位、显示设置和更多操作提供中文无障碍名称。
- 进度既显示文字百分比，也提供可访问标签。
- 连接线标记为装饰性，不进入无障碍树。
- 对“减少动态效果”的系统设置关闭非必要的平滑缩放动画。

## 测试与验收

### 纯函数测试

- 公司、部门、个人三级节点产生稳定的父子坐标和连接线。
- 范围筛选只包含目标集合及其可见祖先。
- 父级不可见时不生成伪节点或伪连线。
- 按对齐数量排序在数量相同的情况下保持稳定。
- 关闭公司或部门层级后重新布局且无重叠。
- 空树、单节点、多根树和大量同级节点均返回有效边界。

### Playwright 行为测试

- 管理者进入 `/objectives` 后看到浮动筛选条、画布、右上显示设置和左下缩放控件，不再看到目标表格。
- 默认范围为“我团队成员的目标”，并渲染真实公司、部门和个人三级卡片与连接线。
- 切换周期和四种范围触发正确数据展示，不显示接口授权范围外的目标。
- 放大、缩小、拖动和重新定位改变视口且保持卡片可操作。
- 显示设置可隐藏层级、负责人、进度和连线，刷新后仍保留合法设置。
- 可管理角色可从卡片执行编辑、更新进度、目标跟进和带确认的删除。
- VP 等只读角色看不到写命令。
- 空数据和接口失败均显示画布内状态，不回退为旧表格。

### 视觉验收

在真实管理者账号和最新演示数据上，以 `1440x900` 为主要视口截图，与参考图逐项比较：

- 浅灰蓝画布面积和留白。
- 左上与右上浮动工具条的尺寸、位置、阴影和选中态。
- 三级目标卡片的尺寸、间距、层级色、文字密度和进度标签。
- 连接线是否清晰且不穿过卡片。
- 左下缩放控件的位置和视觉重量。
- 页面标题、KeyFord 导航和新建目标按钮是否保持现状。

同时在 `390x844` 检查筛选条可达性、画布拖动、卡片文字、操作菜单和弹窗不重叠。浏览器控制台不得出现错误，切换筛选、缩放和刷新后页面状态必须与界面一致。

最后运行前端类型检查、构建、目标地图相关 Playwright 用例和必要的后端目标服务测试。只有自动化验证及真实浏览器截图均完成后，才能报告视觉改造完成。

## 非目标

- 不复制参考系统的 Logo、顶部产品导航、客服、帮助、搜索或通知功能。
- 不开放普通员工的目标地图路由。
- 不增加跨权限查看“其他目标”的后门。
- 不支持自由拖拽并永久保存节点位置。
- 不增加新的目标层级、目标状态、排序字段或审批流程。
- 不改造目标跟进和绩效待办页面。
