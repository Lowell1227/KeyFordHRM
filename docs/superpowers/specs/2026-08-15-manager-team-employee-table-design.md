# 主管团队员工列表表格优化设计

## 目标

参考用户提供的主管员工列表截图，将现有团队绩效任务列表调整为信息清晰、行距紧凑的标准业务表格。复用现有团队任务接口与字段，不扩展后端、数据库或权限规则。

## 现状与参考图差异

当前列表将工号、职位、部门和考核周期压在员工单元格的两行文本中，桌面宽度下仍只有少量独立列；右侧操作使用无文字的眼睛图标。参考图使用稳定的横向表头，每个业务字段都有清晰列位，行高较低，批量操作、状态和行操作都能快速扫描。

本次采用“桌面完整表格、窄屏逐步合并”的方案，而不是固定宽表横向滚动或退回卡片列表。

## 桌面列结构

桌面内容宽度达到 980px 时按以下顺序显示：

1. 选择框：仅在当前指标审核的待处理队列中显示，继续使用现有可选择条件；
2. 员工：28px 小头像、姓名、工号；
3. 部门：显示 `deptName`，缺失时显示 `-`；
4. 职位：显示 `position`，缺失时显示 `-`；
5. 考核周期：显示 `cycleName`，超长时省略并提供悬浮提示；
6. 任务状态：主状态使用现有 `StatusBadge`，处理状态以较弱的补充文字展示；
7. 结果：优先显示 `totalScore`，其次显示 `rawGrade`，均为空时显示 `-`；
8. 更新时间：显示 `updatedAt` 的日期部分；
9. 操作：待处理任务显示“处理”，其他任务显示“查看”。

操作列固定在右侧。点击员工、整行或操作文字都继续打开同一个成员详情，不改变 URL、抽屉或处理权限。

## 列表密度与视觉

- 列表标题区保持“团队成员”和任务数量，批量通过/驳回位于右侧；
- 表头高度约 44px，数据行高度约 52px；
- 表头使用浅灰背景，正文使用白色背景和细分隔线；
- 姓名使用正文强调色，工号使用次要文字色；
- 选中行使用浅蓝背景并保留键盘焦点样式；
- 列表继续保持最小内容高度和底部分页，避免少量数据时页面跳动；
- 与上方筛选面板保持相同的左右边界和圆角体系。

## 响应式规则

### 中等内容宽度：640px 至 979px

- 保留选择框、员工、部门、职位、任务状态和操作；
- 隐藏独立的考核周期、结果和更新时间列；
- 将考核周期合并到员工次信息中；
- 操作仍使用“处理 / 查看”文字，不退回图标。

### 窄内容宽度：低于 640px

- 保留选择框、员工、任务状态和操作；
- 部门、职位和考核周期合并到员工次信息中；
- 员工次信息允许两行显示，但整行保持紧凑；
- 页面不得出现文档级横向滚动，列表内部也不依赖横向拖动才能处理任务。

## 行为与权限保持

- 批量选择仍只允许直属主管选择待处理的指标审核任务；
- 搜索、部门、员工、周期、状态和分页变化仍清除当前页选择；
- 当前行高亮、深链任务恢复、详情加载和错误状态保持现有行为；
- “处理”只改变文案，不扩大可处理权限；只读或已完成任务仍按现有详情逻辑展示；
- 空状态、加载状态、分页和批量结果提示不变。

## 技术范围

本次修改：

- `web/src/views/task/components/TeamTaskList.vue` 的列模板、响应式列计算、行操作和样式；
- 团队任务契约测试与响应式测试中的列、操作和布局断言。

本次不修改：

- `GET /tasks/team` 响应结构；
- 用户、周期或任务数据库字段；
- `TaskListView.vue` 的筛选、查询、详情和批量处理流程；
- 任何角色权限或绩效状态机。

## 验收标准

1. 周强在桌面宽度下看到独立的员工、部门、职位、考核周期、任务状态、结果、更新时间和操作列。
2. 员工姓名、工号、头像层级清晰，行高和参考图接近，不再呈现为大块员工卡片。
3. 张晨待处理任务显示“处理”，点击后能打开可保存、通过和驳回的详情；已完成任务显示“查看”。
4. 批量复选框及批量通过/驳回权限不变。
5. 中等宽度和 390px 宽度下按设计合并次要信息，无文档级横向溢出。
6. 团队契约测试、相关响应式测试、类型检查和生产构建通过。
7. 真实周强页面完成桌面和窄屏截图复核，且没有新增控制台错误。
