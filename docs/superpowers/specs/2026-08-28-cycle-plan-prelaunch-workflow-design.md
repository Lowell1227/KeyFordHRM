# 绩效周期计划创建至正式发起工作流设计

## 文档状态

- 日期：2026-08-28
- 状态：业务设计已逐项确认，等待书面设计审核
- 范围：绩效周期从创建、检查、审核到立即或预约发起的完整管理流程
- 非开发状态：本文只记录已确认的业务与交互规则，不代表功能已经实施或发布

## 1. 背景与目标

当前“周期与计划”将草稿、检查、审核和发起混合展示，存在以下问题：

1. “草稿 + 审核通过”等组合文案不能直接表达当前业务状态，也不能告诉 HR 下一步做什么。
2. “待发起”既被用作列表大类，又被用作审核通过后的精确状态，含义重复。
3. 创建页使用“发起检查、开放检查、开放周期、立即发起”等近义词，增加理解成本。
4. 创建后的检查、审核、预约和发起缺少一条连续、可追溯的工作流。
5. 编辑周期时，旧的“指定审核人”选人控件依赖通用用户接口，周期编辑权限、用户详情权限和会话权限不一致，可能产生两个 `403` 请求并把审核人显示为原始 UUID。
6. 发起后的员工任务属于员工和直属上级的绩效子流程，不应在周期管理详情中重复建设另一套任务页面。

本设计的目标是：

- 让每个精确状态只表达一个业务含义；
- 让普通 HR、HR 管理员和查看者都能直接看到自己的下一步；
- 将计划检查、计划审核、预约发起和正式发起组成一条完整且可回退的工作流；
- 保留审批和执行历史，但不让日志干扰当前操作；
- 在正式发起后复用现有绩效待办页面；
- 修复周期编辑对员工档案类用户接口的错误耦合，不扩大员工档案权限。

## 2. 统一术语

四个固定流程阶段为：

```text
配置计划 -> 计划检查 -> 计划审核 -> 正式发起
```

术语使用规则：

- `提交`：只表示普通 HR 将计划提交给 HR 管理员审核。
- `审核`：只表示 HR 管理员审核计划。
- `发起`：只表示正式生成员工绩效任务并进入进行中。
- `开放`：只用于具体节点时间，例如“目标制定开放时间”“员工自评开放时间”，不再作为周期整体动作名称。
- 第二阶段统一叫`计划检查`，不再叫“发起检查”或“开放检查”。
- 创建页底部继续保留`取消 / 保存草稿 / 下一步`。
- 审核和名单变化处理统一使用`退回`，不再混用“驳回”。

## 3. 范围与非目标

### 3.1 本次范围

- 周期列表和详情的信息架构；
- 周期创建、草稿保存和计划检查；
- HR 管理员审核；
- 立即发起、预约发起、取消或修改预约；
- 发起前重新检查、人员变化确认、业务阻断和技术失败；
- 计划负责人变更、删除草稿、作废计划；
- 流程记录和管理侧通知；
- 周期专用候选人员查询和权限会话一致性；
- 创建至发起边界的测试与验收。

### 3.2 非目标

- 不重做员工和直属上级当前使用的绩效待办页面。
- 不在本设计中展开员工自评、直属上级评分、结果确认、公示和后续归档的完整状态机。
- 不在本设计阶段修改代码、真实业务数据或生产环境。
- 不把钉钉组织或通讯录作为人员范围、直属上级或权限的数据源。
- 不借周期选人功能扩大普通 HR 对员工档案敏感字段的访问权限。

## 4. 角色、负责人和权限

### 4.1 角色定义

- 普通 HR：创建和维护计划、运行计划检查、提交审核、处理退回和业务阻断。
- HR 管理员：审核计划、确认发起前人员变化、立即或预约发起、处理发起失败。
- 其他 HR：可查看全部周期计划和完整流程记录，但不能直接修改非本人负责的计划。
- 员工和直属上级：正式发起后从现有绩效待办进入各自子流程，不进入周期管理后台操作。

当前只有一名 HR 管理员并不产生隐藏例外规则。HR 管理员创建计划后仍须进入独立审核动作，可以审核本人创建的计划，系统分别记录创建和审核行为。

### 4.2 创建人与当前负责人

- 创建人永久记录，不随工作交接改变。
- 新计划默认由创建人担任当前负责人。
- 当前负责人负责编辑草稿、运行检查、提交审核、处理退回和发起阻断，并接收相应通知。
- 当前负责人可以把计划转交给另一名 HR。
- HR 管理员可以重新指定任意计划的负责人。
- 其他普通 HR 不能把自己直接改成负责人。
- 操作名称统一为`变更负责人`，必须二次确认、填写原因并写入流程记录。
- 负责人变化不改变创建人、审核结果、考核范围或计划内容。

## 5. 状态模型

### 5.1 精确状态

| 状态 | 业务含义 | 主要操作人 | 下一主要操作 |
| --- | --- | --- | --- |
| 草稿 | 尚未完成有效检查，或计划内容已变更 | 当前负责人 | 继续编辑 / 下一步 |
| 检查未通过 | 提交审核前的计划检查存在阻断项 | 当前负责人 | 处理问题 / 重新检查 |
| 待提交审核 | 最新计划检查已通过 | 当前负责人 | 提交审核 |
| 待审核 | 已提交，等待 HR 管理员处理 | HR 管理员 | 审核 |
| 已退回 | 审核或发起前名单变化被退回 | 当前负责人 | 查看原因 / 重新检查 |
| 待发起 | 审核通过，可以立即或预约发起 | HR 管理员 | 立即发起 / 预约发起 |
| 已预约 | 已设置未来发起时间 | HR 管理员 | 查看、修改或取消预约 |
| 发起受阻 | 发起前业务检查未通过 | 当前负责人、HR 管理员 | 处理问题 / 确认名单 / 退回重新审核 |
| 发起失败 | 系统执行异常且自动重试仍失败 | HR 管理员 | 重新发起 |
| 进行中 | 正式任务已生成并进入员工绩效子流程 | 按后续流程 | 查看总体进度 / 进入绩效待办 |
| 已作废 | 发起前决定不再执行且保留历史 | 无 | 查看 |

`已结束`是一级页签，不是精确状态；它包含正常结束的周期和`已作废`周期。

### 5.2 核心状态流转

```text
草稿
  -> 检查未通过 -> 重新检查
  -> 待提交审核 -> 待审核
                        -> 已退回 -> 重新检查 -> 待提交审核
                        -> 待发起
                              -> 已预约 -> 到点重新检查
                              -> 立即发起前重新检查
                                    -> 发起受阻
                                    -> 发起失败
                                    -> 进行中
```

补充规则：

- 待审核时，当前负责人可以撤回；撤回后检查结果失效并回到草稿，必须重新检查。
- 审核通过后修改计划内容，原审核结果失效并回到草稿。
- 发起受阻处理完成并检查通过后恢复待发起，不自动发起。
- 发起失败重新执行时不需要重新审核。
- 发起成功后不再回到发起前状态。

## 6. 列表信息架构

### 6.1 一级页签

列表一级页签统一为：

```text
筹备中 | 进行中 | 已结束
```

- 筹备中：草稿、检查未通过、待提交审核、待审核、已退回、待发起、已预约、发起受阻、发起失败。
- 进行中：已经正式发起的周期。
- 已结束：正常结束或已作废的周期。

`待发起`只作为审核通过后的精确状态，不再承担一级分组含义。

### 6.2 列表布局

采用已经确认的 B 收敛版紧凑进度卡：

1. 顶部显示周期名称、期间、当前负责人和当前精确状态。
2. 中部显示`配置计划 / 计划检查 / 计划审核 / 正式发起`四步迷你进度。
3. 底部显示一句明确的“下一步”和当前角色可执行的操作。
4. 每张卡片最多一个填充式主按钮；预约等次要操作使用描边按钮；错误操作使用红色。
5. 非负责人只看到`查看`，不显示没有权限的假操作。

主操作映射：

| 状态 | 当前负责人 | HR 管理员 | 其他 HR |
| --- | --- | --- | --- |
| 草稿 | 继续编辑 | 查看；本人负责时继续编辑 | 查看 |
| 检查未通过 | 处理问题 | 查看 | 查看 |
| 待提交审核 | 提交审核 | 查看 | 查看 |
| 待审核 | 查看审核进度 | 审核 | 查看 |
| 已退回 | 修改计划 / 重新检查 | 查看 | 查看 |
| 待发起 | 查看 | 立即发起；预约发起 | 查看 |
| 已预约 | 查看预约 | 查看、修改或取消预约 | 查看 |
| 发起受阻 | 处理问题 | 处理问题 / 确认名单 / 退回 | 查看 |
| 发起失败 | 查看失败原因 | 重新发起 | 查看 |

列表顶部提供`我的待处理`快捷筛选和数量。计划审核仍在`周期与计划 > 筹备中`完成，不新增独立“计划审核待办”页面，也不混入员工绩效待办。

## 7. 周期详情布局

采用已经确认的布局 1，顺序为：

1. 顶部：周期名称、期间、精确状态、当前负责人和主操作。
2. 四步进度条：配置计划、计划检查、计划审核、正式发起。
3. 当前任务卡：当前为什么停在这里、谁处理、下一步是什么、是否存在阻断。
4. 计划摘要：考核范围、人数、时间节点、指标与评分规则、通知方式。
5. 完整设置：默认收起，按需展开。
6. 流程记录：位于表单和计划设置下方。

发起前不展示“参与任务 0 人、目标已完成 0 人、待主管审核 0 人、已逾期 0 人”等运行阶段统计。改为展示预计参与人数、首个任务、实际或计划开放时间和通知安排。

## 8. 创建与编辑

### 8.1 创建页

- 创建页明确显示四步流程中的第一步`配置计划`。
- 底部固定为`取消 / 保存草稿 / 下一步`。
- `保存草稿`只保存，不执行检查。
- `下一步`先保存当前草稿，再执行计划检查；创建成功但检查调用失败时，应明确说明“草稿已保存，计划检查失败”，不能伪装成创建失败。
- 建议时间只作为就近提醒；真正的节点先后顺序错误继续阻止保存或检查。
- 默认设置优先，复杂设置按需展开，避免完整长表单一次铺满。

### 8.2 编辑与回显

- 草稿和已退回计划由当前负责人编辑。
- 待审核计划锁定，当前负责人必须先撤回。
- 审核通过后的计划整体锁定；需要改变任何计划字段时点击`变更计划`。
- 变更计划必须明确提示审核结果将失效并回到草稿；已经预约时同时取消预约。
- 审核通过后的变更不再按字段判断大小，从而避免用户理解隐藏的“重大/非重大修改”规则。

### 8.3 指定审核人移除

- 创建和编辑表单移除“指定审核人”字段。
- 提交审核后进入具备周期审核权限的 HR 管理员审核池。
- 当前唯一 HR 管理员可以处理，也允许审核本人创建的计划，但必须执行独立审核动作。

## 9. 计划检查

### 9.1 检查时机

- 创建或编辑后点击`下一步`；
- 已退回后重新检查；
- 立即发起前；
- 预约发起设置时和预约到点时；
- 发起受阻处理完成后。

审核状态本身不属于计划检查问题。第一次检查发生在提交审核之前，因此不能用“周期待审核”阻止检查通过。

### 9.2 必须处理

- 周期名称、类型、考核期间等必填信息完整。
- 各时间节点顺序正确。
- 季度、半年、年度计划已经生成每个月的员工自评和直属上级评分节点。
- 考核范围解析后至少有一名有效员工。
- 试用期、已离职等不参与人员已自动排除，并显示排除人数。
- 每名参与员工均存在 HRM 组织架构中维护的`直属上级`关系；不读取花名册“直属主管”或钉钉组织关系。
- 指标模板、指标、权重和评分规则完整，权重合计正确。
- 同一员工不存在相互冲突的同期绩效计划。
- 预约发起时间为未来时间。

### 9.3 提醒确认

- 员工通知关闭。
- 实际发起时间早于或晚于建议开放时间。
- 考核范围、排除人数或组织数据相比上次检查发生变化。
- 某些节点位于非工作日，但业务允许继续。

### 9.4 结果展示

- 页面分为`必须处理`和`提醒确认`。
- 问题显示具体数量、对象、自然语言原因和就近处理入口。
- 例如“3 名员工缺少直属上级”，展开显示人员，操作为`前往组织架构处理`。
- 检查通过时保存计划内容、范围规则和人员快照，状态进入待提交审核。
- 提交审核后，HR 管理员可以查看检查摘要并展开完整快照。

## 10. 计划审核

- 待审核计划内容只读。
- HR 管理员先看周期摘要、完整计划和检查快照，再执行审核。
- 审核通过意见选填；退回原因必填。
- HR 管理员不能在审核页面直接修改计划，应退回当前负责人。
- 当前负责人可以在审核完成前撤回。
- 退回或撤回后原检查快照失效，必须重新检查。
- 审核通过后状态进入待发起，不再显示“草稿 + 审核通过”。

## 11. 正式发起与预约

### 11.1 权限

只有 HR 管理员可以：

- 立即发起；
- 设置、修改和取消预约；
- 确认发起前最新人员名单；
- 重新执行发起失败的计划。

普通 HR 负责人可以处理基础数据和发起受阻问题，但不能正式生成员工任务。

### 11.2 立即发起

- 点击后先按最新数据执行发起前检查。
- 检查通过后以幂等、整批方式生成正式任务，状态进入进行中，再发送员工通知。
- 如果计划节点本来设置为未来开放，必须明确提示本次立即发起会提前开放；计划时间保留在流程记录，实际开放时间记录为当前时间。

### 11.3 预约发起

- 预约时间默认为首个任务开放时间，可以选择其他未来时间。
- 预约时间就是实际首个任务开放时间，而不是单纯的后台执行时间。
- 修改预约时间不使审核失效，但必须记录原时间、新时间、操作人和原因。
- 取消预约后回到待发起，并记录原因。
- 到达预约时间时再次按最新数据执行检查，不能直接复用旧检查结果。

## 12. 发起前人员变化

审核对象是考核范围规则，同时保存审核时的人员快照。正式发起前重新按最新 HRM 组织数据计算名单，并与审核快照比较。

### 12.1 名单未变化

继续正常发起。

### 12.2 名单发生变化

进入发起受阻，不静默增加或删除人员，展示：

- 新增人员；
- 移除人员；
- 变化原因，例如调岗、离职、试用期状态或范围组织变化。

HR 管理员有两个选择：

1. `确认最新名单`：保留原审核结果，把最新名单保存为新的发起基准，恢复待发起；不自动发起，由 HR 管理员重新选择立即或预约发起。
2. `退回重新审核`：退回原因必填，原审核结果失效，状态进入已退回；负责人处理后重新检查，检查通过进入待提交审核，再次提交审核。

预约到点发现名单变化时，本次预约结束，不在确认或修改后自动补发。

正式发起成功后冻结本周期参与人员。之后的调岗只按独立的组织调岗与绩效交接规则影响后续月份的直属上级，不自动增加或删除本周期员工。

## 13. 发起受阻、发起失败与通知异常

### 13.1 发起受阻

- 只表示发起前业务检查未通过。
- 例如缺少直属上级、考核范围失效、模板失效或人员名单变化。
- 不生成任何员工任务，不发送员工通知。
- 问题处理并重新检查通过后恢复待发起，不自动重试或自动发起。

### 13.2 发起失败

- 只表示系统执行异常并在短暂自动重试后仍未成功。
- HR 管理员可以重新发起，不需要重新审核。
- 任务生成、周期状态和必要快照必须整批成功或整批不生效，不允许出现部分员工已发起。

### 13.3 仅通知失败

- 正式任务已经完整生成时，通知失败不能把周期回滚为发起失败。
- 周期保持进行中，显示`通知发送异常`并允许 HR 管理员重新发送。
- 通知异常、重发次数和结果写入流程记录。

## 14. 计划变更、删除与作废

### 14.1 不使审核失效的操作

- 变更计划负责人；
- 设置、修改或取消预约时间；
- 修复员工直属上级、在职状态等外部基础数据；
- 重新执行发起前检查。

### 14.2 使审核失效的操作

审核通过后，周期名称、考核范围、考核期间、指标模板、评分规则、时间节点、通知方式等计划表单内容整体锁定。点击`变更计划`后：

- 明确提示原审核结果失效；
- 已预约时同时提示并取消预约；
- 确认后回到草稿；
- 修改完成后必须重新检查和提交审核；
- 全部变化写入流程记录。

### 14.3 删除与作废

- 从未提交过审核的草稿：当前负责人可以删除。
- 只要提交过审核：不再物理删除，改用`作废计划`。
- 当前负责人或 HR 管理员可以作废；其他 HR 只能查看。
- 作废必须填写原因并二次确认。
- 待审核时作废会终止当前审核；已预约时作废会取消预约。
- 作废后状态为已作废，进入已结束页签，只读保留计划和流程记录。
- 已作废不能恢复；需要重新开展时重新创建计划。
- 已正式发起的周期不能使用本入口，后续终止规则待实际运行阶段另行设计。

## 15. 流程记录

详情页计划表单下方统一使用`流程记录`，不叫“审批流”，因为记录中还包含检查、负责人、预约和发起事件。

按业务时间从上到下展示，每条包含：

- 操作结果；
- 操作人及当时角色；
- 操作时间；
- 必要的原因、前后值或问题摘要。

必须记录：

- 创建计划；
- 计划检查通过或失败及问题数量；
- 提交审核、撤回、审核通过、退回；
- 变更负责人，显示原负责人、新负责人和原因；
- 设置、修改、取消预约；
- 计划内容变更导致审核失效；
- 发起受阻、确认最新名单、退回重新审核；
- 自动重试、发起失败、人工重新发起；
- 正式发起成功、通知异常和重新发送；
- 作废计划。

普通保存草稿不进入可见时间线，避免刷屏。检查失败和名单变化默认显示摘要，可展开完整详情。员工自评、直属上级评分等发起后子流程记录不混入本时间线。

## 16. 通知规则

- 提交审核：通知所有具备周期审核权限的 HR 管理员。
- 审核通过或退回：通知当前负责人。
- 设置、修改或取消预约：通知当前负责人并记录日志。
- 发起成功：通知当前负责人和实际操作的 HR 管理员；员工通知按周期设置执行。
- 发起受阻或发起失败：通知当前负责人和全部 HR 管理员。
- 其他 HR 可查看计划，但不接收无关通知。
- 正式发起前不向员工和直属上级发送计划通知。
- 通知点击后直接进入对应周期详情和当前任务位置。

## 17. 正式发起后的边界

- 正式发起成功后，四个筹备步骤显示为已完成，不再复用为员工绩效阶段。
- 周期详情只展示总体人数、阶段进度、逾期或异常数量和进入相关模块的链接。
- 员工自评、直属上级逐指标正式评分、自动总分等继续使用现有绩效待办页面，并保留用户已经确认满意的页面样式。
- 周期详情不复制员工任务表，不建设第二套绩效待办。
- 季度、半年和年度周期中的普通员工仍然每月自评；直属上级对每个指标正式评分，系统自动计算总分。
- 调岗、指标调整、往月重评和结果确认规则分别按已确认的独立设计执行。

## 18. 周期编辑报错的根因与修复边界

### 18.1 已定位现象

旧编辑弹窗中的“指定审核人”使用通用用户选择控件。弹窗打开时同时执行：

1. 用户列表查询；
2. 已选审核人的用户详情查询，用于把 ID 还原为姓名。

周期编辑人可能只有`cycle_plan_edit`能力，而通用用户详情和数据范围仍按员工档案类权限判断，因此接口返回 `403`，页面只能显示审核人原始 UUID。权限刚调整但旧会话令牌尚未刷新时，还可能出现前端已经显示编辑入口、后端仍拒绝两个请求的会话不一致。

该问题不是周期日期或周期计划数据本身错误。

### 18.2 修复原则

1. 按本设计移除指定审核人字段，从源头删除打开编辑弹窗时的审核人详情查询。
2. 周期参与和排除选人不得继续依赖完整员工档案用户接口；提供周期专用候选查询，只返回 ID、姓名、工号、部门、岗位和必要状态等最小字段。
3. 周期专用候选查询按`cycle_plan_edit`和周期数据范围授权，不把员工档案详情权限开放给周期编辑人。
4. 权限变更后必须刷新或失效旧会话能力，保证前端菜单与后端鉴权使用同一份当前权限。
5. 不能把“重新登录”作为长期修复；重新登录只能临时排除旧令牌因素。

## 19. 数据、并发与执行安全

- 服务端状态机是唯一权威，前端不能只靠按钮隐藏表达权限或状态。
- 检查快照至少关联计划版本、范围规则、人员快照和生成时间。
- 计划内容变化必须产生新版本并使旧检查和审核失效。
- 提交审核、审核、确认名单、发起、作废等写操作校验期望状态，发现状态已被他人推进时刷新并显示最新状态。
- 正式发起使用稳定幂等键、事务或可补偿的一致性执行，避免重复任务和部分成功。
- 预约使用持久化任务，不依赖浏览器或单进程内存计时器。
- 流程记录不可由普通页面操作删除或覆盖。
- 周期候选人员查询执行最小字段和最小权限原则。

建议按职责分离接口：

- 草稿保存与计划更新；
- 计划检查；
- 提交、撤回、审核通过和退回；
- 负责人变更；
- 立即发起、预约、修改和取消预约；
- 确认最新名单或退回重新审核；
- 重新发起、重发通知；
- 作废计划；
- 周期专用候选人员查询。

具体路由命名和数据库迁移在后续实施计划中确定，但不能把不同权限和状态动作压进一个通用更新接口。

## 20. 测试与验收

### 20.1 普通 HR 方园

- 可以创建、保存草稿、点击下一步执行检查。
- 编辑现有草稿时没有用户查询 `403`，不显示审核人 UUID。
- 可以通过周期专用候选查询选择参与和排除人员，但不能读取完整员工档案敏感字段。
- 检查失败时看到具体人员、原因和处理入口。
- 检查通过后可以提交审核，并在待审核期间查看进度或撤回。
- 被退回后必须重新检查才能再次提交。
- 可以处理发起受阻，但不能立即或预约发起。

### 20.2 HR 管理员姚瑶

- 在筹备中列表和我的待处理中看到待审核计划。
- 可以审核本人或他人创建的计划；本人创建时仍需单独点击审核。
- 审核通过后状态为待发起，能立即或预约发起。
- 能修改或取消预约并看到完整日志。
- 名单变化时可以确认最新名单，或退回重新审核。
- 业务检查失败显示发起受阻；系统执行失败显示发起失败。
- 重新发起不会重复生成任务。
- 仅通知失败时周期仍为进行中，并可重发通知。

### 20.3 所有 HR

- 可以查看全部周期和流程记录。
- 非当前负责人不能编辑计划或直接把自己改成负责人。
- 当前负责人可转交，HR 管理员可重新指定；变更记录完整。
- 我的待处理只展示当前账号真正需要处理的计划。

### 20.4 状态与页面

- 一级页签为筹备中、进行中、已结束。
- 每张卡片显示精确状态、四步进度、下一步和一个主按钮。
- 待发起不再同时作为大类页签。
- 计划详情顺序为当前任务、计划摘要与设置、流程记录。
- 发起前不显示运行阶段的四个零值统计卡。
- 正式发起后不复制现有员工绩效待办表格。
- 桌面和窄屏下当前状态、下一步和主操作始终可见。

### 20.5 人员变化与执行

- 审核后组织数据不变时可直接发起。
- 人员新增或移除时不静默发起，正确进入发起受阻并显示差异。
- 确认最新名单后回到待发起，不自动补发。
- 退回重新审核后原审核失效，重新检查通过后进入待提交审核。
- 预约到点发生人员变化时该次预约结束。
- 任务生成失败不会留下部分员工任务。
- 成功发起后参与名单冻结，后续调岗只影响已确认的月份和直属上级交接。
