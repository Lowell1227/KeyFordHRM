# 员工档案导出与合同展示调整

## 目标和范围

解决员工反馈的导出字段不可选、缺少司龄、转签公司输入不统一、历史合同混入当前合同及审核前后显示序号变化。沿用员工档案、合同主体目录和现有审核机制，不重建模块。

用户已采纳五项建议，并明确导出 Excel 应允许自选字段。本文记录采用的设计；截至 2026-11-12，本地实现和专项验证完成，尚未提交或上线。具体验证及限制见 [验收记录](../../acceptance/2026-11-12-employee-archive-quality.md)。

## 采用的方式

采用现有流程上的小范围补齐：增加导出字段选择，按正式任职动态计算司龄，复用公司目录，调整合同展示和标识。用户已采纳此方向。

不采用重新导入或重建合同数据的方式：本次反馈主要来自界面和排序，不能据此改写真实合同日期、删除旧合同或重置审核。也不新增可人工维护的司龄字段，避免与任职记录不一致。

## 导出 Excel

- 点击“导出花名册”先打开字段选择面板，不直接下载。
- 首批可选字段为现有九项：工号、姓名、任职状态、部门、岗位、绩效直属上级、系统权限、直属下属、钉钉登录，以及新增的本次司龄。
- 默认勾选现有九项；可全选、清空、逐项勾选。至少选一项才能导出，不新增拖拽排序或模板管理。
- 人员范围沿用当前筛选和原有权限，导出所有匹配记录，不只当前分页；保留原有数量上限。
- 后端校验可导出字段白名单，审计记录所选字段、筛选条件及人数。身份证、银行卡等敏感档案字段不在本次新增范围内。

## 本次司龄

- 展示名称为“本次司龄”，基于正式生效的本次任职入职日期计算；再入职重新起算，不累计历史任职。
- 在职计算截至北京时间当天；已离职计算截至最后工作日。档案和导出使用同一计算口径。
- 未到岗不提前累计，缺失或矛盾日期显示待完善，不猜填。调岗或资料变更不应重置同一任职经历的起算日。
- 具体展示采用年、月，不足一个月显示“不满1个月”；说明收进小问号，不增加常驻大段说明。

## 公司选择

- 保留签约公司和所属公司共用的合同主体下拉。
- 转签“原公司、新公司”也使用同一主体目录，支持搜索；历史名称仍可展示，不因目录变化自动改写。
- 组织归属和合同签约主体仍是不同概念，不把部门树或组织代码直接当作合同主体。
- 新增员工、档案编辑涉及的合同表单一起核对，保持一致。

## 合同展示与标识

- 顶部改为“最新合同”，默认展示一份；其余合同进入“历史合同”折叠区，显示数量，默认收起。
- 建议以签订日期选最新；缺签订日期时参考生效日期；同日以创建时间和稳定 ID 决定顺序。无日期记录明确标注日期待完善，不猜填日期。
- 最新记录不等于当前期限有效，继续显示尚未生效、已到期、期限内等实际日期状态。
- 不再用“合同8、合同5”这样的数组位置作合同标识。统一显示合同名称和日期；未填写名称时显示合同类型，日期缺失时明确提示。
- 编辑、审核详情、正式档案与变更历史共用相同标题规则。合同 ID 和原始业务数据保持不变。
- 折叠仅影响展示，不修改 `isActive`，不把未展开合同从提交内容中删掉。合同审核仍处理完整正式合同集合。
- 日期断档或重叠不能由显示序号判断；本次不自动补日期或修改前后合同来制造连续。

## 验收边界

- 使用虚构数据验证字段选择、非法字段拒绝、导出范围和司龄边界。
- 验证新增合同审核前后标题稳定，已有合同与日期不丢失；历史折叠不影响编辑、保存和审核。
- 验证 PC 和手机端选择面板、长公司名称、合同折叠及滚动。
- 保留其他任务的未提交改动，不写真实人事数据。本次批准开发不等于批准生产发布，上线仍需用户明确授权。
