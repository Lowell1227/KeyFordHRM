# 查询列表与移动端布局统一设计

## 目标

统一 HRM 查询列表的信息层级与分页位置，清理没有业务价值的“XX 筛选”“展开筛选”“收起筛选”等视觉标签，并为手机端提供独立的信息重排，避免继续把 PC 表格压缩到窄屏。

本次只调整前端展示和前端分页状态，不修改业务权限、数据范围、绩效流程、保存数据或正式员工信息。

## 设计原则

1. 查询条件直接呈现，不再用额外标题解释其用途，也不提供展开或收起入口。
2. PC 查询结果继续使用完整表格；手机端查询结果使用业务卡片，不显示压缩版表格。
3. 所有独立查询结果的总数、每页条数和翻页操作统一放在结果区域底部。
4. 页面只在当前决策所需层级展示信息；详情、历史和说明按需进入抽屉或详情页。
5. 分析图表和统计摘要不是查询结果表，不因本次统一规则强制分页。
6. 手机端查询列表不得产生页面级横向滚动；复杂编辑表格可以在自己的局部容器中滚动。

## 页面范围

### 查询筛选区清理

下列页面移除可见的筛选标题和展开/收起控制，查询字段与查询操作保留：

- 周期与计划
- 指标库
- 考核模板
- 员工档案
- 申诉管理
- 绩效面谈
- 改进计划
- 转正申请管理
- 转正审批台
- 试用期考核管理、试用期评分和我的试用期考核

筛选容器继续保留浅色背景、边界和响应式间距，用于区分查询条件与结果，但不再占用一行显示“筛选条件”。

### 独立查询结果与分页

以下页面或工作区属于独立业务结果列表，需要统一的底部分页和移动卡片：

- 周期与计划
- 指标库
- 考核模板
- 员工档案与组织成员
- 岗位目录
- 人事变更审核的员工、部门、岗位三个队列
- 绩效工作台的团队任务列表
- 部门复核
- 绩效校准名单
- 结果审批
- 结果公示
- 申诉管理
- 绩效面谈
- 改进计划
- 试用期考核三个入口
- 转正申请管理、转正审批台和我的转正申请
- 绩效报表的人员明细和人员关注名单

已经具备服务端分页的页面继续使用服务端分页。接口一次返回完整工作台数据的页面使用前端分页，不为本次展示整理新增 API 或改变返回契约。切换筛选、周期、排序或页面大小时回到第一页；分页后仍沿用原有权限和操作判断。

分页在有结果时始终显示，即使只有一页也展示总数，避免把“共 X 条记录”放回页面标题、筛选区或表格上方。

### 不强制分页的表格

以下内容不是独立查询结果，不增加分页：

- 详情抽屉中的月度结果、指标依据和操作历史
- 单个员工或单个任务详情中的说明表格
- 模板维度与指标编辑表格
- 周期配置、参与范围和启动检查中的编辑或确认表格
- 工作台的有限条数摘要
- 图表旁的部门统计、流程节点统计等有限维度汇总

这些表格仍需在手机端控制局部宽度；能转为键值信息的优先纵向排列，确实需要比较多列时只允许表格容器自身横向滚动。

## 共享组件

### 查询条件容器

新增 `QueryFilterPanel.vue`，使用无标题、不可折叠的查询条件容器替代现有 `CollapsibleFilterPanel`：

- 仅提供默认插槽和统一外观。
- 使用不可见的 `aria-label="查询条件"` 保留辅助技术语义。
- PC 端字段横向换行；手机端字段、选择器和输入框占满一行。
- 查询和重置操作在手机端单独成行，按钮等宽，避免挤在字段右侧。

### 底部分页

新增 `ListPagination.vue` 统一分页。组件接收 `currentPage`、`pageSize`、`total` 和 `pageSizes`，对外发送页码、每页条数更新及 `change` 事件：

- PC：`总数 + 每页条数 + 上一页 + 页码 + 下一页`。
- 手机：`总数 + 上一页 + 当前页 + 下一页`，使用固定的页面大小，不显示跳页输入框。
- 分页容器始终位于结果表格或卡片列表之后。
- 空结果不显示分页，只显示明确的空状态。

### 移动结果卡片

新增 `MobileResultCard.vue` 作为纯展示骨架，提供标题、状态、正文和操作插槽；选择框和业务操作仍由页面传入，组件不判断权限。字段内容由各业务页面决定：

- 顶部：主对象名称和最重要状态。
- 中部：3 至 5 个当前决策必需字段，使用“字段名—值”纵向排列。
- 次要信息：仅在确有需要时使用折叠详情，默认不重复标题或说明。
- 底部：查看详情和当前可执行操作。
- 多选页面在卡片左上角保留选择框；选中后在列表底部上方显示批量操作栏。

页面使用统一的 `desktop-result-table` 和 `mobile-result-list` 容器类切换呈现。PC 表格与移动卡片读取同一份当前页数据和同一套权限判断，避免出现两套业务逻辑。

## 绩效校准布局

绩效校准保留等级分布图和超限提醒，页面顺序调整为：

1. **周期与进度**：标题、周期选择器、周期状态、校准截止、参与人数和五个流程数量放在同一张紧凑卡片中。
2. **等级分布**：图表和 A/B/C/D 数量、占比、上限放在一张分析卡中；超限信息作为同一卡片内的“分布提醒”，不再单独占用一张高度不匹配的右侧卡片。
3. **校准名单**：部门、状态、排序和批量操作组成一条工具区；PC 表格、手机卡片共用当前页数据；分页固定在结果底部。

手机端按上述顺序纵向排列：周期摘要、进度、图表、等级数据、分布提醒、筛选、名单、分页。图表宽度跟随容器，等级数据使用两列网格；告警文字允许换行，不与图表左右挤压。

“仅作校准参考，不阻止操作”的业务含义保留，但以简短辅助说明呈现，不继续放在长标题中。存在超限时只保留一个明确的视觉提醒，避免“存在超限”、告警标题和错误消息重复表达同一件事。

## 部门复核与结果页面

- 部门复核移除标题右侧“待复核 X 项”和筛选区右侧“共 X 条记录”；总数统一由底部分页展示。
- 结果审批和绩效校准补齐分页；结果公示沿用现有服务端分页并统一样式。
- 当前环节、最近办理和操作权限继续使用现有业务口径，不因卡片化减少历史可见性或扩大操作范围。

## 响应式行为

断点统一为 `768px`：

- 大于 768px 显示表格，隐藏移动卡片。
- 小于等于 768px 隐藏查询结果表格，显示移动卡片。
- 页面标题、查询区、批量操作和分页均可自然换行，不使用缩放变形。
- 固定操作列只属于 PC 表格；手机卡片操作区不固定在屏幕右侧。
- 抽屉和弹窗继续使用现有移动宽度规则，并验证不会遮挡分页或底部操作。

验收视口至少覆盖 1440px 和 390px；移动端同时检查长姓名、长部门、长状态、无结果、一页结果、多页结果和批量选择。

## 数据与权限边界

- 不新增、删除或改写员工、组织、绩效结果或审批记录。
- 不改变 API 的授权、筛选口径和数据范围。
- 不新增角色能力，不根据岗位名称推断权限。
- 不改变排序、校准、审批、公示或申诉业务逻辑。
- 本次默认不包含生产发布；代码验证完成后需用户明确授权“上线”或“发布”。

## 测试与验收

实施采用测试先行，至少覆盖：

1. 查询页不再出现“筛选条件”“周期筛选”“指标筛选”“展开筛选”“收起筛选”。
2. 独立结果列表的分页位于结果区域底部，一页结果也显示总数。
3. 1440px 显示完整表格，390px 显示移动卡片，二者使用同一页数据。
4. 390px 页面无页面级横向溢出，查询字段和操作按钮不重叠。
5. 切换筛选、周期、排序和页面大小后返回第一页。
6. 部门复核不再在顶部重复显示待复核数和记录总数。
7. 绩效校准保留等级图表、占比上限和分布提醒，顺序为周期摘要、分析、名单、分页。
8. 有权限和无权限角色在 PC 与手机端看到相同的数据范围及可执行动作。

验证命令包括相关 Playwright 用例、`npm run type-check` 和 Web 生产构建。构建通过、代码推送、生产发布和真实角色验收分别记录，不互相替代。
