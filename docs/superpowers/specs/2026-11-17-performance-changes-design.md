# 目标变更与改进计划 V3

## 已确认范围

- 简历 AI 解析暂停；本轮不发布生产、不修改真实业务记录。
- 目标变更：HR 按周期、员工开放一次变更资格；员工及该考核任务冻结的绩效直属上级可发起，不以分享链接授权。
- 同一任务只允许一个进行中的变更。原目标在审批期间继续生效，退回可重提，HR 可撤销，生效后消耗资格。
- 用户补充确认本期同时支持新增、删除整条目标。删除仅退出当前目标，不删除历史指标、月份快照、评分或进展记录。
- 变更复用该周期原目标审批链和冻结人员。同人跳过规则沿用现有实现；完成月份不改写，仅更新未提交自评或评分的月份。
- 新建改进计划：直属上级发起 → 员工确认 → 部门负责人确认 → HR确认 → 分管领导确认目标 → 员工自评 → 直属上级评价 → 部门负责人评价 → 分管领导确认结果。
- HR确认是共享待办，由 HR管理员或同时具备 cycle_plan_edit、performance_publish 的绩效专员办理，一人确认即可。system_admin、canViewAll 不自动获得 HR 审核资格。
- 同一直属上级兼任部门负责人时不重复确认/评分，保留自动跳过记录。目标退回发起人修改，结果退回直属上级重评。
- 已有 V2 计划保持旧流程，不静默迁移。离职、归档或审批人员缺失应明确提示，不自动处置真实计划。

## 数据与交互

- 所有写操作校验读取版本，事务内竞争只允许一人成功。
- 详情加载与写操作绑定记录 ID 和页面会话，切换记录后旧响应不可覆盖或触发另一记录操作。
- 无权限、无符合条件员工、加载失败分别展示，提供就近重试。
- 新目标使用独立申请及版本，不删除旧指标或历史月度结果。最终生效事务再次核对月份状态。
- PC 与手机连接隔离真实后端验收；禁止外部消息、日程邀请。

## 验证与发布边界

严格档：定向回归开发迭代；最终一次全量 API、API/Web 构建与类型检查、隔离真实角色流程、PC/手机实际页面。固定预览 http://localhost:5173 。预览完成后等待用户单独授权发布。
