# 招聘办理体验整改

用户已明确采纳招聘实用性评审，并要求修复其中问题、保持钉钉面试日程及外部消息关闭、清理已确认的招聘测试数据。评审依据见 `docs/acceptance/2026-11-23-recruitment-usability-review.md`。

- 复用本次应聘、面试邀约、本人反馈、独立录用确认、原入职与确认到岗的既有状态和权限；不新增审批、不要求全员反馈才能录用、不猜历史面试归属。
- `/talent-interviews` 改为HR“应聘办理/面试安排”工作页，HR默认我负责，可按既有全库读取权限选择全部；普通面试官仍仅看本人邀约。查询在服务端授权过滤后分页，支持岗位阶段/关键词和面试日期、状态/待本人反馈。
- 应聘详情优先当前办理、当前应聘面试和下一步；资料、历史与跟进按需展开。新面试必须显式关联本次应聘，旧未关联邀约可查看维护，不自动绑定。
- 统一未保存保护：新建/切换/关闭/Esc/路由离开确认放弃，保存中阻止切换；409后可刷新版本并保留输入，不静默覆盖。反馈/录用意见同步保护。
- 应聘阶段和面试安排分别表达，主动作突出；淘汰/撤回/储备/提交录用前展示未结束面试/未提交反馈及后果，HR可返回处理或明确继续，不自动取消。未来面试提前完成提示，非面试实际完成不得仅按时间自动更改状态。
- 面试邀请提供可编辑模板（姓名、岗位、北京时间），适配现场/电话/线上；明确候选人仍需人工联系，备注对内部参与人可见。钉钉未配置只显示一次说明，不给无效重试；真实失败与不确定结果保留原恢复保护。
- 数据清理与代码发布分开：先盘点、确认具体测试候选人，备份、只处理确认的招聘记录及其所属子记录，正式员工/合同/绩效和关联员工入职历史不自动删除；不物理删除共享附件对象。所有范围与结果审计可追溯。
- 本轮未新增上线授权：修复后给固定真实隔离预览。生产招聘数据清理仅在身份清单确认后执行；不能将其他人后来新增的记录混进批次。
