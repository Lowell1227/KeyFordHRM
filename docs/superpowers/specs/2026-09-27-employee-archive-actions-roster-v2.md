# 员工归档操作与花名册 V2 设计

## 目标

- 归档动作只在业务状态允许时出现，不在无效标签中展示禁用操作。
- 将“批量操作”收敛为直接的“导入花名册”入口，并提供清晰的模板下载动作。
- 下载的花名册模板按员工主档、当前任职、合同记录和填写说明组织，同时继续兼容现有 81 列模板导入。

## 归档规则

- “已离职”标签显示选择列和“归档”按钮；仅没有未完成办理记录的离职员工可选择。
- “已归档”标签显示选择列和“取消归档”按钮。
- “全部”“在职”“试用期”“待入职”“办理中”“草稿”不显示员工归档选择列和批量归档按钮。
- 行级“归档”只对当前可归档的已离职员工显示；存在未完成办理记录时显示“完成办理后可归档”。
- 后端现有“仅已离职且无待审核变更可归档”的校验继续保留。

## 花名册 V2

下载模板包含四个工作表：

1. `员工主档`：一行一名员工，包含姓名、工号及当前员工档案支持的个人信息。
2. `任职记录`：每个工号一条当前任职，包含公司、部门路径、岗位、职级、职系、花名册直属主管、入职与转正信息、工作地点、用工类型和员工状态。
3. `合同记录`：每个工号可有多条合同，包含顺序、合同类型、签约公司、签订/生效/到期日期、期限、转签公司和协议状态。
4. `填写说明`：说明模板版本、关联键、必填项、日期格式、枚举值、审核流程和旧模板兼容。

新模板只暴露当前导入服务和数据库可维护的业务字段，不暴露数据库 ID、系统权限、钉钉身份、密码、审计字段或绩效周期快照。上传仍执行预检、确认和人事审核，不直接覆盖正式档案。

## 兼容规则

- 解析器根据工作表名称识别 V2；没有 V2 工作表时继续按原 81 列首个工作表解析。
- V2 以工号关联三个业务工作表；没有员工主档的孤立任职或合同记录不生成员工行。
- 当前导入流程只维护当前任职。历史任职继续通过人事变更审核形成，避免批量导入绕过生效与审计流程。
- 合同记录保持一对多并按序号排序；签约公司和生效日期为空时分别回退到当前任职公司和签订日期。

## 验收

- API 单元测试证明 V2 模板结构、V2 多合同解析和旧 81 列解析兼容。
- Playwright 证明归档入口仅在“已离职/已归档”出现，其他标签不显示；“批量操作”消失，“导入花名册”和“下载花名册模板”可见。
- API 构建、Web 类型检查、Web 生产构建和针对性 Playwright 通过。
- 本设计不包含生产发布。
