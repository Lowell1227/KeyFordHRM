# 人才库、面试邀约与入离职闭环设计

日期：2026-11-12

状态：2026-11-12 用户已确认本文件对应的完整方案并授权开发；不代表代码已实现、已提交、已上线或业务已验收。生产发布仍需单独授权。

## 1. 已确认的用户要求

1. 员工档案维护保留一个主要按钮，名称为“提交”，编辑过程自动暂存草稿。
2. 用户提出取消宽松审核开关、简化审核概念。本方案采用固定审核规则，不把“保存草稿”当作业务生效。
3. 入职、离职和待我审核必须保留；原“人事办理”入口重新组织，评估独立“入离职”菜单，不删除已有申请与历史。
4. 人才库与入离职共同形成业务闭环，复用现有员工档案、身份匹配、工号和任职历史。
5. 入职增加 HR“确认到岗”，未报到人员不能仅因入职日期到达而自动成为在职员工。
6. 离职本期只做人员离职与 HRM 权限停用，不做工作交接、资产归还或薪资结算。
7. 人才库增加简单“面试邀约记录”：候选人、时间、多选内部参与人、腾讯会议邀请内容或链接、备注。
8. 发起人自行在腾讯会议创建会议，再把邀请粘贴到 HRM。被选中的参与人应能看到同一份会议邀请；内部参与人接入钉钉日程。候选人邀请由 HR 复制后自行发送。
9. 不做个人会议房间管理、固定房间配置、腾讯会议账号绑定、主持人权限管理、自动创建腾讯会议、录制或纪要采集。
10. 候选人存在未结束面试或入职申请时，不硬性禁止删除；展示关联影响并弹窗二次确认，仍允许有删除权限的操作人强制删除。

本文件只增补已讨论范围，不批准上线，不批准修改真实员工数据，不扩大人才库列表权限。

## 3. 方案选择

| 方案 | 取舍 | 结论 |
| --- | --- | --- |
| 只改菜单名称，人才与入职仍人工核对 | 改动少，但重复申请和状态不一致仍存在 | 不采用 |
| 复用现有人事申请，补齐人才关联、到岗确认和简单面试邀约 | 能贯通流程，保持现有权限和历史模型 | 本文件推荐的整体方案 |
| 自动创建腾讯会议，管理账号或固定个人房间 | 增加授权、外部权限和会议管理复杂度 | 用户明确不采用 |
| 人工创建腾讯会议，HRM 记录邀请并同步内部日程 | 少一步自动化，符合个人账号场景与用户明确选择 | 面试邀约采用此方案 |

## 4. 信息架构建议

保持现有一级“人员”模块，建议二级入口为：

| 入口 | 负责的内容 |
| --- | --- |
| 人才库 | 候选人资料、跟进、定向分享、面试邀约、发起入职 |
| 入离职 | 入职、再入职、离职申请；草稿、审核中、待到岗/待生效、已完成、已取消 |
| 员工档案 | 已建档人员资料、档案变更、任职变动、合同和历史 |
| 组织架构 | 部门、组织负责人等组织资料 |
| 基础资料 | 岗位、合同主体等已有基础资料 |

- 工作台集中显示“待我审核”和本人受邀面试。仅显示有权限的入口。
- 申请详情仍能从原业务页面打开；审核和详情引用同一申请，不创建第二套审批。
- “入离职”中的到岗操作单列“待确认到岗”，不能藏在普通档案编辑中。
- 调动等非入离职申请保留在员工档案的变更记录中；组织、岗位审核仍能进入工作台待审，不能在移除旧菜单时丢失。
- 原 `/personnel-processing`、历史通知及外部深链保留兼容跳转，按真实申请类型落到对应列表/详情，不只重定向到一个空首页。
- 不新增一级招聘或独立会议管理菜单。人才详情按需展开面试记录，使用现有紧凑列表、抽屉和筛选模式。

## 5. 面试邀约最小闭环

### 5.1 记录内容与操作

| 字段 | 设计 |
| --- | --- |
| 候选人 | 关联人才 ID，不创建员工账号；从人才详情发起时自动带入 |
| 面试时间 | 开始与结束时间，按北京时间输入；跨设备显示时区明确 |
| 参与人 | 多选有效内部员工；显示姓名和部门消歧，不按岗位或旧“主管”系统角色推断资格 |
| 腾讯会议邀请 | 粘贴官方生成的邀请内容，提取会议链接/会议号供确认；无法提取时允许人工补充有效链接 |
| 备注 | 本次共同可见的安排说明，不自动带出人才库内部跟进、期望薪资或完整联系方式 |
| 状态 | 已安排、已完成、已取消；修改时间保留改期历史，不把时间已过自动视为完成 |
| 同步结果 | 待同步、已同步、部分失败、同步失败，与面试业务状态分开 |

操作：创建、查看、编辑/改期、调整参与人、取消、标记完成、复制邀请、加入面试。先不增加候选人自助确认、评分表或多轮审批；同一人才可以有多条独立面试记录。

“提交”保存这一次邀约；创建/修改使用请求幂等和记录版本，避免双击重复创建及覆盖他人改动。会议链接按真实 URL 解析和官方域名允许列表校验，只允许 HTTPS；拒绝脚本协议、伪装域名、任意 HTML 执行。服务端不抓取用户粘贴的任意地址。链接及可能包含的入会口令不进入普通日志/审计明文。

### 5.2 通知与钉钉日程

1. 以 HRM 面试记录为权威来源，事务内保存记录、参与人及待同步意图；外部调用放在事务提交后。
2. 内部参与人在 HRM 通知/工作台看到同一条受控面试详情和腾讯会议邀请，不要求拥有整个人才库列表权限。
3. 钉钉日程包含面试时间、必要的候选人名称、受控详情入口和会议链接；不带完整简历、期望薪资及内部跟进内容。
4. 钉钉组织者、日历所有者及参与人标识必须来自实际授权和有效身份绑定。不能因为应用已有登录/通讯录权限就假定可写任意员工日历。
5. 每条记录保存实际外部日程 ID、组织者/日历标识、最近同步版本和错误摘要。改期、增加/移除参与人、取消更新同一条日程，不每次创建新日程。
6. 未绑定钉钉或接口权限不足时，HRM 保存不丢失，并明确列出未同步人员/原因。通知状态“已发送”不等于已阅读；日程同步成功不等于候选人已收到邀请。
7. 同步任务必须可恢复、可按版本去重；响应超时先核对远端结果再重试，避免重复日程。延迟的旧任务不得覆盖新时间或复活已取消日程。若远端能力无法保证，禁止盲重试并提示人工核查。
8. 本期从 HRM 修改面试安排，钉钉侧手工改动不反向覆盖人才或人事数据；需用实际接口验证漂移后的重新同步策略。
9. 候选人邀请只生成可复制内容，由 HR 自行发送。不自动发短信/邮件，不把外部候选人加入公司通讯录；复制成功不记录为“候选人已收到”。

**腾讯会议仍由发起人在腾讯会议中维护。** HRM 改期/取消不能宣称已修改/取消腾讯会议本身。改期时需发起人核实外部会议，并在必要时粘贴新邀请；HRM 同步的是新的邀约记录和钉钉日程。

### 5.3 权限建议

- 人才库现有 HR/系统管理员及档案能力边界继续保留。创建、编辑、取消邀约复用人才维护权限，不给普通面试官人才库管理权。
- 被明确选中的内部参与人只能查看该面试记录的时间、安排说明、参与人和会议邀请；不能顺便查询完整人才详情、薪资、联系方式或原件。
- 简历访问继续走独立定向分享授权；被选为面试官不自动获得原件下载权。
- 移除参与人后，立即失去 HRM 记录访问权并同步移除日程邀请；已经发送或复制到外部的会议链接无法由 HRM 收回。不能把撤销 HRM 权限描述成撤销腾讯入会资格。
- 日程失败重试只向当前授权的参与人发送，不向已移除人员补发。接口、通知跳转和附件下载均做服务端权限验证。
- 会议发起人的个人腾讯账号无需绑定 HRM，不收集密码或 Token，不接入腾讯 MCP/REST。

## 6. 人才转入职与到岗确认

### 6.1 主流程

`人才 / HR直接录入 / 既有离职人员 -> 入职申请 -> 提交审核 -> 审核通过待报到 -> HR确认到岗 -> 入职生效 -> 员工档案`

- 人才转入职只传候选人 ID，经后端授权读取预填信息，不把完整手机号放进网址。
- 持久关联候选人 ID、申请 ID 和员工身份 ID。复用已有来源标识/幂等机制；同一人才同一时刻只允许一个未结束入职申请，重复点击打开原申请。
- 先做已有员工/离职身份匹配；再入职复用原身份及历史，通过既有机制分配新任职工号，不新建重复人员。
- 审核通过可以预建待入职记录和预留工号，但必须保持不可登录、不可作为在职范围参与业务；不能把预建记录等同于到岗生效。
- “确认到岗”必须是服务端显式命令，保存实际到岗日、操作人、操作时间和来源申请。页面不能仅把状态改成在职。
- 实现建议：由现有档案审核权限持有人执行到岗确认，不根据岗位名称授权，不新增全员 HR 能力。最终权限矩阵随本文件评审。
- 确认命令校验申请已审核通过、未取消、尚未生效、身份及任职引用有效；在同一事务内处理到岗标记、有效任职投影、工号、候选人已入职关联及审计。
- 所有现有自动生效入口，包括定时任务、登录检查和读取档案触发的投影刷新，都必须增加到岗条件；不能只改页面按钮。
- 候选人“已入职”以关联入职生效为准；禁止仅凭任选一个存在的账号提前标记。候选人不会因此拥有独立系统权限。

### 6.2 例外与历史兼容

- 未报到：保持待报到，可延期或取消；不因日期过期自动完成、自动淘汰或占用正式在职范围。
- 到岗确认与取消并发时只有一个成功；重复确认返回原结果，不重复生成人员、工号和任职记录。
- 实际到岗日期早于/晚于已审核日期属于业务变更。本期建议先修订申请并沿原规则审核，再确认，不静默改写已审核任职日期；不允许确认未来实际到岗日。
- 本规则同时覆盖新入职与再入职；历史补录不冒充本人实际到岗确认，继续保留原历史业务语义。
- 已经在职或已完成的历史入职不回退，不伪造到岗操作人或确认时间。
- 发布时已有未生效入职申请的处理需要发布前出具只读清单并由用户确认，不能批量改真实申请状态；迁移必须能区分新规则请求和历史已生效记录。
- 离职后的人才关联保留原入职事实，不自动把人才状态退回新入库；后续再入职形成新的申请历史。

### 6.3 候选人删除与二次确认

用户已确认：存在未结束的面试或入职申请时，提醒风险但仍允许强制删除，不要求先结束所有流程。

实施设计如下，其中关联流程保留属于本方案的实现建议，不扩展为用户已授权批量取消其他业务：

- 沿用现有候选人删除权限。强制删除只越过关联流程提示，不越过服务端权限、数据范围或并发校验。
- 点击删除时由后端查询未结束的面试和入职申请，弹窗显示实际数量、当前状态及删除影响。按钮为“取消”和“仍然删除”；点击取消不写入任何删除状态。
- 弹窗明确告知：删除后候选人不再出现在人才库；关联面试、钉钉日程和入职申请不会自动取消，需到相应记录单独处理。不把“强制删除”描述成连带撤销所有流程。
- 沿用软删除，保留关联 ID 与审计记录，不物理级联删除已有面试、申请、任职或员工档案。记录操作者、时间、是否强制删除及关联记录摘要，不记录敏感明文。
- 已有面试和申请保留独立访问入口及必要的业务快照，提示“来源候选人已删除”，按原流程权限继续查看、处理和取消；不得因来源被软删除导致已有流程打不开，或自动恢复候选人到人才库。不能对已删除候选人新建面试或发起新的入职申请。
- 确认结果绑定当前候选人及关联记录版本；后端删除时重新校验。若弹窗打开后新增关联流程或影响范围改变，返回最新影响供再次确认，不按过期提示执行。重复删除保持幂等。

## 7. 离职边界

- 继续沿用现有离职申请、HR 审核、最后工作日次日北京时间零点生效的规则，不提前停用。
- 生效后阻止 HRM 新登录，并使已存在的会话不能继续访问受保护业务；保留档案、身份映射、任职和考核历史。
- 不因离职修改已启动考核周期的冻结关系或结果。待办移交等额外政策不在本期自行实现。
- 不删除钉钉成员，不自动代办其他系统账号停用；HRM 身份绑定的启停继续遵循现有机制。
- 保留退回、修订、撤销和审计；离职生效与手动归档仍是不同动作。
- 不纳入交接清单、资产、离职证明、薪资结算和社保结算。

## 8. 员工档案提交与固定审核规则

- 主按钮统一“提交”；自动暂存仅保存草稿，不修改正式员工数据、不触发审核或自动批准。
- 草稿显示保存中/已暂存/保存失败；无变化不生成空申请。关闭、切换员工和快速提交要防止异步保存串单或覆盖最新内容。
- 提交先完成表单校验及当前草稿版本检查，再沿后端固定规则处理：日常免审字段提交后生效，其余进入相应审核；前后端提示使用同一规则口径。
- 一次提交含两类字段时分别展示“已生效的字段”和“待审核的字段”，不能只提示“全部保存成功”。自动生效仍留脱敏审计。
- 不新增未经确认的免审字段。现有日常免审字段范围以 `bfaf0df` 至 `a6c28e9` 实现为基线，编码前提取字段清单和写点覆盖测试；系统生成/派生字段继续只读。
- 取消宽松审核的可见开关及业务自动批准分支；保留历史审核模式/自动批准审计事实，不删除历史记录。若现场仍有宽松配置，发布前需核验并说明影响，不仅隐藏开关。
- 部门合并继续人工审核，本期不修改其任职联动规则。

## 9. 技术设计与数据一致性

- 保持 NestJS + Prisma 模块化单体；沿用 Vue 3、Element Plus 和现有业务列表规范。
- 在 `talent-pool` 内增加邀约记录和参与人持久关联；同步状态与业务状态分离。具体表名由实施确定，不复用人才全库查看权限替代参与人权限。
- 入职申请增加可审计的到岗信息和候选人来源关联，优先扩展已有申请/来源模型，不再建立第二套入职流程。
- 钉钉适配只增加日程能力，不复用组织同步反向覆盖 HRM 人员。沿用现有有效身份映射、服务器凭证保护和安全配置。
- 复用 `NotificationsService` 的日志、去重和推送机制；日程待同步意图需要持久化和恢复，不能只用进程内回调。重试机制按现有调度设施实现，不为本期另建微服务或通用工作流引擎。
- 数据库改动只以可增量迁移方式实现；人才库原有未提交四表迁移先验证是否在目标库执行过，不改写任何已执行迁移。
- 脱敏审计记录创建/修改/取消/确认的操作者、目标 ID、版本和业务差异；不要记录完整手机号、个人凭证或会议邀请口令。人才现有完整手机号审计、无效附件入库等已发现问题列入发布前修补。

## 10. 钉钉接入前置条件

钉钉日程部分必须完成真实能力预检，不能把开发文档中的存在能力等同于本应用可调用：

1. 确认实际应用、授权类型、组织者和可管理日历；检查创建、读取、修改、取消日程及参与人能力所需权限和成员授权范围。
2. 检查选定验收人员的有效 HRM-钉钉身份绑定，不自动重同步/改写组织花名册。
3. 使用获授权的测试人员和明确标识的测试日程验证创建、改期、移除参与人、取消、超时恢复；未经批准不向真实业务人员发送邀约。
4. 权限未具备时可以验证 HRM 内部链路并清晰展示未同步，但不得宣称“钉钉日程已打通”或据此完成该项验收。

本期不要求腾讯会议个人账号授权或腾讯会议 API 权限。

## 11. 测试与验收门槛

| 场景 | 必须满足的结果 |
| --- | --- |
| 面试创建，多选参与人 | 一条记录，同一份邀请；非参与人直接请求被拒绝 |
| 候选人邀请 | 可复制对外内容；不泄露内部评价、不自动发送、不虚报送达 |
| 邀请文本与链接 | 支持官方有效邀请；恶意协议/伪装域名/脚本不能执行，原文本不渲染成 HTML |
| 日程同步与通知跳转 | 真正有权限的验收人员能从日程/通知打开同一条记录；无整库权限也能看受邀详情 |
| 改期、取消、变更参与人 | 更新同一日程；移除人员不能看 HRM 详情；旧同步任务不覆盖新版本 |
| 外部失败和超时 | 记录保留、失败可见、重试不重复创建；不伪装腾讯会议本身已改动 |
| 人才转入职 | 精确关联候选人/申请/员工；重复提交不重复建档，不用姓名猜员工 |
| 候选人强制删除 | 有未结束流程时展示关联影响，取消不删除，二次确认后可软删除；无权限不能强制删除，关联流程与审计保留 |
| 删除并发与关联访问 | 确认期间影响变化需重新确认，重复删除幂等；已有面试/申请仍按原权限可处理，不因完成流程复活候选人 |
| 审核通过但未到岗 | 超过入职日期仍不可登录；任何投影刷新/任务都不能绕过到岗条件 |
| 到岗确认 | 有权限 HR 可操作；无权限、未来日期、取消申请、重复/并发操作受控 |
| 再入职与历史 | 原身份历史不丢失，新任职/工号符合现有规则，旧在职记录不回退 |
| 离职 | 最后工作日不提前停用，次日停用；旧会话业务请求被拒绝，历史可追溯 |
| 单提交与草稿 | 自动暂存不生效；切换员工不串单，提交结果区分即时生效与待审 |
| 菜单与待审 | 旧深链兼容；入离职、档案/组织/岗位待审入口均不丢失 |
| PC 与手机 | 多选、长邀请、抽屉、固定操作区和滚动可用，无文字遮挡 |

验证顺序：相关单测 -> API 全量测试与构建 -> Web 类型/构建 -> 隔离真实数据库/后端链路 -> Playwright PC/手机 -> 经授权的钉钉测试 -> 用户真实角色验收。

隔离环境只使用虚构样本，默认禁止外部通知；第三方传输替身测试与真实钉钉证据分开报告。生产发布前另行核对目标提交、迁移、备份恢复、回滚镜像、快捷登录关闭和外部健康；不恢复整库覆盖后续真实数据。
