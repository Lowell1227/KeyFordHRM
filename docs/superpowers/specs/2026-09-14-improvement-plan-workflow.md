# 绩效改进计划独立流程

## 已确认业务规则

- 主管或更高层上级可为本人管理链、负责部门及其下级部门的在职员工发起；选人范围与后台授权一致。发起不依赖周期任务、成绩或结果公示；关联绩效周期选填，同员工同周期可有多份计划。
- 创建字段：员工、改进背景、目标列表（名称、描述、权重），可选的关联周期和计划预计完成日期。目标权重提交时合计 100%。没有措施、预期结果、评分标准、逐目标期限。
- 发起人提交目标即本人确认并抄送绩效专员。部门负责人确认目标；同人自动通过。员工随后确认。部门负责人或员工拒绝时必须填理由，退回发起人修改，重新经过部门负责人和员工。每轮记录操作日志。仅这份计划目标确认完成后开始执行并锁定目标。
- 员工开始执行后任何时候可自评。员工、当前直属上级、当前部门负责人分别对每个目标填写 0–100 分及评价内容，并填写总体评价。每阶段加权分按权重计算。若直属上级和部门负责人同人，部门评价自动沿用上级评价。
- 分管总由员工所在组织的有效上级审批人确定，只查看并确认或驳回，不评分。驳回退回当前直属上级重新评价，再经部门负责人评价和分管总审核。通过后员工可看最终评价和综合分；最终分取部门负责人加权分，或同人时取直属上级加权分。不回写绩效周期。
- 绩效专员及 HR 管理员查看全量计划和日志，无办理权限。相关人按组织关系查看。工作台按当前办理人显示改进计划待办，独立于周期待办；绩效专员的抄送不算待办。
- 界面沿用绩效任务模块的表单布局、字段旁错误、草稿/正式提交和操作记录时间线，PC 与手机均适配。

## 兼容与验收

- 既有 D 级自动创建数据保留只读，不删除或改写其历史字段；停止以后从结果公示自动创建。
- 新流程中的目标、评分与日志都必须有后台权限校验和并发状态校验。组织调整后待评价人按当前关系变化，不重写已确认目标及历史日志。
- 发布前备份正式数据库，保留 API/Web 回滚镜像，只重建 API/Web；验证正式迁移、健康接口、快捷登录关闭和角色范围。
