# 新增员工分步草稿向导设计

## 目标

将当前单页“新增员工”抽屉改为与员工档案字段范围一致的分步向导。HR 填写姓名后即可形成服务端草稿；每次修改静默自动保存，可随时退出并从草稿中的原步骤继续；只有最后一步提交审核并生成正式新工号。

## 已确认边界

- 姓名是创建草稿的最低条件；其余字段允许稍后补充。
- 能从部门、岗位、日期或历史档案推导的信息自动带入，避免重复填写。
- 自动保存成功只在标题旁显示“已保存”，保存失败才明确提示。
- 草稿不因信息不完整而阻断；正式提交只沿用必要基础字段校验，其他缺失项就近提醒。
- 新增员工和档案编辑覆盖相同的信息范围：任职、管理关系、个人教育、联系保障、合同附件。
- 工号仅在提交审核时由后端生成；草稿阶段不占用工号。
- 手机号、身份证号查重继续复用既有身份检索；命中离职/归档人员时转入再入职流程。
- 钉钉组织和通讯录不参与自动带入人事主数据。

## 页面结构

向导共七步，PC 使用顶部简洁步骤条，手机端显示“第 N/7 步 + 当前步骤名称”：

1. **身份核验**：姓名、手机号、身份证号、身份查重。
2. **任职信息**：公司、部门、岗位、职级、职系、工作地点、用工类型、员工状态、入职/生效日期、试用期、预计/实际转正日期。
3. **管理关系**：花名册直属主管、绩效直属上级。
4. **个人与教育**：性别、出生日期、民族、学历、职称、学校、毕业日期、专业、婚姻、子女、政治面貌、籍贯、户籍。
5. **联系与保障**：身份证地址、现住址、紧急联系人、社保、公积金、银行卡。
6. **合同与附件**：多条合同、合同图片和附件。
7. **预览提交**：按分组展示已填信息、缺失提醒和身份查重结论。

底部动作只有“上一步”“下一步”“保存并退出”；最后一步将“下一步”替换为“提交审核”。关闭抽屉时若自动保存已经成功则直接关闭；保存中先完成保存，保存失败时保留页面并提示。

## 自动带入

- 选择岗位后带入岗位名称和职系；人工填写职级仍保留。
- 首次填写入职日期时同步带入任职生效日期。
- 选择试用期月数后，在已有入职日期且未人工修改预计转正日期时计算预计转正日期。
- 草稿恢复时保留用户已填写值，不用自动值覆盖。
- 身份检索只在手机号或身份证号格式完整时触发。

## 草稿与接口

沿用 `EmployeeDataChangeRequest` 的 `manual_employee_create` 草稿，不新增数据表。`proposedValue` 统一保存：

```ts
{
  employee: Record<string, unknown>;
  profile: Record<string, unknown>;
  contracts: Record<string, unknown>[];
  performance: { managerId: string | null };
  draftMeta: { currentStep: number; completedSteps: number[] };
}
```

创建与更新草稿使用同一接口。自动保存采用防抖并携带 `saveMode: 'auto'`，显式“保存并退出”携带 `saveMode: 'manual'`。自动保存更新现有草稿，不为每次键入重复写审计日志；首次创建和显式保存保留审计。

敏感字段继续在 API 内加密、指纹化，身份证号和银行卡号不得以明文进入 `proposedValue`、日志或响应。合同材料沿用现有私有上传目录和大小、类型、数量校验。

## 提交与审核

最终提交沿用现有身份冲突检查和必要字段：姓名、部门、入职日期、任职生效日期。提交成功后草稿原地转为待审核申请，并在事务内预留新工号；审核通过后完整档案、任职、主管、绩效关系、个人资料和合同统一生效。

## 验收

- 输入姓名后产生草稿且不生成工号。
- 修改字段后出现“保存中”再变为“已保存”，无成功弹窗。
- 关闭后从“草稿”进入，恢复上次步骤和全部字段。
- 岗位、日期自动带入不覆盖人工值。
- 七步包含完整档案字段及合同附件。
- 最终提交仍进行身份查重并生成工号，审核通过后完整信息生效。
- PC 和 390px 宽度下步骤、表单、抽屉滚动和底部操作可用。
