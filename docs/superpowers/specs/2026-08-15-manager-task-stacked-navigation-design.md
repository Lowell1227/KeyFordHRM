# 主管绩效待办上下分组导航设计

## 背景

主管周强当前进入绩效待办后，页面在标题栏使用“我的任务 / 团队绩效”分段按钮切换范围，并在左侧上下文栏只渲染当前范围。这个结构把“我的”和“团队”表达成互斥筛选，用户无法像参考系统一样同时看到两类待办及其阶段。

本设计以用户提供的参考图为准，将主管绩效待办改为固定的信息架构导航：上方是“我的绩效待办”，下方是“我团队的绩效待办”。点击具体阶段切换右侧工作区，范围仍由 URL 表达，但不再作为顶部筛选按钮呈现。

## 现状与参考图对照

| 位置 | 当前实现 | 参考图与目标实现 |
| --- | --- | --- |
| 页面标题栏 | “我的任务 / 团队绩效”分段筛选 | 不显示范围筛选 |
| 左侧上下文栏 | 个人与团队面板二选一 | 两个分组同时可见、上下排列 |
| 个人阶段 | 仅切到个人范围后可见 | 固定显示目标制定、目标确认、自评、结果确认 |
| 团队阶段 | 先切团队范围，再在横向按钮中选阶段 | 固定显示指标审核、主管评分 |
| 团队筛选 | 周期、部门、员工、状态全部堆在左栏 | 周期保留在上下文顶部；部门、员工、状态移到右侧内容区 |
| 选中态 | 范围按钮和阶段按钮分离 | 单个阶段行直接表达当前工作区 |

## 方案比较

### 方案 A：只删除顶部范围按钮

在当前左栏中同时放两组阶段，但继续把周期、部门、员工和状态筛选全部留在左栏。

- 优点：改动最少。
- 缺点：左栏会过长、信息拥挤，仍然不像参考图；在小屏下更难使用。

### 方案 B：固定双分组导航，业务筛选移到内容区（采用）

左栏只承担周期上下文和阶段导航；“我的绩效待办”和“我团队的绩效待办”始终上下可见。团队的部门、员工、处理状态和搜索放在右侧列表上方。

- 优点：符合参考图的信息层级；主管无需先理解范围筛选；阶段和业务筛选职责清晰。
- 缺点：需要同步调整团队列表工具栏和响应式布局。

### 方案 C：拆成个人、团队两个独立子路由

为每个分组和阶段新增嵌套路由与独立页面。

- 优点：路由边界最明确。
- 缺点：会重复现有数据加载和工作区逻辑，改动面与回归风险过大，不符合本次聚焦修复范围。

## 信息架构

主管的绩效待办上下文栏固定为：

1. 考核周期
2. 我的绩效待办
   - 目标制定
   - 目标确认
   - 自评
   - 结果确认
3. 我团队的绩效待办
   - 指标审核
   - 主管评分

普通员工不显示团队分组，继续使用现有个人绩效待办结构和权限。

## 交互与 URL 状态

- 删除主管标题栏中的“我的任务 / 团队绩效”分段按钮。
- 上下文栏顶部只保留一个考核周期选择器：个人阶段激活时更新个人任务周期，团队阶段激活时更新 URL 中的团队周期条件。
- 点击个人阶段时，将工作区切换到 `scope=mine`，同时更新现有个人阶段状态；右侧显示个人任务列表。
- 点击“指标审核”时，将 URL 规范为 `scope=team&stage=goal-review`，保留有效的团队筛选条件并清除不再适用的任务选中状态。
- 点击“主管评分”时，将 URL 规范为 `scope=team&stage=manager-eval`，行为与现有团队阶段切换一致。
- 主管访问裸 `/tasks` 时，仍沿用现有默认入口：进入团队“指标审核”的待处理队列。
- 显式深链、通知入口、任务详情 `returnTo`、刷新和浏览器前进后退继续由 URL 驱动。
- 个人阶段暂沿用当前组件内状态，不扩展后端或 API；主管首次显式进入个人范围时默认展示“目标制定”。员工仍保留现有“全部阶段”入口。

## 阶段状态与数量

- 个人四个阶段继续复用现有 `stageState()` 计算结果，显示“待处理 / 处理中 / 已完成 / 未开始”。
- 团队两个阶段显示各自的待处理数量；当前阶段完整列表响应可直接复用，另一阶段使用轻量分页请求取得汇总数量。
- 阶段汇总请求失败时不阻塞当前列表和处理操作；对应徽标显示占位状态，当前工作区继续展示明确的加载错误与重试入口。

## 团队内容区

团队工作区顶部按参考图组织为：

1. 当前阶段标题与简要说明。
2. 横向处理状态：全部、待处理、未开始、已完成、已豁免。
3. 搜索、部门、员工和重置操作；考核周期统一保留在左侧上下文栏顶部。
4. 团队成员表格、批量操作与选中成员处理工作区。

现有保存指标修改、通过指标审核、驳回指标审核、主管评分保存与提交能力保持不变。

## 响应式行为

- 桌面端保持三列结构：绩效功能导航、上下分组上下文栏、工作区内容。
- 窄屏下上下文栏随现有 `PerformanceWorkspace` 变为顶部区域；两个分组仍按上下顺序展示，阶段行允许横向换行，但不恢复“我的 / 团队”筛选按钮。
- 团队状态和筛选控件在内容区自动换行，保证 390px 宽度无文档级横向溢出。

## 权限与数据边界

- 不修改后端接口、数据库或任务状态机。
- 团队列表、详情和写操作继续校验 `assessmentTask.managerId = 当前用户 id`。
- `employee`、`dept_head`、`vp`、`hr`、`system_admin` 的现有访问边界不因导航改造而扩大。
- 主管只能对现有 API 判定为可处理的直属员工任务执行保存、通过、驳回或评分操作。

## 验收标准

1. 周强进入绩效待办后，左栏同时看到“我的绩效待办”和“我团队的绩效待办”，且上下排列。
2. 页面不再出现“我的任务 / 团队绩效”范围筛选按钮。
3. 个人四个阶段和团队两个阶段均可直接点击，右侧工作区与 URL 范围、阶段一致。
4. 团队“指标审核”仍能看到张晨待处理任务，并可进入保存、通过、驳回操作界面。
5. “主管评分”仍能打开对应团队评分工作区。
6. 部门、员工和处理状态筛选位于团队内容区，不与“我的 / 团队”导航混淆。
7. 刷新、详情往返和浏览器前进后退后，团队阶段和筛选状态保持一致。
8. 员工页面不出现团队分组，现有个人任务能力不回归。
9. 桌面端与 390px 宽度均无文档级横向溢出，浏览器控制台无错误。

## 测试策略

- 先在 Playwright 中增加失败用例，断言主管上下文栏同时存在两个分组、范围筛选按钮不存在、点击阶段会更新 URL 和内容。
- 为团队内容区增加筛选位置与响应式断言，确保筛选不再属于左侧范围导航。
- 复跑团队绩效合同、导航入口、跨详情返回和移动端用例。
- 最后使用真实周强账号进行桌面端与窄屏浏览器验收，并截图对照参考图。
