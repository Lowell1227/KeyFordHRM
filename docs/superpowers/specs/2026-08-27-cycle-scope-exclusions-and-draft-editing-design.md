# 周期范围部门排除与草稿编辑体验设计

## 背景

创建绩效周期时，当前范围选择存在三个已确认问题：

1. “全公司”只能逐人排除，不能按组织部门排除。
2. “自定义范围”只选择部门时，摘要把“单独选择人员数”显示为员工总数，因此错误显示“0 名员工”。
3. 草稿保存后虽然可以进入查看页，但查看页没有直接编辑入口；列表操作名称也不够简洁。

## 目标

- 支持按部门组织排除，并保存、回显、编辑和用于发起计算。
- 勾选父部门时，连同全部子部门一起排除。
- 范围摘要展示部门实际覆盖的预计人数，不再把单独选择人数当作总人数。
- 草稿列表直接提供“编辑、删除”，草稿详情提供“编辑”。
- 保持现有周期、通知策略和已发布登录页行为不变。

## 已确认业务规则

- 部门排除和人员排除可以同时存在，最终按人员去重。
- 部门树勾选父部门时，前端保存父部门及其全部已勾选子部门 ID；后端按保存的部门 ID 解析人员。
- 人员排除优先于参与部门和单独选择人员。
- 旧周期没有部门排除数据时按空数组处理，不改变原有范围。
- 只有草稿周期可以编辑完整计划或删除；其他状态保留原有查看、检查和进度操作。

## 数据模型与接口

在 `AssessmentCycle` 增加字段：

```prisma
explicitExemptDeptIds String[] @default([]) @map("explicit_exempt_dept_ids") @db.Uuid
```

使用加法式 Prisma 迁移，为现有记录设置空数组默认值。同步扩展：

- `CreateCycleDto` / `UpdateCycleDto`
- `CreateCycleBody` / `AssessmentCycle`
- 周期创建、草稿更新和详情返回
- 发起计划哈希
- 发起前候选人员查询和豁免判定

后端正式发起时：

1. 按参与部门和显式参与人员形成参与候选集；“全公司”继续使用全部有效员工。
2. 按 `explicitExemptDeptIds` 解析部门内有效员工。
3. 合并 `explicitExemptUserIds`，按员工 ID 去重。
4. 命中部门或人员排除的员工标记为本周期豁免，不进入正常绩效流程。
5. 部门排除字段纳入发起计划哈希，避免范围变化后误用旧检查结果。

## 前端范围选择

`CycleParticipantScopePicker` 增加 `excludedDepartmentIds` 双向绑定和独立草稿状态。

抽屉页签：

- 全公司：`排除部门`、`排除人员`
- 自定义范围：`按部门`、`按人员`、`排除部门`、`排除人员`

部门排除复用现有有效组织树。参与部门与排除部门互斥：同一部门不能同时处于两类选择中；切换选择时从另一类中移除，避免冲突。

人数摘要使用部门节点的 `directMemberCount`：

- 对所有最终勾选的部门 ID 汇总直属人数，避免父子部门 `memberCount` 重复累计。
- 自定义范围示例：`1 个部门（预计 8 人） · 另选 0 人`。
- 全公司示例：`全公司 · 排除 2 个部门（预计 18 人） · 另排除 1 人`。
- 预计人数只表示当前组织数据下的范围提示，正式人数以“保存并检查”的发起前检查结果为准。

切换范围模式时不隐藏已有排除选择；用户可以在对应排除页签查看和清空，避免静默丢失。

## 草稿查看与操作

周期列表：

- 草稿行的操作区直接显示 `编辑`、`删除`。
- 点击周期名称或列表行仍进入周期查看页。
- 非草稿周期继续显示与状态对应的检查、预约、进度或归档操作。

周期查看页：

- 草稿状态在右上角显示主按钮 `编辑`。
- 点击后打开现有“编辑绩效周期”对话框，并完整回显参与部门、单独人员、排除部门和排除人员。
- 其他状态不显示完整计划编辑按钮。

## 测试与验收

后端测试：

- 创建、更新和读取草稿时保存 `explicitExemptDeptIds`。
- 部门排除命中员工并与显式人员排除去重。
- 父子部门 ID 同时出现时不会重复生成任务。
- 部门排除变化会改变发起计划哈希。
- 旧周期空数组行为保持不变。

前端测试：

- 全公司可以同时选择排除部门和排除人员，并提交两个字段。
- 父部门选择后包含子部门 ID。
- 仅选择部门时显示预计覆盖人数，不显示错误的“0 名员工”。
- 保存后重新编辑能回显排除部门。
- 草稿列表显示 `编辑`、`删除`。
- 草稿查看页显示 `编辑`，非草稿不显示。
- 桌面与 390px 视口操作可用。

线上验收：

1. 使用受控 HR 或系统管理员账号创建草稿。
2. 验证全公司部门排除、人员排除和摘要人数。
3. 验证自定义范围部门人数。
4. 保存后从列表查看，再从查看页进入编辑。
5. 重新打开确认所有范围选择回显一致。
6. 运行发起前检查，核对预计参与人数和豁免人员。

## 发布与回滚

- 从最新 `main` 构建 API 和 Web 候选镜像。
- 发布前备份数据库、正式 `.env` 和当前 API/Web 镜像标签。
- 先执行加法式数据库迁移，再替换 API 和 Web。
- 保持 `ENABLE_TEST_QUICK_LOGIN=true`，直到用户明确确认全部验收完成。
- 外网验证健康接口、登录、周期创建、保存回显、编辑入口和发起前检查。
- 如需回滚，恢复旧 API/Web 镜像；新增空数组字段可保留，不影响旧代码。

## 非目标

- 不自动修改真实组织关系或人员归属。
- 不把钉钉组织作为范围数据源。
- 不改变非草稿周期的完整计划编辑权限。
- 不在本次修复中正式发起或删除用户的真实周期数据。
