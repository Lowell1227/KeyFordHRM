# 目标跟进参考图完整重构设计

## 目标

将现有“选择目标后管理行动项”的目标跟进页，完整重构为参考图所示的“选择人员与考核周期后查看考核指标”页面。页面需要在布局层级、视觉密度、选中态、搜索、折叠、周期切换、自定义列和空状态等方面高相似度对齐参考图，并让普通员工也能关注本人和直属上级的目标。

本次保留 HRM 现有公共导航、路由兼容和目标数据权限，不把参考系统的全局顶部导航复制到 HRM，也不显示当前没有真实能力支撑的“创建群聊”按钮。

## 已确认决策

- 完整替换当前“选择目标 → 管理行动项”的页面主交互。
- 页面改为“选择人员 → 选择周期 → 查看考核指标”。
- 保留 HRM 当前蓝色一级导航和顶部用户栏，只重构“目标跟进”页面内部。
- 普通员工可以进入目标跟进，默认查看本人，也可以查看直属上级。
- 所有角色的人员栏均只展示“我”和“直接上级”，不借此页面扩大到下属或全公司员工。
- 暂不显示“创建群聊”，不提供无效入口。
- 页面是关注和查看场景，不提供新增、编辑、删除或更新进度入口。
- 保留 `/action-items` 路径，兼容历史收藏和既有跳转。

## 方案选择

采用页面级完整重构：保留公共应用壳和现有后端领域模型，新建目标跟进专用页面与只读数据视图。该方案能达到参考图的页面结构，又不会让目标地图、绩效待办和其他模块被动改变。

不改造共享绩效工作台为全局参考图样式，因为这会影响目标地图和绩效待办。不保留行动项模式切换，因为两个主交互并存会造成页面含义不清，也不符合完整替换要求。

## 信息架构

页面在 HRM 公共应用壳内部包含四层结构：

1. 页面标题栏：仅显示“目标跟进”，高度、边框和留白与参考图一致。
2. 绩效功能导航：纵向显示“目标跟进、目标地图、绩效待办”，目标跟进为当前项。
3. 人员选择栏：提供员工搜索、“我”和“直接上级”两个可折叠分组。
4. 主内容区：顶部显示当前人员、头像和考核周期；下方显示“考核指标”白色卡片。

主内容区不显示创建群聊、行动项筛选、负责人筛选、刷新按钮、列表/看板切换或新建行动项。

## 人员与权限

### 页面访问

“目标跟进”路由和绩效导航入口对所有已登录角色开放。目标地图和绩效待办继续使用各自现有角色范围，不因本次改动扩大权限。

### 人员范围

- “我”始终显示当前登录用户并默认选中。
- 当前用户存在 `directManagerId` 时显示“直接上级”分组；否则整个分组不渲染。
- 直属上级使用当前登录信息中的 ID 和姓名组成最小安全视图；没有头像时用姓名首字生成参考图样式头像。
- 搜索只过滤“我”和“直接上级”中的项目，不调用全员搜索，也不扩大人员可见范围。
- 选择直属上级不绕过现有目标数据权限；只返回当前查看者本来可见、且负责人为直属上级的目标。没有可见目标时显示正常空状态。

### 只读边界

页面不出现写操作。目标创建、编辑、进度更新和行动项接口继续保留在后端，供其他既有或后续业务入口使用，但不从目标跟进页暴露。

## 数据与接口

### 周期

- 使用所有登录用户均可读取的周期接口。
- 默认选择状态为进行中的最新周期；不存在进行中周期时选择开始时间或创建时间最新的周期。
- 周期切换立即重新加载当前人员的指标。

### 考核指标

目标跟进使用目标模型作为考核指标来源，按 `ownerId + cycleId` 查询当前人员在当前周期的目标。列表返回下列展示字段：

- 目标 ID、名称和排序信息；
- 当前查看者可见的最新行动项摘要及更新时间；
- 目标状态；
- 目标完成进度；
- 目标权重。

为避免前端按目标逐条请求行动项，增加目标跟进专用只读查询或在现有目标查询中一次性返回每个目标的最新可见行动项摘要。聚合查询必须复用行动项现有可见性规则，不能因展示“最新进展”而泄露不可见行动项。实现时优先选择不会改变其他目标页面返回语义的专用读取契约。

“最新进展”显示最近更新的行动项标题和进度；没有行动项时显示“暂无进展”。权重为空时显示 `--`，顶部“维度权重”按当前列表中有效权重求和。

### 状态映射

- 草稿或进度为 0：未开始；
- 有效目标且进度在 1 到 99：进行中；
- 进度为 100：已完成；
- 已归档目标：已归档。

展示层不直接暴露英文枚举。

## URL 与导航状态

人员和周期写入 URL 查询参数 `employeeId` 与 `cycleId`。刷新、浏览器前进和后退需要恢复相同选择。

历史 `objectiveId` 深链接继续兼容：页面读取目标详情后，自动定位其负责人和周期，并在指标列表中突出对应目标。解析完成后保留可分享的规范查询参数，不让历史跳转落入空页面。

人员或周期参数无效、越权或已删除时，回退到当前用户和默认周期，同时清理无效参数。

## 组件边界

### 目标跟进页面容器

负责解析路由、加载周期、协调人员与周期选择、请求指标数据，以及组合加载、错误和空状态。页面容器不直接承载复杂行样式。

### 人员选择面板

负责搜索、分组展开收起、人员选中态和键盘可访问性。折叠状态存入 `kayford.goalTracking.collapsedPeopleGroups`，读取时校验 JSON 和布尔值。

### 考核指标面板

负责人员摘要、周期选择、总权重、自定义列、指标表头和数据行。桌面端使用连续表格式行，窄屏切换为字段分组。

### 自定义列菜单

序号和指标名称固定显示；“最新进展、状态、进度、权重”允许勾选显示。选择存入 `kayford.goalTracking.visibleColumns`，读取时过滤未知键并确保固定列不可隐藏。

### 既有组件使用

保留 `PerformanceWorkspace` 作为页面标题、绩效功能导航和三栏容器。人员栏不复用带固定标题的 `PerformanceContextPanel`，以便准确还原参考图的搜索和分组结构。目标地图与绩效待办继续保持当前组件使用方式。

## 交互细节

- 首次进入时先恢复合法 URL 状态，否则选中本人和默认周期。
- 点击人员立即更新选中态、URL 和指标列表。
- 搜索无结果时在人员栏内显示紧凑提示，不影响已选人员和主内容。
- “我”和“直接上级”标题可点击折叠，图标方向、`aria-expanded` 和持久化值同步。
- 周期下拉使用参考图的内联文字形式，选择后显示轻量加载状态。
- “自定义列”打开勾选浮层；关闭后保留结果，刷新页面仍恢复。
- 指标行默认只读，不增加参考图中未体现的抽屉、编辑按钮或隐式跳转。
- 历史 `objectiveId` 定位成功后，以轻量背景强调目标行，不改变列表排序。

## 视觉规范

- 页面标题栏保持白色，使用弱分隔线和紧凑高度。
- 绩效功能导航宽度沿用现有约 148 像素；人员栏约 240 至 256 像素。
- 主内容区使用接近参考图的浅灰蓝背景，内容顶部和卡片之间保持 14 至 16 像素间距。
- 当前人员头像使用青蓝色圆角方块，姓名和周期形成两行紧凑信息区。
- 指标卡片为白色、约 12 至 16 像素圆角，无厚重阴影。
- 卡片标题、表头和数据行使用弱分隔而不是 Element Plus 默认厚表格边框。
- 序号使用浅蓝圆角数字标记；指标名称为主要文字；辅助列使用低饱和度文字。
- 当前人员使用浅蓝整行高亮；悬停只改变轻微背景色。
- 字号、行高、搜索框高度、下拉框边框和列间距按参考图的紧凑密度实现。

## 响应式设计

### 桌面端

- 保持功能导航、人员栏和主内容三列结构。
- 指标表头和数据行使用一致网格列宽，主内容占用剩余空间。
- 长目标名称与最新进展允许换行或在合理宽度下省略，不能挤压进度和权重列。

### 窄屏

- 绩效功能导航变为横向可滚动导航。
- 人员选择栏移动到主内容上方，人员项目横向排列。
- 指标行按“指标名称、最新进展、状态、进度、权重”纵向分组。
- 页面不得出现文档级横向滚动；搜索、人员切换、周期切换和自定义列均保持可操作。

## 加载、空状态与错误处理

- 周期和指标首次加载使用低干扰骨架，不让旧数据与新选择混淆。
- 没有直属上级时不显示空分组。
- 没有周期时显示“暂无可用考核周期”。
- 当前人员在所选周期没有目标时，使用参考图风格空状态并显示“暂无考核指标”。
- 人员或周期查询失败时在对应区域显示错误与“重新加载”，不把接口失败伪装成空数据。
- 深链接目标不存在或不可见时提示无法定位，并安全回退到默认状态。
- 快速切换人员或周期时忽略过期请求结果，避免较慢响应覆盖当前选择。

## 预计修改范围

- `web/src/router/routes.ts`：把目标跟进开放给普通员工并切换到新页面组件。
- `web/src/router/navigation.ts` 或相关导航配置：让员工看到目标跟进入口，同时保持目标地图权限不变。
- `web/src/views/objectives/`：增加目标跟进页面、人员面板和指标面板；移除该路由对旧行动项工作区的使用。
- `web/src/components/performance/PerformanceWorkspace.vue`：仅在确有必要时增加不影响其他页面的窄扩展点，不改变目标地图和绩效待办现状。
- `web/src/api/` 与 `web/src/types/api.types.ts`：增加目标跟进只读数据契约。
- `api/src/objectives/`：增加目标跟进只读聚合能力，并继续复用现有目标数据范围。
- `web/src/views/objectives/ObjectiveMapView.vue`：把旧“行动项”跳转调整为兼容的目标跟进深链接，避免语义失效。
- 对应 API 单元测试、路由/导航契约测试和 Playwright 页面测试。

## 保持不变

- HRM 蓝色一级导航、顶部用户栏和其他模块页面。
- 目标地图和绩效待办的页面结构与权限。
- 目标、行动项和周期的写接口及数据库结构，除非专用读取契约确需非破坏性返回扩展。
- 现有目标创建、目标编辑、目标进度更新和行动项后端能力。
- 钉钉登录、工作通知和组织同步；本次不新增群聊能力。

## 测试与视觉验收

### 自动化测试

- 普通员工能看到并进入目标跟进，但仍看不到无权限的目标地图。
- “我”和“直接上级”的显示、缺失上级场景、搜索过滤和折叠持久化正确。
- 默认周期、周期切换、人员切换和 URL 恢复正确。
- 直属上级目标读取不绕过既有数据范围，其他员工目标仍不可见。
- 最新进展、状态、进度、单项权重和总权重映射正确。
- 自定义列不能隐藏固定列，刷新后恢复合法选择，损坏存储值安全回退。
- `objectiveId` 深链接能定位负责人、周期和目标行；无效或越权 ID 安全回退。
- 周期为空、指标为空、接口失败和过期请求均显示正确状态。
- 390×844 下无文档级横向溢出，关键操作可访问。

### 验证命令

- 前端目标跟进聚焦 Playwright 测试；
- 前端导航与角色可见性契约测试；
- 后端 objectives 聚焦单元测试；
- `npm run type-check`；
- `npm run build`。

### 浏览器验收

使用普通员工和主管两个真实角色进行验收：

1. 打开目标跟进并核对参考图结构、三栏比例、颜色、留白和指标行密度；
2. 切换本人、直属上级和考核周期；
3. 搜索人员、折叠分组、配置自定义列并刷新页面；
4. 使用浏览器返回和前进验证 URL 恢复；
5. 打开历史 `objectiveId` 深链接验证定位；
6. 检查浏览器控制台无错误；
7. 保存桌面端和 390×844 窄屏截图，与参考图逐项对照。

构建或类型检查通过不能代替浏览器验收；只有真实角色的刷新、返回、权限、控制台和截图证据齐备，才能宣称本次视觉与交互改造完成。

## 风险与控制

- **页面语义改变：** 保留旧路径并兼容 `objectiveId`，同时调整目标地图中的跳转文案和参数。
- **直属上级可见性：** 人员选择只增加当前用户直属上级这一条明确关系；目标查询仍叠加现有数据范围，不开放通用员工检索、任意 `ownerId` 查询或权限绕过。
- **最新进展查询性能：** 使用单次专用查询或关联子查询，禁止前端对每个目标发起一个行动项请求。
- **共享工作台回归：** 页面特有结构放入专用组件，只给共享组件增加向后兼容的扩展点。
- **持久化脏数据：** 对本地存储做结构和白名单校验，非法值回退到默认设置。
- **参考图与系统字段差异：** 只呈现现有真实目标、行动项和周期数据，不制作假按钮、假状态或虚构字段。
