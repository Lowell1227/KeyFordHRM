# 人事基础资料统一与既有待办收尾

## 用户确认的范围

2026-11-14 用户确认：以当前正式库为核对基准，补齐现有目录，并把职级和档案常用选项纳入基础资料；此前人员一致性修缮一并收尾。交付固定隔离预览，不代表授权生产发布或批量更正真实员工资料。

## 方案与边界

- 仅清理现值不能防止重复自由录入；另造通用字典平台会形成第二套权限和数据来源。采用扩展现有 PersonnelReferenceData、管理页和选择器的方案。
- 保留合同主体、工作地点、职系、岗位。部门仍由组织架构维护，不复制部门目录。
- 新增 job_grade（职级）、education（学历）、marital_status（婚姻状况）、political_status（政治面貌）、household_type（户籍类型）、contact_relation（与联系人关系）、bank_name（开户银行）、contract_name（合同名称）。
- 前六类新增值使用启用目录选项。bank_name、contract_name 提供常用选项并保留手工填写，不把支行、合同日期/期限做成普通选项。
- 已有历史值未触碰时继续回显、可保留；停用/改名不批量重写历史，新选择只用启用项。空值仍按原字段必填规则处理，草稿不强制完整。
- 基础资料只返回选项，不披露关联员工个人信息。沿用已有档案编辑/审核和组织维护权限，不新增授权。用工类型、合同签订类型、流程状态和系统权限不开放为普通自定义选项。
- 入职、再入职、任职和档案编辑共用适用的选择器；API 正式提交校验同一来源。导入预览必须识别未维护的目录值，导出按已保存值输出，不映射改写历史。
- 不从正式库自动生成选项。正式库只读核对形成候选、别名、异常及待确认映射；不得将疑似敏感误填值写进日志、报告或选项。
- 公司内部映射、岗位职系归属必须由业务确认；不按名称猜测，不覆盖身份、账号、附件、任职/审批/绩效历史。

## 既有待办

沿用 personnel-consistency-remediation 计划和执行记录的 F01-F10、N01-N09；不回退已有未提交修缮。O01 偶发重开档案失败继续针对性复现，无法复现/归因则保留风险，不能宣称已修复。实体 Safari、真实零点调度、正式资料初始化及加密花名册副本仍是独立边界，不虚构通过。

## 验收

- 新目录创建、同名/非法类型/越权、停用/改名历史保护有直接回归。
- 严格档 API 全量、迁移与真实 HTTP/数据库集成；Web 类型检查/构建和真实预览 PC/手机操作。
- 页面从基础资料新增选项，到入职/档案选用、提交、重开及导出，数据一致。用虚构资料，不发送外部通知/日程。
- 交付分别说明实现、提交、上线、业务验收；生产发布另等授权。
