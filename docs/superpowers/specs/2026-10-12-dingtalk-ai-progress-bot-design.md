# 钉钉 AI 目标进展助手（第一期）设计

> 日期：2026-10-12
>
> 状态：会话设计已确认，待书面审阅；尚未实施或上线
>
> 范围：员工在钉钉单聊更新已有绩效目标进展，确认后写入 HRM；系统管理员动态选择 Kimi、DeepSeek 或千问

## 1. 目的与成功标准

员工不必先进入多字段表单，可以在钉钉向机器人发一句工作进展。系统结合该员工当前可更新的正式目标，提出待保存内容；员工核对并点击“保存进展”后，才产生 HRM 正式进展记录。绩效直属上级按既有权限看到最新确认记录，不会把 AI 草稿当成正式结果。

第一期成功的最低标准是：本人身份与目标匹配正确；量化目标展示员工确认的实际值、目标值和完成度；定性目标不虚构百分比；未保存、保存失败和重复点击均不会产生错误记录；系统管理员能在页面中测试和切换 AI 服务商，无需重新发布应用。

本设计沿用 HRM 员工档案及已确认花名册为人员、组织、直属关系的权威来源。钉钉只提供应用入口、消息和身份标识，不将钉钉通讯录写回 HRM。

## 2. 现状与设计取舍

- 正式绩效目标使用 `IndicatorInstance`，日常进展使用 `IndicatorProgressUpdate`。现有进展服务按员工本人、考核月份与任务状态校验并追加审计；第一期沿用这一事务和权限边界，不复用另有审核与汇总规则的 `Objective` / `ActionItem` 作为第二套正式进展。
- 现有进展接口要求 0–100 整数百分比、状态和说明，但记录实体尚无日常“实际完成值”和“保存时目标值”的结构化字段。量化完成度和定性无百分比需要向现有进展模型做兼容扩展。
- 现有钉钉代码覆盖登录和工作通知，没有应用机器人接收消息及卡片回调。复用当前 HRM 钉钉应用，采用应用机器人单聊与 Stream 模式；不使用只能群发的自定义群 Webhook 机器人，也不新增绩效微服务。
- “系统概览”目前只读。新增独立的“系统管理 → AI 服务配置”，而不是在只读概览或机器人聊天中维护服务商密钥。

## 3. 第一阶段用户流程

1. 员工与当前 HRM 钉钉应用的机器人单聊，发送一条文本进展，例如“客户拜访完成 12 家”。第一期不接收群聊作为正式进展入口。
2. 后端以钉钉发送人映射到有效 HRM 身份，仅取本人处于可更新期间的正式目标。AI 只对这条消息与最少必要的本人目标信息做候选识别，不直接写数据库。
3. 匹配唯一且信息充分时，机器人返回“待保存进展”卡片：目标名称、所属月份、进展说明、员工待确认的实际值与目标值、计算出的完成度以及可选的状态。量化数值或状态缺失时不猜填；匹配不唯一的卡片不提供直接保存按钮。
4. 员工核对无误点击“保存进展”。若目标匹配不明确或需切换匹配的目标、修改说明、数值、状态，点击“修改”，进入钉钉内的简短 HRM 确认页；选择或修改后仍须明确点击“保存进展”。确认页不编辑正式目标基线。卡片和确认页均不得以打开、关闭或超时替代保存。
5. 保存前服务端重新验证发送人、绑定、有效任职、目标归属、可更新月份、最新进展及草稿状态。成功后返回已保存状态和 HRM 详情入口。绩效直属上级按既有任务关系和可见范围看到最新确认进展。
6. 员工更正已保存的进展时，追加一条新的确认记录并保留此前记录与前后值审计，不原地覆盖历史，不重新触发目标审核。

## 4. 量化、定性与当前状态

- 仅当正式目标具有有效正数 `targetValue`，且员工确认本次实际值时，服务端根据实际值 / 保存时目标值计算完成度；AI 给出的计算数字只作为预览，不作为入库权威。记录实际值、目标值及单位快照，以免将来目标基线变化改写历史含义。
- 量化目标卡片同时展示“实际 / 目标”和完成度。超过目标时标注“超额完成”；现有 0–100 进度条最多显示 100%，实际 / 目标仍保留超额事实。不得加权合成个人总体完成率。
- 正式目标没有可用数值基线，或员工只描述定性工作时，展示员工确认的状态与说明，不显示虚构的 0% 或 AI 估算百分比。进展记录中的百分比和状态允许按业务含义为空；现有页面不得把空百分比转译成“0%”。扩展保存服务时保持旧版 Web 请求契约兼容，并为机器人确认路径提供可空字段。
- 日常进展的实际值是跟进数据，不写入 `IndicatorInstance.actualValue` 等考核评分字段；月度自评和主管评分仍按原流程办理。

## 5. 组件与数据边界

### 5.1 钉钉接入

在现有 NestJS 模块化单体中增加钉钉机器人适配层，负责 Stream 连接、单聊消息接收、互动卡片发送和点击回调。入口只接受配置的企业、机器人和单聊会话。卡片编辑页需要正常的 HRM 钉钉登录身份；卡片 ID、草稿 ID 或页面链接本身都不是授权凭据。

身份匹配优先使用已启用的钉钉外部身份绑定；必要时通过当前应用可授权的钉钉用户信息把 `senderStaffId` 解析为 unionId，再匹配绑定。每次正式保存复用有效任职准入和目标本人权限校验。若权限或外部接口不足，不用姓名、手机号、钉钉部门或组织树猜测员工身份。

### 5.2 AI 候选识别

设置一个“进展识别”业务接口，向所选服务商发送员工本次文本及本人候选目标的最少必要字段，返回统一的候选结构：目标 ID 候选、进展说明、实际值候选、状态候选及不确定标识。服务端校验结构、目标 ID、数值与长度；模型的结果只能生成草稿，不能调用正式写入接口。识别不唯一时由员工选择，不自动代选。

第一期支持 Kimi API 开放平台、DeepSeek API 和阿里云百炼千问文本模型。三个适配器共用业务结果契约，但服务商请求参数和允许访问的官方域名由各自适配器控制；管理页面不提供任意外部 URL 输入。Kimi Code 服务与 Kimi API 开放平台凭据不混用。

### 5.3 草稿与正式保存

待保存草稿放在 Redis，绑定员工、钉钉会话、候选目标、服务商配置版本和一次性草稿 ID，24 小时后失效；未确认文本不进入正式进展表。正式记录沿用 `IndicatorProgressUpdate`，增加可空的实际值、目标值/单位快照及内部来源/幂等关联。来源只用于后台审计，不在员工或上级前台显示“AI 参与”标签。

保存与审计在同一事务内完成。草稿 ID 对正式写入具有数据库级唯一约束，重复卡片回调或网络重试返回已保存结果，不产生第二条进展。保存后更新卡片状态；若钉钉卡片更新失败，以 HRM 已保存状态为准，下次点击仍能读到已保存结果。

## 6. 动态 AI 服务配置

新增“系统管理 → AI 服务配置”独立页面和后端接口，只有 `system_admin` 可进入、查看状态及执行配置、测试、启用或停用；普通 HR、员工和绩效直属上级均无配置权限。第一期仅有一个业务场景“目标进展识别”，同时只启用一个服务商；之后其他 AI 场景可复用服务商配置，但不在本期建设其业务功能。机器人总开关默认关闭，试运行期间只响应管理员明确列出的受控账号。

页面分别维护 Kimi、DeepSeek、千问的凭据是否已配置、模型标识和必要的受控地域选项。API Key 为只写输入，读取接口只返回“已配置/未配置”和安全的配置摘要，不能回显密钥或写入日志。密钥在服务端加密后单独持久化；加密主密钥从部署密钥配置读取，不与密文同库存放，也不放入源码或文档。非敏感的当前启用服务商可使用现有系统配置机制，所有配置变更写审计但不记录明文或请求正文。

管理员先使用不含真实员工信息的样例文本“测试连接”，成功后才能启用该配置。切换对新到达的消息生效；已生成待保存卡片不重新调用模型，其保存依照 HRM 当前目标和权限再校验。模型调用失败不自动切换其他服务商，以免未经选择地把员工内容传给另一家；机器人说明失败并提供手动更新目标进展的入口。未配置有效服务商或缺少加密主密钥时，机器人 AI 功能保持关闭。

## 7. 错误处理与安全

- 未绑定、绑定停用、离职或无有效任职：只给出账号不可用或需联系管理员的业务提示，不展示其他员工目标。
- 当前没有可更新目标、月份已锁定或月度自评已提交：解释当前不能保存的原因和下一步，不绕过既有工作流。
- 多目标匹配或数值单位不明：进入确认页选择或补充，不用置信度阈值替代员工确认。
- 草稿过期、卡片被转发或回调发送人不同：拒绝保存，提示重新发送；不可凭卡片链接越权。
- 服务商超时、响应不合规、密钥失效或费用/限流错误：不保存，不自动降级到另一服务商；向员工给出手动入口，向管理员展示不含敏感内容的错误类型。
- 只向所选服务商发送当前员工消息与本人必要目标字段；不发送通讯录、其他员工目标、薪酬、考核结果、附件或聊天历史。日志不记录 API Key、完整消息正文和模型原始响应。

## 8. 第一阶段不包含的能力

不包含目标起草/提交/审核 AI 检查、上级目标或工作资料检索、机器人收文件、行动步骤、每周进展卡、每日定目标提醒、主管汇总或私聊查询，也不改现有提醒开关。这些均沿此前已确认业务方向进入后续独立阶段，不能因为第一期接入机器人而提前向真实员工发送消息。

## 9. 验证与发布门槛

1. API：验证身份绑定、任职资格、本人目标、月份锁定、保存事务、重复回调、过期草稿、量化/定性、超额目标、审计脱敏，以及三家服务商适配与动态切换；数据模型和共享流程改动扩大到全量 API 测试及构建。
2. Web：验证系统管理员配置页与 HR/员工拒绝访问、PC/手机确认页、字段内错误提示、目标选择、修改/保存及保存失败保留输入；完成类型检查/生产构建和针对性 Playwright。
3. 钉钉：先在隔离数据或受控测试账号验证真实单聊、卡片回调与同账号登录，不向正式员工群发或主动发送测试通知。测试前明确参与账号、发送范围、外部模型调用和清理方式。
4. 发布前现场确认现有钉钉应用有应用机器人、Stream 与互动卡片模板权限，且密钥已在安全渠道配置。缺少任何一项则可部署代码但功能保持关闭，不宣称机器人已可用。
5. 涉及数据库迁移时先备份并隔离演练，保留可识别的 API/Web 回滚镜像；只替换必要服务。发布后分别验证外部健康、迁移、资源、配置开关和受控角色路径；技术上线与员工/上级业务验收分开记录。

## 10. 验收场景

- 员工发一条明确指向本人目标的量化进展，卡片展示正确的目标、实际 / 目标和完成度；未点击“保存进展”时 HRM 无新记录。
- 员工切换错误匹配的目标或修改数值后再保存，HRM 仅新增一条经本人确认的进展；绩效直属上级按既有权限读到最新记录，其他员工不能读取。
- 定性进展不显示 AI 编造的百分比；量化超额保留实际 / 目标事实；进展更正保留前后历史与审计。
- 重复点击、卡片转发、身份停用和月份关闭均不会越权或重复入库，并给出可理解的提示。
- 系统管理员能分别配置并测试三家服务商、切换进展识别的启用服务商；非管理员无法访问密钥或配置接口，切换不影响已生成卡片。
- 服务商不可用时不调用未启用的另一家，也不生成正式记录；员工仍可走原 HRM 手动更新路径。
