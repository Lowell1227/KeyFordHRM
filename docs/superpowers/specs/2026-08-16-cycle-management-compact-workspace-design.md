# 周期与计划简洁工作台设计

## 背景

“周期与计划”当前使用筛选表格承载跨周期管理，使用多个弹窗承载周期详情、新建周期、开放检查和截止日延期。业务能力完整，但高频操作需要在表格、长表单和不同弹窗之间切换；新建周期同时展示参与范围、开放时间、七个截止时间、四个等级比例和五个公示字段，正常默认配置与真正需要 HR 决策的例外配置混在一起。

绩效工作台已经形成稳定习惯：先选定业务上下文，再进入整页处理状态，页面始终突出当前状态和下一操作，返回时恢复原列表上下文。本次复用这些原则，但不照搬员工切换栏。周期管理的主要对象是周期和流程阶段，因此采用紧凑周期表格、短新建表单和横向流程详情。

## 目标

1. HR 在列表中直接看清每个周期的当前状态、下一节点和唯一主操作。
2. 常规季度、月度和年度周期只填写少量必要信息；系统默认值不逐项打扰用户。
3. 周期详情只突出当前阶段、异常和下一操作，完整设置按需展开。
4. 开放检查默认只展示阻断项；正常人员明细不占据主页面。
5. 从列表进入详情和返回时保留状态分组、精确筛选、关键词与分页。
6. 保留现有周期状态机、角色权限、开放检查、预约开放、立即开放和截止日只能延期的业务规则。

## 非目标

- 不将周期列表改成卡片墙、看板或甘特图。
- 不新增周期状态或修改状态流转条件。
- 不修改员工、主管、HR、审批角色的现有权限。
- 不要求列表接口为每条周期执行开放检查或返回实时阻断数量。
- 不重做模板匹配、组织汇报关系、校准、审批和公示模块。
- 不把申诉、面谈和改进计划改为单周期工作台。

## 信息架构

`/cycles` 保留为唯一入口，通过 URL 查询参数表达列表和详情状态：

```text
/cycles?group=attention&status=launch_blocked&type=quarterly&keyword=2026&page=2
/cycles?group=attention&status=launch_blocked&type=quarterly&keyword=2026&page=2&cycleId=<id>
```

- `group=attention|active|finished` 表示顶部状态分组。
- `status`、`type`、`keyword` 和 `page` 表示次级筛选。
- `cycleId` 存在时进入该周期的整页详情；清除后恢复同一列表上下文。
- 首次从列表进入详情使用浏览器历史入栈；详情内部刷新、重试和设置抽屉不增加历史记录。
- 无效或无权限的 `cycleId` 被清除，并显示明确提示。

## 周期列表

### 顶部结构

顶部保留“周期与计划”标题和“新建周期”主按钮。原状态下拉的高频语义提升为三个分组页签：

- 待处理：草稿、开放受阻。
- 进行中：待开放、指标制定、自评、主管评分、HR 校准、审批、已公示和申诉中的周期。
- 已结束：已关闭周期。

精确状态、周期类型和关键词收进同一行的“筛选”区域。选择精确状态时自动切换到该状态所属分组；切换状态分组时清理原精确状态，避免产生互相矛盾的条件。分组页签不额外显示数量，从而不为三个分组发起预取或聚合请求。

### 表格结构

表格收敛为四个业务列：

1. 周期：主行显示名称；副行显示类型、起止日期和参与范围摘要。
2. 当前状态：显示精确状态标签；开放受阻时附一行简短原因。
3. 下一步：根据状态显示下一业务节点和时间，不展示与当前阶段无关的日期。
4. 操作：只展示一个状态驱动主按钮和“更多”菜单。

主按钮映射：

| 状态 | 主按钮 |
| --- | --- |
| 草稿 | 开放检查 |
| 开放受阻 | 重新检查 |
| 待开放 | 查看预约 |
| 指标制定中至申诉中 | 查看进度 |
| 已关闭 | 查看归档 |

点击周期名称或表格行进入详情。主按钮也进入同一详情，但自动定位到与状态对应的当前任务。修改截止日、取消预约等低频动作放入“更多”菜单；破坏性或不可逆动作继续要求确认。

列表不为每条草稿调用开放检查接口。未执行检查的草稿显示“待完成开放检查”；只有进入详情或显式重新检查时才读取阻断项。

## 新建周期

新建仍使用弹窗，但从长表单改为默认优先的短表单。弹窗首屏只显示：

1. 周期：月度、季度、年度、试用期或自定义。
2. 周期值：例如“2026 Q4”；月度、季度和年度据此自动生成名称与起止日期。
3. HR 负责人：HR 登录时默认本人，系统管理员必须选择。
4. 参与范围：默认全公司，可切换为指定部门和人员。
5. 时间计划摘要：用一行摘要说明目标开放、自评开放和结果公示的大致时间，并标记“已按默认规则生成”。

只有自定义周期直接展示名称和起止日期。试用期周期继续沿用现有业务所需字段，不用季度规则推导。

以下内容折叠在“高级设置”中：

- 额外参与人员与明确豁免人员；
- 目标制定和自评开放时间；
- 七个节点截止时间；
- A、B、C、D 等级上限比例；
- 员工公示可见字段。

高级设置显示摘要，例如“时间节点 9 项 · 等级规则默认 · 公示字段 4 项”。用户修改自动生成值后标记为“已调整”，重新选择周期值时提示是否重新生成时间，避免静默覆盖人工修改。

底部操作：

- “保存草稿”：创建后返回列表并高亮新周期。
- “创建并开放检查”：创建成功后直接进入新周期详情并执行开放检查。

关闭存在修改的弹窗时显示未保存确认。所有跨字段时间错误就近标注到相应时间项；顶部只显示一条汇总提示，不以临时消息代替字段错误。

## 周期详情

详情替代原“周期详情”和“开放检查”两个弹窗，使用与绩效工作台一致的整页进入与返回模式。

### 顶部栏

- 返回按钮；
- 周期名称、类型和精确状态；
- 起止日期；
- 当前状态对应的唯一主操作；
- “更多”菜单承载延期、取消预约等次级动作。

### 横向流程条

将十一种精确状态归入五个展示阶段：

1. 规划配置：草稿、待开放、开放受阻；
2. 目标制定：指标制定中；
3. 绩效评价：员工自评中、主管评分中；
4. 校准审批：HR 校准中、审批中；
5. 公示归档：已公示、申诉中、已关闭。

流程条只表达进度，不允许点击跳过状态。已完成、当前和未开始使用三种稳定视觉状态；开放受阻在当前阶段显示错误标识。

### 当前任务卡

主内容只回答四个问题：

- 当前处于什么阶段；
- 下一节点和截止时间是什么；
- 是否存在阻断或逾期；
- HR 现在能执行什么操作。

参与人数、模板数量、任务进度等辅助统计保持紧凑。完整参与名单、全部时间节点、等级规则、公示字段和原始详情放入“查看全部设置”抽屉，不与当前操作并列抢占注意力。

### 运行阶段

周期已经开放后，详情首页不重复实现各业务工作台。它只展示阶段摘要和现有模块入口，例如“进入 HR 校准”“进入结果公示”。这些入口继续受现有角色权限和状态限制。

## 开放检查

草稿或开放受阻周期进入详情时，可以执行开放检查。检查结果采用异常优先展示：

- 检查通过：显示参与人数、部门数、模板数和目标开放时间的紧凑摘要；完整人员表默认折叠。
- 检查失败：按业务问题类型聚合阻断项，例如未匹配模板、缺少直属主管或参与范围无效；每项显示影响数量、自然语言原因和可用的“去处理”入口。
- 前端不把技术型 blocker code 作为主标题；代码仅保留给诊断、测试和日志。
- “去处理”跳转到相关模块时携带 `returnTo`；返回后恢复当前周期并允许重新检查。
- 只有检查通过时显示“立即开放”和“按开放时间预约”。现有角色和时间限制保持不变。

完整参与人员明细通过“查看检查明细”展开，继续展示员工、部门、直属主管、匹配模板和豁免原因。

## 截止日延期

“修改节点截止日”继续遵循只能向后延期和保持流程顺序的现有规则。入口放在详情“更多”菜单中，使用抽屉或紧凑弹窗展示完整时间轴。

- 默认突出当前及后续仍可延期的节点；历史节点只读。
- 修改某一节点时即时校验前后顺序。
- 保存前展示本次变更摘要。
- 保存成功后刷新当前任务卡和完整设置，不退出详情。

## 状态、数据与接口

首版复用现有接口，仅为周期列表查询增加可选的状态分组参数，不新增端点：

- `GET /cycles`，增加可选 `group=attention|active|finished`；精确 `status` 存在时按精确状态查询
- `GET /cycles/:id`
- `POST /cycles`
- `GET /cycles/:id/preflight`
- `POST /cycles/:id/launch`
- `POST /cycles/:id/schedule`
- `POST /cycles/:id/schedule/cancel`
- `PATCH /cycles/:id/deadlines`

前端根据周期状态和已有时间字段计算“下一步”文案。列表不得逐行调用详情或开放检查接口，避免 N+1 请求。只有进入详情后才读取详情；只有用户执行或重新执行开放检查时才读取检查结果。

服务端把状态分组映射为数据库状态集合并继续使用现有分页查询。列表响应结构保持不变，不增加三个分组的聚合计数。

如果现有列表响应无法稳定提供参与范围摘要，首版副行只显示类型和起止日期，不为该摘要新增接口字段。

## 错误与边界状态

- 列表加载失败：保留筛选条件，显示重试入口。
- 详情加载失败：保留顶部返回和周期上下文，显示重试入口。
- 开放检查失败：保留上一次成功结果但标记为非最新，允许重新检查。
- 创建成功但自动检查失败：周期已经创建，进入详情并明确提示“周期草稿已保存，开放检查失败”，不得伪装为创建失败。
- 操作后状态已经被其他人推进：刷新详情并提示当前最新状态，不继续执行基于旧状态的动作。
- 没有任何周期：显示新建周期引导；无新建权限的角色只显示空状态说明。

## 响应式展示

- 桌面端保持紧凑表格；操作列固定在右侧。
- 中等宽度合并下一步时间的次要说明，完整内容使用提示或详情展示。
- 窄屏将表格转换为紧凑行卡片，但仍保持“周期、状态、下一步、主按钮”四项顺序。
- 横向流程条在窄屏允许横向滚动，但返回、当前任务和主操作无需横向滚动即可使用。
- 新建弹窗在窄屏变为单列，底部操作固定可见。

## 组件边界

- `CycleManageView.vue`：路由查询状态、列表与详情分支、数据加载和业务动作编排。
- `CycleCompactTable.vue`：周期四列表格、状态驱动主操作和更多菜单。
- `CycleCreateDialog.vue`：短表单、高级设置、时间默认和创建动作。
- `CycleWorkspaceShell.vue`：整页顶部栏、横向流程条、加载错误外壳和响应式布局。
- `CycleCurrentActionCard.vue`：当前阶段、下一节点、阻断项和主操作。
- `CycleSettingsDrawer.vue`：完整参与范围、时间轴、等级规则和公示字段。
- `CyclePreflightPanel.vue`：检查摘要、阻断项聚合和完整人员明细。

组件只拆分展示和局部表单责任；现有 API 调用、权限判断和状态动作继续由页面层编排，避免把状态机分散到多个组件。

## 验收标准

1. 列表默认只显示周期、当前状态、下一步和操作四个业务列。
2. 每行只出现一个状态驱动主按钮；其他动作位于更多菜单。
3. 状态分组、精确筛选、关键词、分页和详情周期均可由 URL 恢复。
4. 常规季度周期不展开高级设置即可创建，名称、日期和节点时间由系统生成。
5. “创建并开放检查”成功后直接进入新周期详情；检查失败不回滚已创建草稿。
6. 关闭已修改的新建表单前出现未保存确认。
7. 周期详情显示五阶段横向流程条和一个当前任务卡，不再使用详情弹窗。
8. 开放检查默认只突出阻断项；检查通过时完整人员表保持折叠。
9. 检查通过后仍能按现有规则立即开放或预约开放。
10. 截止日只能延期、保持顺序的规则不变，并在字段附近即时反馈。
11. 从详情返回列表后恢复进入前的分组、筛选、关键词和分页。
12. 现有权限、状态机、审计记录及后端接口语义保持不变。
13. 桌面端与 390px 窄屏无页面级横向溢出，主操作始终可见。
14. 周期相关契约测试、导航测试、类型检查和生产构建通过，并完成 HR 真实页面验收。
