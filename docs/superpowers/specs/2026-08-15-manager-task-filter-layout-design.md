# 主管绩效待办筛选与列表排版优化设计

## 目标

在不改变绩效任务接口、权限和 URL 查询参数的前提下，精简主管团队待办的筛选区域，让搜索、部门、员工筛选更紧凑，并加强筛选面板与成员列表的视觉连续性。

## 现状与参考方向

当前团队工作区存在以下问题：

- 搜索框旁仍有独立“搜索”按钮，与回车搜索重复；
- “搜索 / 部门 / 员工”标签位于控件上方，增加了筛选区高度；
- 筛选面板边框、内部分隔线和下方列表形成多个割裂的区块；
- 中等宽度下控件容易换成不均衡的多行，列表起点被继续向下推。

参考图采用更紧凑的横向筛选条，筛选与列表属于同一工作区域，信息层级依次为：绩效阶段、处理状态、业务筛选、成员列表。

## 交互设计

### 搜索

- 删除独立“搜索”按钮；
- 搜索框保留前置搜索图标和“搜索姓名或工号”占位文字；
- 输入后按 Enter 执行搜索，并继续复用现有 `applyTeamSearch()`、URL `keyword` 参数和页码重置逻辑；
- 点击输入框清除按钮后立即清除搜索条件并刷新列表；
- 普通输入过程不自动请求，避免每次按键都刷新团队列表。

### 下拉筛选

- 去掉控件上方可见的“部门”和“员工”标签，保留 `aria-label` 供可访问性和自动化测试使用；
- 部门下拉占位文字为“全部部门”，员工下拉占位文字为“全部员工”；
- 选择后立即沿用现有 URL、任务选择清理和列表刷新行为；
- 重置按钮保留为紧凑图标按钮，并通过提示文字说明用途。

## 布局设计

### 桌面与常规内容宽度

- 处理状态按钮保持在筛选区域第一行；
- 第二行使用单行紧凑工具栏：搜索框、部门下拉、员工下拉、重置按钮；
- 搜索框占用剩余空间，设置合理最小宽度；部门和员工下拉使用稳定的紧凑宽度；
- 工具栏使用浅色背景、轻边框和统一圆角，减少原有上下标签造成的高度；
- 缩小筛选区与成员列表之间的间距；成员列表头与筛选区左右边线、内容起点保持对齐。

### 窄内容区与移动端

- 使用团队工作区容器宽度决定换行，不依赖整个浏览器窗口宽度；
- 中等宽度下搜索框独占第一行，部门和员工下拉在第二行并排，重置按钮位于末尾；
- 手机宽度下搜索框、部门、员工依次单列，控件宽度占满可用空间；
- 保持页面无文档级横向溢出，成员列表继续使用现有内部响应式行为。

## 列表视觉衔接

- 筛选区域不再表现为与列表割裂的大卡片；
- 团队成员标题、任务数和批量操作保持现有业务含义与按钮权限；
- 统一筛选条、列表标题和列表内容的水平内边距；
- 不改变表格列、任务详情侧栏、分页或批量处理逻辑。

## 技术范围

本次仅修改：

- `web/src/views/task/TaskListView.vue` 的团队筛选模板与相关样式；
- 对应 Playwright 测试中的搜索按钮缺失、Enter 搜索和响应式布局断言。

本次不修改：

- 后端 API、数据库和绩效任务状态机；
- 搜索、部门、员工筛选的 URL 参数；
- 主管可见范围和处理权限；
- 左侧“我的绩效待办 / 我团队的绩效待办”结构。

## 验收标准

1. 周强打开团队绩效待办时看不到独立“搜索”按钮。
2. 在搜索框输入姓名或工号并按 Enter 后，URL 和列表立即更新；清空输入框后列表立即恢复。
3. 部门与员工下拉在桌面宽度下与搜索框处于同一紧凑工具栏。
4. 处理状态、筛选工具栏、成员列表的层级清晰，左右边距一致，视觉上属于一个连续工作区。
5. 390px 宽度下控件不重叠、不截断，页面无文档级横向滚动。
6. 周强仍可打开张晨待处理任务，保存、通过和驳回操作保持可用。
7. 契约测试、入口测试、类型检查和生产构建通过；真实浏览器复核桌面与窄屏布局。
