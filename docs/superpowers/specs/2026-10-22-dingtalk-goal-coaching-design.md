## 1. 产品目的与已确认决策

帮助员工跨过“目标不知道怎么定”的第一道门槛。在钉钉中表达工作、提供材料、获得专业辅导，形成本人理解并认可的目标，沿现有 HRM 流程办理。

已确认的业务约束：

- 员工先拟目标，再由主管审核确认；复用现有流程，不另建审批系统。
- 起草内容不向主管展示，员工明确提交后才进入主管处理范围。
- 上级目标与本人重点工作同时存在，不要求员工二选一。
- 会议、消息、文档是目标形成与完善的依据，HRM 是正式目标留档位置。
- 首版包括多材料输入、系统背景、无材料起步、专业辅导、多轮修改、审核退回后的完善。
- 指定钉钉消息、会议纪要、在线文档的直接接入是首版重点，不只提供文件上传后的分析。
- 采用“单聊收材料 + 按需读取指定来源”；不做文件夹持续同步或全企业知识扫描。
- 既有试点限制仍是姚瑶（工号 312）单人，不恢复此前四人范围，不向其他人发消息，不改真实绩效结果。

本文其余章节是供本次评审的具体设计，不将技术建议或保存期限冒充已确认业务政策。

## 3. 首版材料入口

所有材料先进入本人私有的本次辅导会话。来源分为“员工提供”和“服务端验证的钉钉来源”，不得混为一谈。

| 入口 | 首版预期行为 | 接入验证条件 |
| --- | --- | --- |
| 文字及消息摘录 | 直接发送、粘贴或客户端支持的选定消息转发，允许多条累积后一起分析 | 验证单条与合并转发的实际回调类型；不支持的类型明确提示替代方式，不伪装已读完整上下文 |
| 截图与富文本 | 提取文字和结构，保留可定位到图片的依据；模糊数字让员工核对 | OCR 能力、中文识别、图文混排及尺寸限制通过测试；图片只按材料处理 |
| Word/PDF/Excel | 解析正文、页码或工作表/单元格来源；扫描件转 OCR；支持多份材料综合 | 先支持 DOCX、PDF、XLSX；旧 DOC/XLS 提示转换。加密、损坏或超限文件不静默截断 |
| 语音 | 优先利用可用转写；缺失或明显错误时提示重述或补充文字 | 钉钉语音回调和转写实际可用性需验证；不默认承担长会议录音全量转写 |
| 指定在线文档 | 员工提供链接后解析受支持资源，按绑定本人身份和资源权限读取 | 应用接口权限、本人资源权限、企业边界及文档类型均通过；不能用管理员身份兜底 |
| 指定会议纪要 | 读取已存在且本人有权访问的纪要、摘要或转写，形成带出处的参考内容 | 对具体产品、认证方式、API/工具契约及企业能力做验证；不把会议日程信息当纪要正文 |

“直接接入”不等于遍历原聊天会话。首版不持续监听员工群聊，不自动入会录音，不获取整库文件，也不沿材料中的链接自动扩大读取范围。

连接器暂不可用时，展示原因和上传/粘贴入口。替代入口保证流程可继续，但不能据此把该直连能力标记为已交付。若某项无法在既定权限下实现，应报告并重新确认范围，不静默删除首版重点。

### 材料接收与选择

1. 先校验身份和试点范围，再下载、解析或调用模型。
2. 每份材料显示“接收中、可分析、需授权、解析失败、已排除”，可逐项移除。
3. 累积材料后展示本次清单，由员工点击“开始分析”；一条明确的“请分析这些材料”也可触发分析，但仅绑定已展示的具体清单。
4. 只将本次选中的材料、必要系统上下文送入已启用的处理服务。首用说明用途、服务商和隐私范围。
5. 未识别到原消息作者/时间时标记“员工提供，原始出处未验证”；不能把提交人当原作者，不能编造会议、页码或引文。

## 4. 员工体验与目标辅导

### 有材料时

员工：“这是会议纪要和主管的要求，帮我拟本季度目标。”

助手先给出简短理解：明确要求、可能相关的本人职责、需要澄清的冲突，再提出少量候选目标；不一次抛出整套必填问题。员工可以选择保留、合并、拆分、删除或补充。

### 没有材料时

员工：“不知道这季度怎么定目标。”

助手使用已授权且实际存在的岗位、周期、上级目标或本人历史目标，提出可讨论的方向，并问一个影响最大的具体问题。岗位职责缺失时承认缺失，不能只凭岗位名称假定实际工作，更不能推断系统权限。

### 专业辅导规则

- 区分“做一次活动”与“交付什么成果”，但保留适合岗位的过程性目标。
- 定量目标明确基线、目标值、单位、数据口径和证据；未知数值留待员工补充，不凭空生成增长率。
- 定性目标明确交付物、质量标准、完成时间和验收方式，不强造百分比。
- 标出协作依赖、资源约束与本人可控范围，不将其他部门全部责任转给员工。
- 上级要求与本人工作、不同材料之间有冲突时展示冲突，请员工决定，不私自判断领导意图。
- 区分“原文明确要求”“助手建议”“员工已确认”，专业检查不是新的强制绩效政策或打分标准。
- 合并重复内容、检查目标之间的冲突与总量，解释调整原因；不按固定条数或固定权重强行套模板。
- 主管退回后，读取本人有权查看的具体意见，给出修改建议与差异；不能把对主管意见的解释当作审核结论。

### 系统字段与草稿衔接

候选目标映射到现有目标名称、说明、考核标准、数据来源、数据口径、目标值/定性目标值、单位、权重及合法上级对齐关系。已有字段与业务校验继续有效。

没有现成结构化字段的辅导信息先留在私有建议中；不把模型任意字段塞进正式表。需要增加正式字段时应在实施计划中说明迁移及业务影响，取得确认。

首次进入明确本人考核任务；有多个候选周期时由员工选择，不能让模型猜任务。普通材料分析不要求已有可更新进展目标，但写回草稿必须满足该任务当前允许本人编辑的条件。

建议卡片只展示摘要与清晰动作：“继续完善”“查看目标草稿”“保存到我的草稿”。长表格、逐项权重及正式提交在现有钉钉内 HRM 页面办理；沿用同一个任务入口，不创建第二套目标表单。

## 5. 正式写入、版本与隐私

辅导建议与 HRM 目标草稿分开保存。辅导建议不是正式目标，也不是另一套审批对象。

### 保存流程

1. 员工预览本次将新增、修改或删除的目标，尤其显示现有手工内容的变化。
2. 明确点击“保存到我的草稿”。服务端重新核对身份、任务归属、可编辑状态和版本。
3. 将选定变化与最新完整草稿合并校验，再经现有目标服务保存；不能用新建议整表覆盖员工其他目标。
4. 保存操作绑定会话版本、任务版本和幂等键；重复回调仅返回同一结果，过期卡片不覆盖新内容。
5. 版本冲突时保留建议并要求重新核对差异，不自动重试覆盖。
6. 保存成功仍是草稿；打开卡片、阅读建议、开始分析或说“可以”均不等于提交审核。

### 可见性

- 私有材料、辅导对话、候选建议仅本人业务身份可读；管理员默认只能查看运行状态和脱敏错误，不增加查看全文入口。
- 写回 HRM 后的未提交草稿仍须满足不向主管展示；需覆盖详情、列表、导出、目标地图、参考目标接口、通知和直接访问等路径。
- 提交后按现有审批和授权范围展示目标，不自动附上原始聊天、文件或辅导过程。
- 已提交版本不因员工继续辅导而变化；审核退回或撤回后的私有修改不能提前泄露。主管可见的既有已提交版本与新草稿应明确区分。
- 已确认目标不能由助手直接改写；只能形成私有修改建议，并进入系统已有合法变更路径。没有适用路径时保持建议状态。
- 主管身份取真实任务快照及现有业务规则，不能从钉钉组织、岗位名称或模型输出推断。

源码读取路径中的草稿隐私风险必须先以隔离真实角色测试复现和定界。如果确认需要调整现有共享权限，先向用户说明影响并确认，再实施；不得绕过风险接通助手保存。

## 6. 技术职责与数据处理

保持模块化单体，不新增微服务。新增目标辅导应用服务，复用现有身份、AI 服务配置、文件基础设施、审计和任务业务层。

| 职责 | 输入与输出 | 不得承担 |
| --- | --- | --- |
| 消息分流 | 已验证单聊事件 → 查询、进展、目标辅导或材料输入 | 用模型猜测后直接写业务数据；破坏现有四类查询与进展入口 |
| 材料接入 | 员工选定资源 → 授权材料与来源信息 | 管理员代读、任意 URL 抓取、整库扫描 |
| 内容解析 | 受限文件 → 文本、结构、来源定位、解析警告 | 执行宏、脚本、外部嵌入对象或文档中的指令 |
| 目标辅导 | 本人上下文与选定材料 → 结构化候选及澄清问题 | 自行改权限、提交、审核、算分或生成事实依据 |
| 草稿衔接 | 本人明确选择与版本 → 现有任务草稿保存结果 | 绕过任务服务或覆盖并发修改 |

新增辅助记录至少包含：本人和企业标识、会话/任务绑定、材料来源与读取时间、授权上下文、内容摘要与定位、建议版本、任务基线版本、模型/规则版本及保存操作回执。正式目标仍只有原 HRM 业务数据一份。

辅导过程需支持跨日继续，不能直接依赖现有短期进展草稿的存储期限。建议使用 PostgreSQL 保存私有会话与版本元数据、现有私有文件基础设施存材料副本、Redis 仅承担短期任务和锁；具体迁移进入后续实施计划。

专业辅导规则独立版本化：目标澄清、成果表达、定量/定性标准、对齐与冲突检查。可借鉴或评测千问办公的专业能力，但本版不依赖其专家运行时，也不将千问模型 API 等同于千问办公技能。模型输出通过结构与业务验证后才可展示或进入保存确认。

## 7. 安全、保存期限及异常

### 安全要求

- 文档和转发消息都是待分析数据，不是系统指令；材料中的“提交目标、向某人发送、读取其他资料”等文字不触发操作。
- 下载前校验企业、本人、来源和资源权限；进入分析、恢复会话、重新获取在线材料时重新校验。失效或撤权的在线来源不能靠缓存继续提供原文访问或再次分析。
- 只访问经验证的钉钉资源及下载域名；阻止内网/环回地址、非允许协议和越界重定向。临时下载凭据不得返回聊天、模型或日志。
- 校验实际文件格式、大小、解压体积和解析耗时；限制压缩炸弹、恶意文档与外链。首版不处理压缩包和执行性附件。
- 原文、对话与模型回复不写普通运行日志；密钥使用现有加密配置，不进入本文、提示词或卡片。
- 只有必要内容进入已批准的服务商；新增 OCR、多模态或转写供应商需另行说明并授权，不能静默切换服务商或区域。
- 用户移除材料后，排除其片段及派生会话摘要，标记受影响建议需重算/复核；不能只隐藏附件列表却继续向模型发送其内容。

### 待本文评审的运行默认值

以下是设计建议，不是已生效策略：每次最多 10 份材料，单份最多 20 MiB；解析内容超限时提示选择范围，不静默截断。长录音和视频不纳入首版自动转写。

原始材料临时副本建议在解析完成后 24 小时内清理；提取文本、私有会话与未保存建议在连续 30 天未使用后清理，保留到期提示和主动删除入口。已保存 HRM 草稿及正式记录不随辅助资料删除。

清理仅针对本系统副本，不删除钉钉源消息/文档；用户删除后立即停止使用，备份副本按既有备份生命周期淘汰，不能承诺即时从所有备份消失。审计保留主体、时间、动作和结果，不保留原文；审计期限沿用经核实的既有政策。

### 失败行为

- 无权限、过期链接、纪要尚未生成：明确说明哪份材料不可用，允许剔除或换一种提供方式。
- 解析不完整、语音/OCR 数字不可靠：标记具体位置，不能当确定事实生成目标值。
- 模型超时或响应不合规：保留本人草稿和材料选择，允许重试或回到现有页面；不自动调用其他供应商。
- 部分材料成功：展示缺失清单，员工决定是否基于剩余材料继续。
- 多任务/多周期歧义：先选任务；材料内容不能决定系统身份或权限。
- 同一会话连续收到多条输入：按版本串行合并，旧结果不能覆盖新材料和员工修改。

## 9. 验收标准

### 员工业务体验

1. 无材料、只有模糊想法时，可以从已有真实背景起步；员工不必先填写完整表格或理解绩效术语。
2. 同时提供会议纪要、消息和文档，助手能综合而非逐份重复摘要；每条关键要求可追溯，推测清楚标注。
3. 上级目标与本人工作能够同时纳入；无法量化的成果有可讨论的验收标准，不出现编造数值。
4. 员工能连续修改、合并、删除建议，关闭后在有效期内继续；删除材料后不会残留在后续分析上下文。
5. 保存前看见与现有草稿的差异；保存不提交、不通知主管、不丢其他手工目标。
6. 主管退回后，助手基于真实反馈给出修改建议；正式审核和最终确认仍由原流程承担。

### 权限、可靠性与技术验证

7. 本人、主管、同部门无关人员、HR、管理员分别验证材料和未提交草稿边界；覆盖直接 API、列表、导出、地图和转发卡片。
8. 错企业、错身份、名单外、停用/离职、撤权及资源权限不足，在解析/模型调用/保存前分别拒绝；异步返回时投递前重新检查。
9. 重复消息、重复点击、旧卡片、任务状态改变和并发手工编辑都不会重复写入或覆盖新版本。
10. 恶意材料指令、任意链接、伪装文件、解析失败和服务商故障不会越权或产生正式记录。
11. 既有帮助、四类绩效查询、进展识别与确认保存行为不被目标辅导分流破坏；重新验证实际卡片落地与免登。
12. API 运行相关集成与权限测试；涉及共享权限/数据模型时运行全量测试与构建。Web 运行类型检查/构建及 PC/手机针对性 Playwright，验证长文本、材料状态和字段旁错误。

### 单人试点限制

真实联调仅姚瑶，其他消息接收人保持零发送。主管/HR 分角色验收先在隔离数据与模拟消息投递中完成。

真实“提交主管审核”会触发既有主管通知，因此不属于当前单人试点可直接执行的动作。需要扩大真实流程测试时，必须单独确认收件人和写入范围；不能为了演示自行触发通知，也不能全局关闭正常员工通知来规避限制。

本次设计确认不授权真实绩效草稿写入、应用权限调整、数据库迁移或发布。上线须另行明确目标提交、最新生产基线、备份/回滚、变更服务与功能开关；只开启通过闸门的能力，继续区分开发完成、上线与业务验收。
