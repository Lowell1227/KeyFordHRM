# 绩效工作区界面优化设计

## 目标

参考用户提供的三个实际系统页面，在不改变后端接口、业务状态机和权限规则的前提下，将现有“行动计划、目标地图、绩效考核”重组为统一、紧凑、适合钉钉内嵌的绩效工作区。

本轮只覆盖三个员工与管理者高频页面：

- `/action-items`：菜单与页面语义调整为“目标跟进”，保留行动项管理能力。
- `/objectives`：目标地图。
- `/tasks`：菜单与页面语义调整为“绩效待办”，保留任务详情入口。

HR 后台、校准、审批、报表、试用期、转正等页面不在本轮改造范围内。

## 方案比较

### 方案 A：共享绩效工作区组件（采用）

新增一个只负责布局和导航的 `PerformanceWorkspace`，由三张现有页面提供标题栏、上下文栏和主内容。该方案能统一结构，同时继续复用现有 API、表单弹窗、权限判断和路由，改动边界清晰。

### 方案 B：直接复制参考图结构到三个页面

实现速度快，但会复制导航、上下文栏和响应式样式，后续调整容易产生三个版本，不采用。

### 方案 C：重做整个应用壳层

可以最大程度接近钉钉截图，但会同时影响后台管理和其他业务模块，验收风险与回归范围过大，不在本轮采用。

## 信息架构

应用现有左侧主导航和顶部用户操作区保持不变。进入本轮三个绩效页面后，主内容区呈现统一的三段结构：

1. 页面标题栏：显示当前页面名称和搜索入口区域。
2. 绩效二级导航：固定显示“目标跟进、目标地图、绩效待办”，直接切换三个现有路由。
3. 工作区主体：根据页面需要分为上下文栏和主内容区。

桌面端工作区的稳定宽度规则：

- 二级导航宽度 `148px`。
- 上下文栏宽度 `256px`；目标地图可折叠为顶部筛选工具条，不强制显示空栏。
- 主内容区占据剩余宽度，最小宽度为 `0`，内部表格自行横向滚动。
- 圆角不超过 `8px`，不使用嵌套卡片和大面积渐变。

窄屏下不复制桌面三栏：二级导航改为顶部横向标签，上下文栏改为可横向滚动的筛选区，主内容位于下方，保证按钮和文本不重叠。

## 共享组件边界

### `PerformanceWorkspace.vue`

职责：提供标题、三页导航、可选上下文栏、主内容区和响应式结构。

输入：

- `title: string`
- `activeSection: 'tracking' | 'map' | 'tasks'`
- `contextWidth?: string`

插槽：

- `toolbar`：标题栏右侧命令。
- `context`：员工、周期或阶段列表。
- 默认插槽：页面主内容。

组件不请求数据、不判断角色、不修改业务状态，只通过 Vue Router 切换现有路由。

### `PerformanceContextPanel.vue`

职责：提供上下文栏的标题、可折叠分组、选中项和状态标签样式。它只渲染传入数据，通过事件上报选择结果。

### 页面适配

- `ActionItemsView.vue` 继续拥有目标、负责人、状态筛选和全部增删改逻辑；工作区上下文栏展示当前目标及目标列表，主区保留列表/看板切换、行动项表格和表单弹窗。
- `ObjectiveMapView.vue` 继续拥有周期、层级、部门、用户和目标 CRUD；顶部工具条展示周期与目标范围筛选，主区保留目标树表格。没有数据时使用轻量空状态，不虚构目标。
- `TaskListView.vue` 继续调用 `tasksApi.findMine`；上下文栏按周期展示“我的绩效待办”阶段，主区展示当前任务列表。阶段状态由真实任务状态映射，不能把不存在的任务渲染为“已完成”。

## 页面交互

### 目标跟进

- 默认选择 URL 查询参数中的目标；没有参数时选择目标列表第一项。
- 上下文栏可搜索目标并显示目标名称、负责人和进度。
- 主区标题显示当前目标，保留新建行动项、刷新、列表/看板切换。
- 无目标时显示“暂无可跟进目标”；有目标但无行动项时显示“该目标下暂无行动项”。

### 目标地图

- 周期选择继续驱动 `objectivesApi.findAll({ cycleId })`。
- 目标范围使用“全部目标、公司目标、部门目标、个人目标”分段控件，并映射现有 `level` 查询参数。
- 保留当前新建、编辑、更新进度、删除和跳转行动计划能力；只读角色仍只看到允许的操作。
- 工具条与树表格位于同一连续工作区，不再以多张浮动卡片分隔。

### 绩效待办

- 默认展示全部周期；用户选择具体周期后，只展示该周期任务。
- 上下文栏按员工阶段呈现“目标制定、目标确认、自评、结果确认”；只有管理角色且有对应真实任务时才展示团队阶段。
- 当前阶段从任务状态推导，点击阶段筛选任务，点击主区任务进入现有 `/tasks/:id`。
- 状态颜色只表达“待处理、处理中、已完成、未开始”，同时保留现有 `StatusBadge` 的业务状态说明。

## 数据与权限

- 不新增 API，不修改 Prisma 模型，不更改任务状态机。
- `ObjectiveMapView` 和 `ActionItemsView` 沿用现有 `canManage` 角色判断。
- 员工列表、部门列表等数据仍按现有角色分支加载，避免因界面改造扩大数据可见范围。
- 绩效待办只使用 `tasksApi.findMine` 返回的数据，不构造团队任务或他人绩效结果。
- 后端 403、空数据和网络失败继续保持安全降级；页面显示空状态或现有错误提示，不泄露受限数据。

## 视觉规范

- 主色沿用项目现有蓝色，状态色使用绿、橙、红和中性灰，避免单一紫蓝色主导。
- 页面背景使用浅灰蓝，导航和内容面使用白色；边框采用低对比度中性灰。
- 标题为紧凑的工作台字号，不使用营销式大标题。
- 命令按钮使用 Element Plus 图标和文字；筛选使用选择器、分段控件或搜索框。
- 空状态优先复用现有 `EmptyState`，不新增与业务无关的插画资产。

## 错误与加载状态

- 列表和树加载时保留固定工作区尺寸，通过 `v-loading` 表达加载状态，避免布局跳动。
- 获取筛选项失败时保留空选择器，主数据失败时清空当前列表并显示现有错误提示。
- 切换周期、目标或阶段时重置对应分页，避免停留在不存在的页码。
- 路由切换和对话框关闭不丢失后端已保存数据；刷新后根据 URL 查询参数恢复目标选择。

## 测试与验收

### 自动化

- 新增 Playwright 页面结构测试，验证三个路由都出现共享二级导航，且当前项正确高亮。
- 验证员工角色看不到无权限入口和管理按钮。
- 验证目标地图筛选、目标跟进目标切换、绩效待办阶段切换仍触发真实页面行为。
- 运行 `npm run type-check`、`npm run build` 和相关 Playwright 测试。

### 视觉验收

- 在 `1440x900` 桌面视口检查三栏比例、表格滚动、弹窗和空状态。
- 在 `390x844` 移动视口检查导航改为横向、控件不溢出、文本和按钮不重叠。
- 使用浏览器截图与用户提供的参考图对比信息层级；目标是结构和工作流相似，不复制钉钉外壳或第三方品牌元素。

## 非目标

- 不复制钉钉左侧消息、通讯录等外层客户端界面。
- 不实现参考图中项目当前没有的数据权限或“其他目标”查询能力。
- 不新增消息推送、组织同步或钉钉免登功能。
- 不调整 HR 管理后台的信息架构。
