# 员工档案提交立即生效

用户于2026-11-13明确选择：“所有档案可编辑字段提交即生效，包括绩效直属上级；入离职仍走原流程”。此项替代旧方案中日常档案按字段拆分免审/待审核的规则；本轮开发授权不等于生产发布授权。

## 行为

- 有员工档案编辑权限的操作员，在原员工数据范围内维护所有档案可编辑字段，点击“提交”即生效；不再要求另一名HR二次审核。
- 自动暂存只保存草稿。打开已有草稿、未处理的旧档案变更，可继续填写并提交；不自动批量处理历史待审数据。
- 现有 `manual_archive_change` 复用原单、版本保护、修订历史和事务内资料/合同/任职/关系生效逻辑。已生效部分以正式数据为准，历史快照不能回滚他人已生效内容。
- 页面只提示“档案已更新”。合同新增/修改/移除随提交生效；错误贴近字段或集中为一条页内提示，输入保留。
- 人员设置中的绩效直属上级、批量归属部门遵循同一字段规则，提交即更新，避免关联入口继续要求审核。
- 兼容的 `PATCH :id/profile` 入口也委托同一提交逻辑；既有 `manual_profile_change` 历史申请不自动改写。
- 待到岗员工的资料修正沿用原待入职任职，不创建可被定时投影误选的新任职；资料与绩效关系在确认到岗后仍保留。到岗日期、工号生成及账号启用继续由原入职流程控制。
- 新入职、再入职、离职、到岗确认、工号生成、系统权限、花名册导入及组织审批流程不变。档案编辑不得绕过入离职改变账号启停；已启动考核任务的关系快照不改。
- 当前合法性校验、附件权限、敏感字段保护及并发冲突保护保留。空修改不制造申请或生效记录。

## 实现选择

复用现有档案变更与审计，限定日常 `manual_archive_change` 和人员设置的 `manual_performance_relation` 直接生效入口。不开全局自动审批，不增加平行档案表或宽松审核开关。内部状态可复用兼容的已生效状态，但不伪造人工审核人、审核动作；界面明确显示直接生效。
