## 第一批 · 邮箱试用与岗位进度

1. **先试一个岗位。** 选一张已批准且当前可用的招聘需求和一位现有招聘经办。配置生产侧经过核对的单账号、准确目录和读取起始时间，使用现有「读取招聘邮箱」按钮。客户端凭据用受控服务端配置传递，沿用最小访问和只读验证；本机 DPAPI 文件仅作本机配置，不能直接当生产配置。目录选择和初次起始时间须有对应的明确范围依据。
2. **核对本次资料。** 在隔离环境先验一个样例闭环。正式试用只处理经办确认可用于招聘的邮件，历史邮件、来源不明资料及其他目录继续由原业务范围控制。验证有简历附件、普通文档或图片、仅正文、缺岗位、同名岗位以及重复读取。明确的外部职位 ID 或已核实的一一对应链接才可作为自动归岗依据，其他由经办确认。支持保存待核对、补材料、去重复用原档案，以及用户已选的「仅入库」「入库并创建应聘」。
3. **让岗位详情看见前段进度。** 复用现有招聘需求详情和已上线后段统计，增加待收简历、待筛选、面试中，以及需要定位的待确认阶段。分清收件记录和应聘单，统计与点开后的列表同源。归岗不明显示在经办队列，由经办处理后才进入相应岗位的统计。
4. **提前关联意向需求。** 从需求收件或明确由经办选定需求时，保留应聘的意向需求关系，供筛选、面试和阶段视图使用。命中既有同岗应聘时由经办确认复用，不能静默搬到另一张需求。旧应聘缺准确来源继续显示待关联，避免按岗位名倒填。一条当前应聘在岗位统计中只有一个意向归属，变更须留痕。提交录用仍以正式选定且校验过的获批需求及冻结快照为准，独立录用确认照旧。当前意向、历史提交快照和名额各有明确依据。

## 第二批 · 经办工作台

- 复用全局工作台的招聘待办，追加「待核对简历」「待归岗位」「入职日期已过，待确认结果」。继续显示原有跟进、面试、反馈和录用确认。每条显示岗位、经办人和下一步，点击定位到原收件、应聘或入职单。
- 只展示现有角色和数据范围内的相关记录。招聘经办看到自己应处理的收件与跟进，面试评审和独立录用确认人继续在原范围工作。到岗提醒依据当前仍有效的预计到岗日期和已有办理状态，按北京时间计算，改期或关闭后从待办消失。已到岗、明确终止、已办结的收件不进入相应未办队列。
- 待办从实际业务记录派生，完成原业务即可消除提醒。第一版使用站内工作台，外发通知沿用当前独立授权和配置。

## 第三批 · 招聘结案和渠道分析

- 在需求详情支持经办登记招满、暂停或取消，记录办理人、时间、原因或依据。提交前展示批准人数、接受待到岗、实际到岗、剩余名额和尚待处理的应聘，提供明细入口。经办在 BOSS 官方端处理相应外部职位，在 HRM 记录已处理状态。
- 保留当前有效的审批、录用和名额规则。候选人接受占一个名额，明确终止才释放，延期和单次可重提的入职撤回继续保留，实际到岗计入已招。结案状态不推断在办人员的结果，也不自动释放。涉及暂停、取消后如何限制新的录用等尚未明确的业务规则，由项目经理单列，优先复用现有等价状态和已确认的校验。
- 招聘分析从需求和应聘取数。渠道采用经办核对的应聘来源，分别展示有效应聘、进入面试、录用和到岗，缺来源单列。收件工作量可单看收件数；应聘转化按唯一应聘计数，同人不同岗位分别统计，多次来信和重复面试不重复计数。录用与接受口径分别注明，所有数字可查看权限范围内的明细。

## 验收及发布

| 检查 | 通过条件 |
| --- | --- |
| 邮箱和收件 | 验证指定目录只读、实际样本能进入待核对、重复读只保留一份收件状态；缺岗位或不可靠标识需要人工核对。附件解析和普通邮件区分，失败可恢复。看到邮件不等于候选人同意入库。 |
| 人员与阶段 | 独立核对同人复用、不同岗位和同名岗位、仅入库与创建应聘、跨需求变更留痕。挂起的收件或早期应聘不占名额。原独立录用确认、到岗与终止流程回归通过。 |
| 待办与结案 | 招聘经办、普通查看者、窄录用确认人、面试评审、人事按各自权限实测。到岗延期、单次入职撤回、终止、确认到岗均能正确更新名单。结案后可追溯仍有的待办与原外部职位。 |
| 报表 | 同一天中有重复来信、同一人两个岗位、同一应聘多次面试，列表与去重统计对得起来。按渠道、岗位和期间可复核。 |
| 发布 | 以固定隔离预览完成真实后端、PC 与手机验收。涉及迁移、权限或共享写入走严格档。发布前重核最新主线、生产与并行交付、备份和回退，按批发布受影响服务。上线后用实际角色只读冒烟，真实业务由有权经办完成。 |
