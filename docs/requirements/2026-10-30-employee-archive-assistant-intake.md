# 员工档案助手：首条资料接收契约（评审稿）

日期：2026-10-30。状态：用户已确认姚瑶单人、钉钉单聊、虚构资料、仅保存待核草稿的实施与上线范围；功能实施中，尚未启用或写生产资料。

依据：[员工档案共用流程](2026-10-30-employee-archive-shared-workflow.md)。共用能力已随 `80244b3` 上线；本稿只描述助手如何接入，不重做初始化、档案库、审核或维护页面。

## 1. 产品范围

HR 主动提供一条变更资料 → 核对对象与差异 → HR 明确点击“保存待核草稿” → 进入现有档案草稿/问题浮层 → 按现有规则提交、审核和生效。

- 员工仍在原钉钉 OA 发起申请。首轮不订阅或批量拉取 OA，不改变 OA 正文、状态或审批链。
- HR 提供的“已审批”文字只是来源声明；未从可信接口核实的审批结果不能标成已核实，更不能据此跳过 HRM 审核。
- 既有 66 条待核草稿及其来源、身份问题和真实冲突原样接续，不能再次批量导入、自动绑定或补齐未知事实。
- HRM 是正式档案唯一来源。千问办公、WorkBuddy 等后续适配使用同一业务服务；本稿不表示它们已经接通。
- 推荐首轮沿用姚瑶单人钉钉单聊，只用虚构、非敏感样例验收。外部渠道启用及实际资料范围须明确确认；缺少既有档案维护能力时应拒绝，不能自动扩权。

## 2. 受控输入与预览

服务端取得已认证的真实操作者、组织、渠道和原始事件标识；来源不得由模型自报。内部契约至少包含：

| 信息 | 约束 |
| --- | --- |
| 操作者 | 来源于 HRM 会话或已验证渠道绑定；服务层再次检查 `employee_archive_edit`。 |
| 接收来源 | 受控 `sourceSystem`、稳定 `sourceReference`、实际提供时间及材料摘要。来源须在现有共享来源集合登记，不能冒用初始化来源。 |
| 人员对象 | 明确选定的现有人员 UUID，或明确标记为未绑定的待核资料。姓名相同、电话候选、历史工号相似均不能自动认定。 |
| 资料提案 | 只接当前支持的字段；省略表示未提供，显式空值保持待核语义。敏感字段不经模型推断、回填或清空。 |
| 资料基准 | 现有人员的事实指纹；已有请求的请求 ID、版本和来源绑定。不能使用无版本的旧预览覆盖新事实。 |
| 来源证据 | 服务端从实际接收材料形成引用、摘要及校验结果。不得信任模型生成的 OA 编号、审批人或审批状态。 |

预览展示对象、当前资料、提供值、来源性质及缺项/冲突，明确指出“尚未保存，正式档案未改变”。预览不写草稿、审计业务动作、正式账号或工号，也不外发真实资料到模型。

首条验收建议使用虚构人员及既有工作地点选项，验证 `workLocation` 一项的完整通路。此为首个验收切片；入职、离职及其他基础信息仍按同一共用流程逐项接入，不把任职状态直接改写当作完整入离职流程。

## 3. 保存边界

- 渠道首轮只可预览并明确保存接收草稿；需要继续修订时进入既有 HRM 草稿页。已有有效草稿先返回对应入口，不能自动选中其他 HR 的草稿、覆盖或另建重复单。
- 已明确匹配员工：扩展并复用 `saveArchiveDraft` 的共用保存能力，保留现工号、事实基准、来源及问题；不能直接调用 submitted 入口。
- 未绑定资料：复用 `saveEmployeeCreateDraft` 保存待核资料，保持 `userId = null`、`employeeNo = null`、`recordStatus = draft`。保存不表示此人是新员工，更不自动新增或再入职。
- 首次建立来源、校验问题、草稿及审计必须在同一事务完成；现有员工保存方法的审计目前与保存分离，需要在共用服务内收敛，不能复制第二套存储实现。
- 接收前按受控来源和稳定事件标识去重。同一来源同一内容返回原请求当前真实状态及维护入口；同一标识不同内容报冲突，不重复建单或静默替换，也不将已提交、已审核或已生效请求回退为草稿。
- 保存前重验权限、来源、对象和事实指纹；版本或事实已变化返回 409，保留输入并要求重新核对，不能自动重试覆盖。
- 模型不能指定操作者、工号、系统权限、审核结果、问题解决标记、绩效关系，不能创建猜测的组织、删除合同或调用提交/审批/正式应用方法。
- “确认以当前资料为准”只走既有问题确认接口、指纹和审计；不写正式事实、不审批、不用于关闭身份或缺项问题。

首次成功保存返回现有请求 ID、版本、`draft` 状态、问题列表及下一步维护入口，用户文案为“已保存待核草稿，正式档案未改变”。重复接收返回原请求当前真实状态、版本和入口，并说明“该资料已接收，本次未重复保存”；原请求已生效时应如实展示，不再声称正式档案未改变。接收动作本身不能写成“变更完成”或“审批通过”。

## 4. 首轮验收

采用隔离环境与虚构资料；生产首轮只核对允许身份及入口，不自动提交或修改真实档案。

| 场景 | 必须证明的结果 |
| --- | --- |
| 有权限 HR 预览 | 无数据库变更，来源声明与正式事实分开展示。 |
| 明确保存一条工作地点建议 | 仅生成一条现有变更草稿、来源、问题与审计；正式资料、工号和账号不变。 |
| 草稿期间重复事件 | 返回原草稿，不多建单、不重复记保存动作。 |
| 原请求已提交或生效后重放 | 返回原请求当前真实状态与入口；不回退、不声称仍是草稿，本次零重复写入。 |
| 同标识异内容 | 拒绝并给出重新核对动作，不替换原材料。 |
| 资料基准过期 | 409，输入保留，不覆盖新事实。 |
| 员工已有其他 HR 草稿 | 返回既有维护入口，零覆盖、零重复建单。 |
| 同名、电话候选、来源冲突 | 保持未绑定或阻断并要求核对，不认定正式人员、不生成工号。 |
| 明确未绑定资料 | 只保存无用户/无工号的待核草稿，不进入新增/再入职流程。 |
| 普通员工、纯审核 HR、伪造操作者/来源 | 保存拒绝；未授权资料不进入模型或返回给调用者。 |
| 伪造“OA 已批准”及提交/审核动作 | 来源仍为 HR 提供；不能跳过现有提交、审核和生效。 |
| 缺项、空值、未知地点 | 不猜补、不默认回填；通过既有问题浮层显示下一步。 |
| 现有共用功能回归 | 原 66 条待核资料的来源和问题不丢失；未变合同来源不重写；电脑/手机入口一致。 |

## 5. 实施前的结论

当前服务提供了草稿、问题、审核及审计基础，但尚没有可直接开放给渠道的通用资料接收接口。需补的接缝是受控来源、服务层权限、幂等、事实/版本核对以及同一事务保存；不需要新建档案数据库或审批系统。

用户在确认上述含义后要求继续完成并上线，授权仅覆盖本稿中的单人虚构资料试用；不扩大真实资料可见范围、不外发个人资料、不读取 OA、不启用第二测试人。先在当前领先代码上完成首条通路及隔离验收，再按此范围发布。首轮仅开放未绑定虚构样例，真实员工变更、通用文字提取及其他渠道作为后续增量，不能称为本轮已完成。
