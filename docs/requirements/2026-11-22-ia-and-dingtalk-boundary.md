# IA-ALIGN-01 菜单与钉钉边界

确认日期：2026-11-22。当前授权为开发、提交任务代码和固定预览，不包含生产发布。

## 模块归属

| 一级模块 | 范围 | 不包含 |
| --- | --- | --- |
| 工作台 | 全局待办与常用业务入口，继续复用来源状态及深链 | 第二套待办表、状态、通用流程引擎 |
| 绩效 | 绩效任务、绩效运营、绩效分析、绩效设置 | 转正最终办理、自动转正 |
| 人员 | 员工档案、组织架构、人事基础资料、入离职、试用与转正 | 招聘人才对象维护 |
| 招聘 | 人才库、既有面试队列、录用确认与入职衔接 | 招聘需求与编制、职位发布、Offer 文书、薪资审批 |
| 薪酬规划 | 仅系统管理员可见的只读边界 | 任何员工薪酬数据、导入、计算、审批、导出 |
| 系统管理 | 既有系统概览和 AI 配置权限；能力状态与运行状态分开 | 从规划页扩展业务权限或修改外部通道开关 |

招聘交接后，员工档案、合同、任职、入离职及 HR 到岗确认继续归人员。人才跟进保留在人才对象内。试用期评价可复用绩效能力，但绩效结果不自动触发转正。

## 权限决策

- 用户再次确认：本次沿用现有“档案维护/审核”与人才库共享的后端授权，不新增独立招聘权限。仅有组织维护或绩效专员能力的 HR 不因此获得人才库。
- 面试官只访问本人参与对象和本人队列；菜单不因有一次面试而开放完整人才库。录用确认人只见原窄权限队列，提交人不能确认本人申请；系统管理员不自动具有录用确认权。
- 招聘建设规划和薪酬规划仅系统管理员可见，无业务操作，不授予任何新数据权限。
- 独立“人员 HR / 招聘 HR”授权需后续单独评审后端能力、菜单、路由、数据范围和迁移，本次没有模拟这种隔离。

## 保持的链接

- 保留 `/talents`、`/talent-hiring`、`/talent-interviews`、公开分享和所有现有对象路径。
- `/recruitment` 按当前授权跳首个真实业务页，并保留 query/hash；建设规划独立为 `/recruitment/planning`。
- `/entry-exit` 仅在人员菜单出现；招聘只通过现有已接受应聘对象衔接，不建立第二个入职列表。
- 人员和转正 legacy redirects、绩效通知和对象深链保持原标识及参数。指标库复用已有页面/API恢复缺失的 `/indicators` 路由。

## 钉钉边界（只记录）

- 请假、出差、外出、加班、补卡、排班、打卡及通用 OA 表单/审批留在钉钉，含撤回、转交、附件、评论和审计。
- 报销、付款默认不进入 HRM。本次不建设 OA、考勤、报销同步或任何薪酬计算。
- 仅在后续算薪或分析需求确认时，再评审最小化只读同步终审结果；草稿、审批中、退回、撤销不构成工资事实。
- 将来拟议的最小字段：员工映射、事项类型、起止、时长与单位、最终状态、完成时间、撤销/变更版本、实例 ID、原单链接、同步时间。
- 同实例幂等、版本可追踪、可审计、可补偿是将来同步的必要约束，不代表当前已经接入。
- 考勤核算周期已确认为自然月 1 日至月底；封账、跨月、补差、奖金、复核尚未确认。

## 系统状态表达

- 站内通知、钉钉工作通知、钉钉待办、钉钉面试日程分开展示。工作通知和日程的代码已实现，不等于外部能力已开启。
- 钉钉工作通知仅复用 `GET /notification-settings/dingtalk`。`available` 同时受部署总开关和凭据影响，不能从 false 断言缺凭据。
- 已启用 / 业务开关已关闭 / 平台不可用或未启用 / 读取失败各自独立。读失败不降格成“待建设”，不猜开关。日程没有只读运行状态接口时明确未提供，不新增接口或改配置。
