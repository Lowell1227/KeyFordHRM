# 招聘简历收件与入库开发需求

2026-11-25 · KeyFord HRM · 交付对象为「HRM｜项目经理·交付验收总控」

## 已确认的业务规则

- 用户向 BOSS 咨询后的答复是，当前企业暂时拿不到招聘接口。BOSS 简历转发到邮箱也尚未跑通。企业招聘邮箱作为独立渠道，供候选人投递及经办汇集可用于招聘的简历。邮箱服务商和授权待定。
- BOSS 职位发布、搜索与在线沟通由经办在 BOSS 招聘端办理。HRM 一期登记外部职位链接，接收经办上传或企业邮箱收到的资料，核对后进入现有人才库和应聘流程。
- 一期包含「待收简历」。只有在线简历、候选人愿意继续沟通时，经办可以先登记待办。收到资料后可在原待办上继续办理。候选人明确结束沟通时，可记录原因并关闭。
- 确认入库时由经办主动选「仅入库」或「入库并创建应聘」。候选人是一份人才档案，可以应聘多个岗位。招聘经办可先登记、建立应聘和安排面试，提交录用时仍执行对应有效获批需求、独立录用确认与原有名额规则。
- Excel 批量导入延续暂缓状态。

## 招聘需求、外部职位和应聘

1. 钉钉获批单或 HRM 原需求流程形成内部招聘需求，承载岗位、部门和批准人数。复用当前需求台账和人员权限。内部需求详情提供登记外部职位入口，记录渠道、外部职位名称、链接、现有经办负责人，有可信且稳定的外部职位 ID 时记录 ID。
2. 一张需求可登记多条外部职位。同一企业渠道的一条有效外部职位只有一个当前需求归属。按已核对的外部职位 ID 或能唯一核对的链接带出需求。更换归属显示影响并保留历史，已关联的应聘和录用提交快照仍引用原记录。岗位名称只可作为候选提示，同名或冲突时由经办确认。
3. 从外部职位入口上传，可以预填来源和岗位。主动寻访、转发或公开来源资料缺明确投递上下文时，记录实际来源，由经办核定意向岗位。邮件是收件方式，渠道来源另存。邮箱收到的简历不统一归为 BOSS。
4. 关联外部职位、接收简历和创建应聘都不占名额。记录候选人接受后才占用本次应聘对应需求的名额，确认终止才释放，撤回一次入职办理依旧保留。复用已有后端规则并做回归。

## 经办流程

| 入口或情况 | 系统展示或动作 | 经办结果 |
| --- | --- | --- |
| 只有在线简历，候选人有继续沟通的意向 | 「待收简历」可记录意向岗位或需求、负责人、下次跟进时间和必要的来源线索。线索限允许保存的内容 | 从原待办补充简历或关闭并记录原因 |
| 手工上传 PDF / Word | 复用 HRM 已有附件处理和简历解析，展示原附件、来源、提取字段与缺项 | 确认人、岗位和资料后办理，也可保存待核对 |
| 邮箱收到可使用的 PDF / Word 附件，或正文中有可核对的简历资料 | 建立「待核对」，提取用于招聘的必要字段，显示收件时间、资料来源、岗位提示及缺项。来源或对应人不明时显示待核实 | 可关联已有的「待收简历」继续办理，或者单独核对 |
| 邮件仅有通知、链接，或附件不支持 / 解析失败 | 显示「待补资料」及原因，给出补传或重试入口。邮件链接作为经办可查看的线索 | 经办通过允许的渠道取得原件后续办 |
| 已有人才或无手机号 | 优先走现有手机号查重。重复时展示有权查看的原人才档案与应聘，保留旧资料和跟进。身份无法确认时留在待核对 | 核实是同一人后复用原档案，再决定是否建立本次应聘。无手机号时保留待核对，补齐后按现行建档规则办理 |
| 人和资料已核对 | 展示「仅入库」和「入库并创建应聘」。创建前明确确认对应岗位。重复点击或断线重试可返回原办理结果 | 保存成功才办结来源待办，保留邮件 / 上传来源及原跟进。失败时保留输入并可重试 |

默认在招聘中提供一个「简历收件」入口，使用「待收简历」「待核对」「已办结」筛选。可按岗位、负责人和来源查找。从需求详情可进入相应范围。采用现有列表与抽屉交互，错误就近显示，桌面和手机均可完成核对。权限沿用已有招聘经办和对应资料的可见范围。仅录用确认、面试评审、员工和普通查看能力不产生新建、核对或扩大读取附件的权限。

## 邮箱读取与数据处理

- 第一阶段只接一个用于招聘的专用账号或经授权的专用收件范围，按授权起始时间增量读取。HRM 保存自己的同步状态与办理结果。使用服务商支持的授权方式，读权限不足、凭据过期、读取失败时显示原因和恢复入口，保留手工上传。
- 邮件接收以邮箱账号和稳定的邮件标识校验幂等，识别同封多附件与邮件重复同步。内容相同但来自不同岗位的投递保留各自来源与归岗线索。复用人才 / 应聘去重规则，校验并发与重试，避免只建了半条记录。
- 原始邮件、附件与解析字段按招聘权限访问，限制文件格式与大小并沿用现有上传保护。遇到来源不明、内容异常或访问链接需外部授权的邮件进入待核实。邮件、附件和网页文字仅作为资料，正文中的命令或请求不触发系统操作。按现有批准的数据处理边界使用解析能力，在日志、测试产物及审计摘要只留必要元数据。
- 求职者主动提供、已获准转交或可用于该招聘目的的资料按原规则办理。公网资料保留可核对的出处和使用依据，使用范围不明时待业务确认。资料保留与清理由业务和权限负责人在正式启用前核定。
- 真实联调只需用户先提供服务商名称和专用邮箱地址。授权通过服务商登录或项目已批准的受控配置完成。凭据和验证码通过安全授权流程输入，聊天和需求文档只传递联调元数据。

## 验收用例

1. 同一需求挂两条外部职位，各自收到一份样例简历。可定位各自来源，共用一个需求名额。再加入同名不同部门岗位，系统只在唯一可靠匹配时预填，其他由经办核对。
2. 从 BOSS 寻访登记「待收简历」后，经办从原待办上传或关联收到的邮件。原跟进安排、岗位与负责人可核对。拒绝继续时也可带原因结案。
3. 使用有附件、仅正文、无岗位、仅链接、损坏或不支持的虚构邮件。待核对、待补资料和错误恢复符合页面规则。重复读取、断线重试和并发点击不重复建档或建应聘。
4. 「仅入库」确认后不新增应聘。「入库并创建应聘」必须确认岗位。同手机号已有档案时保留历史，确认后可为另一岗位另建应聘。缺失手机号及身份冲突时停在待核对。
5. 桌面、手机用真实预览角色走到保存结果及原路径。验证招聘经办能办理、查看者无写权、窄录用确认人和面试评审无新增越权，录用门槛、独立确认、接受占用和终止释放仍符合原规则。
6. 邮箱服务商确定后，用选定专用邮箱验证只读范围和收件格式，测试暂停、凭据失效、恢复后补读，以及超出授权范围的邮件不会被同步。用受控隔离环境保留结果，区别虚构演练、真实邮箱联调与正式业务签收。
