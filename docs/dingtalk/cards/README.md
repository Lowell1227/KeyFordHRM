# 钉钉绩效卡片：主动查询接入包

本包承接已评审的五类卡片设计。本轮完成四类新增模板文件和主动查询适配，复用原有目标进展模板。**代码已在隔离分支实现并验证，未合并、未上线，未向真实员工发送消息。**

## 员工怎样使用

| 发给同一个“绩效助手” | 返回内容 | 正式操作在哪里完成 |
| --- | --- | --- |
| 我的待办 / 我的绩效 | 本人及实际分配给本人的绩效事项，最多展示 5 条 | 原 HRM 办理页 |
| 我的目标 / 查看目标 / 制定目标 | 本人正式考核目标的当前状态 | 原目标制定、审核后确认页 |
| 我的自评 / 填写自评 / 绩效评价 | 本人实际已开放期间，明确月份或整周期 | 原自评页，携带真实 periodId |
| 我的结果 / 查看结果 | 已批准可核对的结果、已确认待公示、已公示或真实异议重评状态 | 原结果页；不在聊天中发送分数、等级、系数或完整评语 |
| 帮助 | 命令和进展保存说明 | 不执行业务写入 |
| 真实工作进展文字 | 原有进展确认卡 | 核对后明确点击“保存进展”，才写入正式进展 |

“我的”查询始终是本人数据，包括具有 HR 角色的本人。上级/复核/审批事项来自实际处理人和期间权限，不根据“主管”岗位名称产生。无任务时明确告知，不生成示例业务卡。多个月份同时开放分别展示，不按当前日历月份猜测。

卡片是查询时的快照。打开链接会进入现有登录、权限和状态检查页面，正式写动作仍按原流程校验。再次查询得到最新卡片；本轮不自动修改历史查询卡，不新增定时催办或群发。

## 模板文件及配置

| 文件 | 新应用下的模板名称建议 | 服务端配置键 |
| --- | --- | --- |
| `todo.json` | 我的绩效待办 | `DINGTALK_BOT_TODO_TEMPLATE_ID` |
| `goal.json` | 绩效目标 | `DINGTALK_BOT_GOAL_TEMPLATE_ID` |
| `evaluation.json` | 绩效评价 | `DINGTALK_BOT_EVALUATION_TEMPLATE_ID` |
| `result.json` | 绩效结果 | `DINGTALK_BOT_RESULT_TEMPLATE_ID` |

原进展模板继续使用 `DINGTALK_BOT_CARD_TEMPLATE_ID`，不需要重新拖拽、不需要先重建旧卡。现有模板 ID 保持 `69ff499a-f107-47a1-bb8c-99359aa64583.schema`。已保存状态的查看入口已改为正式目标进展详情，不再依赖 24 小时草稿。

钉钉平台尚无本轮已核实的模板创建 API，平台创建/导入是剩余的人工步骤：在“绩效助手”应用范围创建空白模板，右上角 **更多 → 导入** 对应 JSON，检查变量和预览，然后发布该模板、记录模板 ID。四个模板导入即可，不需要逐个组件重新配置。官方导入步骤见 [钉钉卡片示例仓库](https://github.com/open-dingtalk/dingtalk-card-examples#项目介绍)。

文件采用官方导出的 `editorData/widgetInfo/type/mode` 外层结构，编辑器版本 3.0.0；Card/BaseText/SingleButton 默认属性取自官方“卡片配合 H5 实现复杂业务”示例，固定到修订 `2201b867795e273c0b1ac6d908d72cbc486e19bb`。模板没有模型调用、表单提交、评分回调或自动确认；按钮只绑定受控 HRM 链接。样例数据全是合成内容，不是真实员工数据。正式钉钉编辑器导入、重新保存/编译以及 PC/手机渲染仍需现场验证，不能用 JSON/XML 可解析代替。

新增四个 ID 暂未填写时，机器人仍可用同一应用发送安全文字办理入口；不会改用旧 HRM 应用发第二份消息。部署文件已通过 `env_file` 读取环境项，无须改动 Compose 服务范围。此文档和 `.env.example` 不含凭证，配置时不要把密钥贴到聊天或提交到仓库。

## 本地复验

```powershell
# 仓库根目录：离线生成，不联网、不调用钉钉
node scripts/dingtalk-cards/build-templates.cjs
node --test scripts/dingtalk-cards/build-templates.test.cjs

# api 目录：单元测试与构建
npm test -- --runInBand
npm run build

# api 目录：仅该套测试拥有的一次性 PostgreSQL/Redis，无全局测试 setup
npm test -- --config test/jest-ai-progress.json --runInBand
```

测试不加载正式 `.env`，钉钉及模型传输被替换为合成响应。集成测试创建后销毁自己的容器，验证真实身份准入、本人目标/期间读取、无查询写入、未批准结果不外发、重复投递和原有进展保存并发规则。

2026-10-13 本地证据：API 110 套 / 1476 项通过，独立 PostgreSQL/Redis 集成 20 项通过，API 构建通过；模板契约 2 项通过，四个 XML 可解析，重复生成 SHA256 一致。上述不代表钉钉原生渲染、生产发布或姚瑶业务验收。
